# Обновление существующего окружения

## Анализ до согласия

Для каждого компонента сопоставь установленную версию, путь, менеджер установки,
требования проекта и доступную совместимую версию из официального источника.
Отчёт должен различать «уже актуально», «доступно обновление», «ограничено pin»
и «версия/состояние неизвестны». Не выдавай отсутствие сведений за актуальность.
Проверь дубли в PATH: более новая копия может быть установлена, но не выбрана.

Используй чтение локальной metadata и официальных release notes.
Не запускай package index refresh или installer на этапе анализа.
Для Homebrew отключи автоматическое обновление при metadata-запросах
(`HOMEBREW_NO_AUTO_UPDATE=1`). Если локальные каталоги устарели, укажи это и
проверь целевую версию в официальном источнике. Не называй её проверенной,
пока совместимость с проектом не установлена.

Включи в отчёт конкретные версии до/после, изменения файлов проекта,
необходимость повторного patch/rebuild/регистрации hooks и проверки результата.
Получай согласие по разделу 3 `../SKILL.md` до любого применения.

## Выполнение после согласия

Обновляй тем же менеджером, которым установлен компонент. Не создавай вторую
установку для обхода старой. При смене менеджера или среды включи миграцию
в согласуемый список. Не удаляй общие SDK caches и окружения других проектов.

| Компонент | Способ обновления и ограничения |
| --- | --- |
| Homebrew CLI/casks | После согласия обнови metadata и только выбранные formula/cask через `brew upgrade <имена>`; проверь итоговые версии |
| WinGet/Chocolatey | Только выбранные package IDs/версии через `winget upgrade --id <ID> -e --version <версия>` или `choco upgrade <пакет> --version <версия>` после проверки установленного `--help` |
| Linux packages | Обнови metadata после согласия; установи выбранные версии через менеджер distro, например `apt-get install --only-upgrade <пакеты>`; без общего system upgrade |
| FVM CLI | Обнови FVM платформенным менеджером; обновление FVM само по себе не меняет Flutter pin |
| Flutter/Dart, Melos и pub-пакеты | Смотри следующий раздел; Dart обновляется вместе с Flutter, Melos остаётся dependency проекта |
| Java, Android SDK/NDK | Обновляй выбранные пакеты в совместимых пределах Gradle/Flutter; не подменяй NDK latest и не стирай AVD |
| Python и uv | Обнови выбранный runtime/CLI; перед заменой проверь, какие tool venv и hooks используют его путь |
| uv tools, включая Semgrep | Обновляй только выбранное окружение и согласованную версию; проверь flags project wrappers |
| DCM | Соблюдай `dcm_global.yaml`, сохрани рабочую активацию и проверь реальный анализ |
| Graphify | Соблюдай distribution/version и hashes producer patch manifest; затем patch check, tests, hooks и граф |
| Impeccable | Обновляй текущим официальным installer; сохрани project scope/provider, PRODUCT.md, DESIGN.md и custom hooks |
| Остальные внешние skills | Сравни с исходным bundle; сохрани локальные правки и обнови выбранный scope без вложенных Git repositories |

Менеджер может предлагать более новую версию, чем была согласована. Перед
применением перепроверь target. Если менеджер не умеет установить согласованную
версию, покажи альтернативу и согласуй изменение, не выбирай latest молча.

## Flutter, Dart, Melos и workspace

Обновление самого FVM не означает `fvm use stable` или смену `.fvmrc`.
При обычном обновлении окружения сохраняй pins Flutter, Melos и pub lockfile.
Доступный новый SDK/Melos покажи отдельно и предложи включить в список.

Если пользователь подтвердил изменение SDK или pub dependencies, прочитай
`../../anistar-flutter-update/SKILL.md` и используй его workflow для применения,
совместимости и проверок. Factory Install отвечает за предварительный анализ,
конкретный список целевых обновлений и согласие. Передай подтверждённые версии
и ограничения. Не проси повторного согласия на тот же неизменившийся список.
Не расширяй подтверждённое обновление одного пакета до всех major dependencies.

Для Melos меняются dependency в корневом `pubspec.yaml` и соответствующий
`pubspec.lock`, затем проверяется `fvm dart run melos --version`, bootstrap
и используемые команды проекта. Глобальная активация Melos не обновляет workspace.
Не редактируй lockfile вручную.

## Graphify и Impeccable

Текущий producer patch привязан к версии в `tool/graphify/patch-manifest.json`.
Если upstream новее, покажи «обновление ограничено producer patch», пока новая
версия не проверена отдельно. Не удаляй patch ради latest. Изменение самого
manifest/patch — отдельная задача tooling, которую обычное обновление не включает.
Совместимую переустановку с восстановлением patch выполняй по
[agents-and-graph.md](agents-and-graph.md).

После обновления Impeccable проверь его engine, skill и manifests hooks.
Не обновляй пользовательские дизайн-документы как побочный эффект.
После смены interpreter/CLI path обнови только подтверждённые hooks/MCP/PATH,
которые на него ссылаются, и проверь запуск из агентского host.

## Проверка и завершение

Проверь фактические версии и функции выбранных компонентов, а не только exit code
менеджера. Запусти соответствующие gates из `../SKILL.md`. Для изменения
SDK/dependencies используй полный порядок из `anistar-flutter-update`.
Ошибка проверки не разрешает добавлять новый инструмент или менять pins за
пределами согласованного списка. Сохрани рабочие данные и сообщи blocker.
При повторном запуске сначала сверяй состояние с уже выполненными действиями.
