# Factory Install

Процесс: **анализ → краткий отчёт → выбор и согласие пользователя → выполнение → проверка**.
Он обязателен для установки, обновления и восстановления окружения.
Запрос запустить скилл или «установи всё» разрешает сначала анализ, но не заменяет
согласие с конкретным списком изменений после отчёта.

Выбери режим по запросу: установка недостающего, обновление существующего,
восстановление неисправного или только диагностика. При установке рассматривай
весь комплект ниже, включая Graphify и Impeccable, но предложи выбрать нужное.
При обновлении проверь доступные совместимые версии уже установленных инструментов.
Отсутствующие компоненты покажи отдельно. Не добавляй их автоматически к обновлению.
Диагностика заканчивается отчётом без изменения окружения.

## 1. Исходное состояние

Работай из корня checkout. Прочитай `AGENTS.md`, `README.md`,
`docs/melos_tooling.md`, `docs/vcs_guidelines.md`, раздел окружения в
`docs/05_development_and_testing.md`, `tool/e2e/README.md`,
`tool/graphify/README.md` и адаптер текущей среды в `.agents/adapters/`.

Определи ОС, CPU, shell, права, пакетный менеджер и host выполнения.
Отличай PowerShell, Git Bash и Linux внутри WSL2. Прочитай только свою платформу:

- macOS: [references/macos.md](references/macos.md).
- Windows, включая выбор WSL2/native: [references/windows.md](references/windows.md).
- Linux: [references/linux.md](references/linux.md).

Проверь Git status, текущие hooks и `core.hooksPath` до изменений.
Проверь наличие, версию, фактический путь, архитектуру, способ установки и
работоспособность каждого компонента. Отличай отсутствующий CLI от отсутствующего
PATH, неактивной лицензии и неисправной установки. Проверь SDK cache, зависимости
workspace, skills, MCP, hooks и состояние графа. Для обновления прочитай также
[references/updates.md](references/updates.md).

**До согласия разрешены только чтение и диагностика без установки.**
Не запускай installers, обновление package indexes, `npx` с загрузкой пакетов,
`uv tool run`, `fvm install`, `pub get`, bootstrap, codegen, hooks install,
загрузку engine, построение графа или запись PATH/configs. Даже version/doctor
команды запускай только если они не bootstrap-ят отсутствующий SDK/engine.
Иначе прочитай установленную metadata и отметь работоспособность как непроверенную.
Не устанавливай отсутствующий инструмент только ради анализа остальных.

Если граф уже существует и Graphify доступен, начни поиск требований с
`graphify query "installation bootstrap prerequisites security hooks tooling"`.
Отсутствие Graphify на новом компьютере не мешает читать перечисленные документы.

## 2. Комплект и версии

| Компонент | Источник и критерий |
| --- | --- |
| Git, Bash, curl, zip/unzip, xz, patch, ripgrep | Shell scripts проекта; `patch` нужен installer Graphify |
| Python и uv | Python 3.10+ по `scripts/with_python.sh`; 3.12 подходит для изолированных Python CLI |
| FVM, Flutter и Dart | Точный Flutter из `.fvmrc`; сверить legacy `.fvm/fvm_config.json`, если существует; Dart входит в Flutter |
| Melos и pub-пакеты | Установить через `fvm flutter pub get --enforce-lockfile` из корневых `pubspec.yaml` и `pubspec.lock`; проверить `fvm dart run melos --version` |
| Java и Android | JDK из руководств; SDK/NDK из Gradle и выбранного Flutter; [references/android.md](references/android.md) |
| DCM | Диапазон `dcm_global.yaml`; проверить CLI и доступ к нужным анализаторам |
| GitHub CLI | `gh --version`, авторизация для host из Git remote |
| Lefthook | `lefthook.yml`, `scripts/lefthook.sh`, сохранение существующих hooks |
| Gitleaks, OSV-Scanner, Semgrep | `scripts/security_*.sh`, `.gitleaks.toml`, `.semgrep/`, `.semgrepignore` |
| Graphify и его skill | Distribution/version из `tool/graphify/patch-manifest.json`; пакет `graphifyy`, CLI `graphify` |
| Impeccable и engine | Skill, references и launcher для текущих ОС/CPU |
| Factory skills и роли | `.agents/skills/`, `.agents/agents/`, `.agents/contracts/`, адаптер и настройки host |
| Node.js LTS / npm | Для installer Impeccable; установленный engine работает без Node |
| FFmpeg с libx264 | Полный комплект включает обслуживание HLS fixtures; не пересоздавать fixtures при установке |

При установке и восстановлении файлы проекта определяют версии.
При обновлении предложи точные совместимые целевые версии и отдельно покажи
изменения pins/lockfile. До согласия их не меняй. Не устанавливай глобальный
Flutter/Dart для обхода FVM.
Способы установки сверяй с официальными ссылками платформы и установленным `--help`.
Неподдерживаемую архитектуру укажи как blocker.

## 3. Отчёт и обязательное согласие

Покажи небольшой отчёт в чате, без отдельного файла: ОС/CPU/shell, режим,
готовность окружения и таблицу предлагаемых действий. Совместимые компоненты
без изменений можно сгруппировать в одну строку.

| Компонент | Сейчас | Цель | Действие и причина |
| --- | --- | --- | --- |
| FVM | Отсутствует | Проверенная версия | Установить для управления Flutter |
| Melos | Версия из lockfile | Та же версия | Оставить, если запуск исправен |
| Выбранный CLI | Установленная версия | Совместимая доступная версия | Обновить по запросу |

Строки выше — формат, а не результаты диагностики. Подставь реальные данные.
Используй действия: установить, обновить, восстановить, оставить, исключить,
заблокировано. Для изменяемых компонентов укажи конкретные версии, способ и
область установки. Если цель определить нельзя, обозначь неизвестность и не
включай её выполнение в согласуемый список.

Отдельно перечисли предлагаемые изменения PATH, hooks, MCP, pins/lockfile,
пересборку графа и создание AVD. Укажи существенные загрузки/перезапуск, если они
нужны. Оценку размера давай только при наличии данных. Отметь необязательные
инструменты и возможности, которые будут недоступны при их исключении.

Спроси, согласен ли пользователь с перечисленными изменениями и какие пункты
нужно исключить. **Дождись явного ответа.** Молчание, таймаут или отсутствие
ответа в UI не означают согласие. Не используй форму выбора, которая продолжает
работу автоматически без ответа. При отказе закончи без изменений.

Разрешены весь подтверждённый список или явно выбранное подмножество.
Пользователь может исключить инструмент; не устанавливай его как скрытую
зависимость другого пункта. Объясни зависимость и исключи зависимые действия
либо согласуй изменённый список. Если подтверждённый список меняется по ходу
работы, покажи дополнение и получи согласие перед новыми действиями.
При возобновлении не запрашивай согласие повторно на неизменившийся список,
который уже подтверждён после анализа; проверь, что состояние осталось актуальным.

## 4. Выполнение подтверждённого списка

После согласия выполни только выбранные действия. Команды в references — рецепты,
а не разрешение устанавливать весь комплект. Сохраняй совместимые установки и
пользовательские настройки. Не выполняй общее обновление системы.
Для установки выполни инструкции платформы, затем
[references/android.md](references/android.md). Для обновления используй
[references/updates.md](references/updates.md).
На macOS устанавливай системные пакеты через Homebrew. Python CLI изолируй
через uv, когда для них нужен отдельный version pin.

Настрой PATH в текущем процессе и профиле текущего пользователя без дублирования
записей. Проверь команды из нового shell и агентского host: GUI-приложение
может не наследовать PATH терминала. Не записывай машинные пути в tracked configs.

Продолжай подтверждённую независимую работу при интерактивном шаге.
Пользователь сам вводит пароль администратора, проходит GitHub/DCM login,
принимает лицензии и подтверждает trust,
когда система этого требует. Не запрашивай секреты в чате. Назови точное действие,
если без участия пользователя продолжить нельзя. Не обходи системные ограничения.

## 5. Workspace

Если workspace входит в подтверждённый список, выполняй команды последовательно:

```bash
fvm install
fvm flutter --version --machine
fvm flutter precache --android
fvm flutter pub get --enforce-lockfile
fvm dart run melos --version
fvm dart run melos bootstrap --enforce-lockfile
fvm dart run melos run generate
```

FVM устанавливается платформенным способом до этих команд и управляет Flutter SDK.
`pub get` устанавливает Melos как dev dependency проекта. Проверь, что его версия
совпадает с `pubspec.lock` и требованием `pubspec.yaml`. Запускай его через
`fvm dart run melos`: глобальная установка Melos для этого проекта не требуется.

Проверь `.fvm/flutter_sdk` и совпадение SDK с `.fvmrc`.
Если FVM не создал project link, прочитай `fvm use --help` и создай ссылку на тот же
точный pin с `--skip-pub-get`. Изменение версии проекта допускается только как
отдельно показанное и подтверждённое обновление по `references/updates.md`.
При ошибке lockfile выясни причину. В установке и восстановлении не выполняй
`pub upgrade`; подтверждённое обновление зависимостей следует `references/updates.md`.
Проверь diff после генерации. Не исправляй generated files вручную.

## 6. Skills, MCP, hooks и граф

Следуй [references/agents-and-graph.md](references/agents-and-graph.md).
В пределах подтверждённого состава этап включает Graphify с патчем, Impeccable,
локальный `asd-ste100`, обнаружение Factory skills, MCP текущей среды,
Lefthook и Graphify hooks, первый граф кода
**и документов** с HTML. Для уже исправленного графа используй incremental update.
Наличие CLI само по себе не доказывает готовность графа или MCP.

## 7. Проверка

Сначала проверь пути/версии CLI, `fvm flutter doctor -v`, `lefthook validate`,
Graphify patch check и regression tests, `graphify hook status`,
`graphify query "Flutter FVM security hooks"`, запуск Impeccable engine и
доступность skills/MCP в host. Отсутствие Xcode, браузера или Linux desktop
toolchain не блокирует Android-проект. Ошибки Android toolchain блокируют сборку.

Для подтверждённого полного окружения после подготовки выполни последовательно:

```bash
fvm dart run melos run security
fvm dart run melos run check
fvm dart run melos run test:e2e
fvm dart run melos run build:android:prod:apk
```

`security:deps` обращается к OSV и передаёт package metadata.
Отличай findings сканера от ошибки его установки. Сохрани результат и сообщи о нём.
Не отключай правила и не исправляй код приложения в рамках установки.
Для shallow clone получи недостающую историю из настроенного remote перед полным
Gitleaks scan, если remote доступен. Иначе назови blocker.

Flutter/Gradle/codegen запускай последовательно. Fixture E2E требует двух AVD.
При недоступной виртуализации выполни независимые проверки и укажи непроверенный
E2E. Не запускай live-тесты, не обновляй goldens, не создавай аккаунты, commit,
push или публикации.

Для частичного состава выполни доступные проверки выбранных компонентов.
Не устанавливай исключённые инструменты для прохождения gate; отметь недоступные
проверки. После изменений tooling выполни `graphify update .`, если обновление
графа подтверждено и Graphify доступен, затем `git diff --check`.
Исправляй только окружение в заданном объёме. Не повторяй неизменившийся
неуспешный installer без новой причины или исправления.

## Результат

Сообщи ОС/CPU и среду выполнения, подтверждённый состав, установленные,
обновлённые, восстановленные, сохранённые и исключённые компоненты,
фактические FVM/Flutter/Dart/Melos/DCM/Graphify версии, готовность hooks, skills, MCP и графа.
Приведи свежие результаты проверок, путь APK при успешной сборке и оставшиеся
действия пользователя. Разделяй «установлено», «настроено» и «проверено».
Windows с готовым WSL toolchain и недоступными AVD не является полностью
проверенной Android-средой. Не заявляй проверку ОС, на которой запуск не шёл.
