## 1. Контекст и ожидаемый результат

На главной, в каталоге и избранном обоих профилей видны компактные согласованные метки и рейтинг «★ 8,7».

## 2. Что входит в задачу (`implemented`)

1. UI Kit предоставляет общую визуальную основу меток: скруглённый фон, обводка, высота, отступы и иконки. Presentation каталога/избранного подставляет исходный рейтинг и подтверждённое состояние избранного в карточки обоих профилей.

2. Рейтинг показывает одну дробную цифру с запятой без знаменателя, например «★ 8,7»; семантическая подпись — «Рейтинг 8,7 из 10». Не пересчитывать исходное значение и не превращать отсутствие или некорректное значение в ноль.

3. Избранное и оценка сохраняют разные смыслы. Неизвестный статус не становится подтверждённой звездой. Метки декоративны для фокуса и не получают самостоятельного действия. Действия карточки, подтверждение изменения сайтом, ошибка и повтор избранного остаются прежними.

4. Обновить значимые регрессии отображения и семантики на главной/в избранном обоих профилей; синхронизировать визуальное описание docs/specs/02_favorites.md, docs/specs/06_tv_interaction.md, docs/specs/10_mobile_interaction.md и UI Kit README.

## 4. Архитектурный контекст

- **Владелец:** `catalog`; остальные затронутые компоненты указаны ниже как места подключения и проверки.
- **Переиспользование:** публичные компоненты UI Kit и существующие контракты Domain функциональных областей; локальное состояние и жизненный цикл остаются в Presentation. UI Kit принимает визуальные данные и действия, не импортирует код функциональных областей и не управляет сетью и нативным плеером.
- **Ограничения:** сохранить Clean Architecture, Riverpod DI и текущую модель BLoC, неизменяемость данных, `BaseRepository` и `Result`/`Failure`. Presentation не обращается к Data напрямую. Не импортировать чужой закрытый `src/`; внутренние пути ниже — ориентиры чтения. Новые пакеты, сервер/DTO/парсер/хранилище и протоколы аккаунта не входят. Не править сгенерированные файлы вручную; неизвестные типы — `Object?` и проверки, логи — `Logger` без секретов, HTML и подписанных URL.
- **Критические решения:** D-04: компактная общая основа меток при разных смыслах; «★ 8,7» и «Рейтинг 8,7 из 10»; без ложного нуля и отдельного фокуса.
- **Подтверждённые факты и внешние условия:** контракт и границы подтверждены утверждённым планом; неразрешённых внешних зависимостей и `EXT-*` нет. Физическое устройство требуется для QA, не для начала разработки.

Текущие ориентиры подтверждены одним ограниченным поиском по модулям после фиксации границ задач; точные будущие символы и порядок правок выбирает исполнитель:

- `lib/packages/features/catalog/presentation/widgets/anime_card.dart`
- `lib/packages/features/catalog/presentation/mobile/mobile_anime_card.dart`
- `test/packages/features/catalog/presentation/widgets/anime_card_test.dart`

- [ ] Всё поведение раздела 2 реализовано, релевантные unit/widget/golden-регрессии обновлены вместе с контрактами.
- [ ] Проверить формат исходного числового рейтинга, одну дробную цифру, запятую, полную семантику и отсутствие метки нуля для отсутствующего/некорректного значения.
- [ ] Подтверждённое true/false и неизвестное избранное отображаются корректно; метки не добавляют цели фокуса/действия. Ошибка изменения не даёт неподтверждённой звезды; существующие карточные действия сохраняются.
- [ ] UI соответствует ADR-0008 и применимым спецификациям TV, телефона и анимаций; изменения не затрагивают соседние протоколы.

Перед готовностью эпика к `main` закрыты все обязательные результаты, отсутствуют временные заглушки и достижимые `UnimplementedError`, выполнены необходимые интеграционные проверки и комплексное ревью.
