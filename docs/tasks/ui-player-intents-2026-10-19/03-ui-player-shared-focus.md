## 1. Контекст и ожидаемый результат

Каталог, избранное, серии и строки выбора плеера одинаково показывают фокус с согласованным контуром изображения.

## 2. Что входит в задачу (`implemented`)

1. Общая публичная нейтральная оболочка UI Kit на основе TvFocusable, AppFocusStyle и AppMotion принимает визуальное содержимое, состояния и действия без моделей функциональных областей и Domain. Она владеет рамкой, свечением и переходами. Подключить её к карточкам каталога/избранного обоих профилей, карточкам серий и строкам выбора серии/качества плеера.

2. Карточный вариант умеренно увеличивается, строковый — нет. Согласовать внешний контур рамки и внутренний контур изображения с учётом толщины рамки; одинаковые числовые радиусы сами по себе не гарантируют совпадение. Заглушка, изображение и оба конца Hero сохраняют геометрию.

3. Сохранить палитру, AppMotion.fast = 160 мс, действия короткого/долгого OK и касания, маршрут фокуса и возврат к доступной цели. Фокус, выбранное и просмотренное остаются различимы. Увеличение не обрезает рамку и не перекрывает соседей.

4. При отключённых анимациях движение отсутствует, фокус остаётся виден; загрузка не получает фокус и сохраняет геометрию. Ошибка изображения использует существующую заглушку без изменения данных. Пустое состояние, ошибка списка и исчезновение элемента сохраняют доступное штатное восстановление.

5. Обновить связанные widget/golden-регрессии, docs/specs/06_tv_interaction.md, docs/specs/08_motion.md и описание визуального контракта в lib/packages/ui_kit/README.md.

## 4. Архитектурный контекст

- **Владелец:** `ui_kit`; остальные затронутые компоненты указаны ниже как места подключения и проверки.
- **Переиспользование:** публичные компоненты UI Kit и существующие контракты Domain функциональных областей; локальное состояние и жизненный цикл остаются в Presentation. UI Kit принимает визуальные данные и действия, не импортирует код функциональных областей и не управляет сетью и нативным плеером.
- **Ограничения:** сохранить Clean Architecture, Riverpod DI и текущую модель BLoC, неизменяемость данных, `BaseRepository` и `Result`/`Failure`. Presentation не обращается к Data напрямую. Не импортировать чужой закрытый `src/`; внутренние пути ниже — ориентиры чтения. Новые пакеты, сервер/DTO/парсер/хранилище и протоколы аккаунта не входят. Не править сгенерированные файлы вручную; неизвестные типы — `Object?` и проверки, логи — `Logger` без секретов, HTML и подписанных URL.
- **Критические решения:** D-03: общий владелец рамки/свечения/переходов — UI Kit; карточки увеличиваются, строки нет; геометрия учитывает толщину рамки, включая заглушку и Hero.
- **Подтверждённые факты и внешние условия:** контракт и границы подтверждены утверждённым планом; неразрешённых внешних зависимостей и `EXT-*` нет. Физическое устройство требуется для QA, не для начала разработки.

Текущие ориентиры подтверждены одним ограниченным поиском по модулям после фиксации границ задач; точные будущие символы и порядок правок выбирает исполнитель:

- `lib/packages/ui_kit/lib/src/widgets/tv_choice_tile.dart`

- [ ] Всё поведение раздела 2 реализовано, релевантные unit/widget/golden-регрессии обновлены вместе с контрактами.
- [ ] Проверить обычное состояние, фокус и переход обоих вариантов; изображение, заглушку, Hero и системное уменьшение анимаций; выбранное и просмотренное не теряются.
- [ ] Widget-проверки подтверждают прежнюю активацию и возврат фокуса; геометрические и golden-проверки подтверждают согласованные контуры без обрезания, перекрытия текста и соседей.
- [ ] UI соответствует ADR-0008 и применимым спецификациям TV, телефона и анимаций; изменения не затрагивают соседние протоколы.
- [ ] Выполнить последовательный общий контроль реализации: `fvm dart run melos run check` → `fvm dart run melos run test:e2e` → `fvm dart run melos run build:android:prod:apk`; результаты и препятствия записать раздельно. Команды Flutter, Gradle и генерацию кода выполнять последовательно по `docs/melos_tooling.md`. После изменения кода или инструментов — `graphify update .`.
- [ ] Интеграция соответствует `docs/vcs_guidelines.md`: обычная база `main`; стек веток не назначен. Перед готовностью эпика к `main` закрыты все обязательные результаты, отсутствуют временные заглушки и достижимые `UnimplementedError`, выполнены необходимые интеграционные проверки и комплексное ревью.
