## 1. Контекст и ожидаемый результат

Исследован протокол сортировки года и режиссёра в пределах EXT-01. Задача реализует соответствующую часть утверждённого плана; демонстрационные аккаунт/видео/задержки/локальные данные не становятся логикой приложения.

### Организация выполнения

B0 — ранний исследовательский подэтап пакета B. Исполнитель передаёт проверяемую матрицу либо воспроизводимый отказ координатору и владельцу B; это не отдельная передача production-кода в TestWriter/DevReviewer. Фикстуры пишет TestWriter при передаче всего пакета B. Исследование не объявляется успешным доказательством протокола при неполной матрице.

EXT-01 ограничивает только задачу 14.

## 2. Что входит в задачу (`implemented`)

1. В рамках EXT-01 исследовать два новых вида исходных href года/режиссёра: раздельные request-local группы DLE cookies, пять критериев × два направления, активный порядок и страницы 1/2. Проверить исходные CP1251 percent-encoded байты и +; прежняя проба title/asc с обеими группами не считается доказательством.
2. Публичное чтение без реального входа/мутации аккаунта, без раскрытия сырых HTML/cookies/signedURL в логах. Отчёт содержит безопасные признаки/ссылки и точную матрицу подтверждений; пригодные обезличенные ответы передаются TestWriter для fixtures.
3. Завершиться проверяемой матрицей либо воспроизводимым отказом в отведённое время. Неподдержанное сочетание или недостающие доказательства блокируют только задачу 14; передать факт на пересмотр семантики, не подставлять локальную сортировку и не урезать критерии молча.
4. Остальные задачи UI Kit, каталога, карточки, плеера и прежних фильтров продолжаются независимо от EXT-01. Новые фильтры не подключаются до доказанного результата.

## 4. Архитектурный контекст

- **Область записи:** `infrastructure/anistar/` — только допустимые свидетельства/контракт; `docs/specs/09_catalog_filters.md — фактическое подтверждение`.
- **Переиспользование и ограничения:** Сохранить Clean Architecture: Presentation использует domain-контракты; Data преобразует публичные DTO и возвращает Result/Failure через BaseRepository. Riverpod — DI, BLoC — экранное состояние, App — маршруты. Без private src-импортов, dynamic, print, логирования HTML/cookies/credentials/signedURL; generated не менять вручную. UI Kit не знает feature-модели/предметные запросы/маршруты; загрузка изображения AppNetworkImage разрешена.
- **Критические решения:** D-01, D-08, D-13; общие D-14/D-15: goldens разрешены без повторного вопроса, commit/push только последним действием всего редизайна.
- **Подтверждённые факты и внешние условия:** EXT-01 применим только к доказательству/включению новых фильтров. Опоры текущего устройства: публичные контракты применимого пакета и существующие точки входа, перечисленные в утверждённом плане; точные файлы уточняются в execution brief без новых продуктовых решений.

**Границы записи:** пакет A владеет UI Kit, home, auth, common, log_viewer, App/Runner и navigation rail; пакет B — catalog (кроме rail), anime, favorites, watch_history и изменениями протокола/DTO anistar; пакет C — player. Общие файлы и документы изменяет только назначенный владелец в последовательном окне. Не откатывать чужие правки. Запрос на изменение вне своей области передаётся координатору.

## 5. Как проверить и принять

- **Проверяемый результат после PR:** Исследован протокол сортировки года и режиссёра в пределах EXT-01.

- [ ] При подтверждённом протоколе матрица различает два пути, все 10 порядков, страницы 1/2, выбранную группу cookies и активный порядок; иначе зафиксирован воспроизводимый отказ с точным перечнем неподтверждённых сочетаний, блокирующий интеграцию 14.
- [ ] Зафиксированы отрицательные случаи/изоляция и воспроизводимый результат без credentials; пропуски помечены, не выданы за успех.
- [ ] Применимые тесты, эталоны и правила архитектуры проходят на зафиксированном пакете. TestWriter сохраняет команды/результаты и tested file hashes. Все затронутые goldens можно генерировать без вопроса пользователю; PNG/diff просматриваются, затем выполняется сравнение.
- [ ] Проверки Developer/Static Gate → TestWriter → DevReviewer идут по Factory Implement; Flutter/Gradle/codegen/общие gates запускаются последовательно в общем командном слоте. На время check/E2E/APK и генерации координатор замораживает весь проверяемый workspace и фиксирует общий снимок/хеши; для точечных тестов фиксируются пакет и потребляемые общие зависимости. DevReviewer выполняет только проверку формата и анализ без изменения production. Общие gates не дублируются после каждой внутренней задачи.

### Проверки QA после PR
