## 1. Контекст и ожидаемый результат

Аккаунт, подтверждение закрытия и служебные экраны согласованы. Задача реализует соответствующую часть утверждённого плана; демонстрационные аккаунт/видео/задержки/локальные данные не становятся логикой приложения.

### Организация выполнения

Эта задача входит в крупный пакет A1; внутренние задачи не запускают отдельную полную цепочку. Developer последовательно завершает весь пакет, выполняет Static Gate и фиксирует состав/хеши, затем передаёт весь результат TestWriter → DevReviewer → исправления по фабрике. Developer пишет рабочий код; TestWriter — тесты; документация через DocWriter/владельца окна. До передачи могут идти локальные проверки разработчика, но новый пакетный test-report не заявляется заранее. После фиксации production-код пакета не изменяется до возврата из тестирования/ревью; новая правка повторяет затронутые gates.

## 2. Что входит в задачу (`implemented`)

1. Аккаунт показывает подтверждённый логин и инициалы; фото только из настоящего источника, новый API не вводить. Logout — отдельное подтверждённое удаление сессии; ошибка удаления не объявляет успех.
2. Back сначала закрывает панель, затем меню/вложенный маршрут, затем возвращает корневой раздел на главную. В корне главной Android показывает «Выйти из приложения?» с начальным фокусом «Остаться». Отмена сохраняет контекст; подтверждение штатно закрывает приложение без удаления аккаунта/избранного. На iOS не добавлять exit/abort.
3. Применить общие цвета/Manrope/Lucide/состояния к ошибкам маршрутов, повтору и журналу. Сохранить действия журнала и доступ только debug/profile; содержимое моноширинное. Для отсутствующих HTML-макетов использовать каноническое поведение и общие визуальные роли.
4. Логотип не становится командой закрытия. При исчезновении исходной цели возврат фокуса выбирает доступную цель; служебные ошибки безопасны и не раскрывают URI/credentials.

## 3. Что отложено (`deferred`)

- Нет временно отложенного обязательного поведения внутри результата задачи. Остальные задачи эпика — отдельные результаты, не скрытые заглушки. Эпик нельзя объявлять завершённым до выполнения всех обязательных задач.

## 4. Архитектурный контекст

- **Область записи:** `lib/packages/features/home/`; `lib/packages/features/common/`; `lib/packages/features/log_viewer/`; `lib/app/`; `lib/runner/`.
- **Переиспользование и ограничения:** Сохранить Clean Architecture: Presentation использует domain-контракты; Data преобразует публичные DTO и возвращает Result/Failure через BaseRepository. Riverpod — DI, BLoC — экранное состояние, App — маршруты. Без private src-импортов, dynamic, print, логирования HTML/cookies/credentials/signedURL; generated не менять вручную. UI Kit не знает feature-модели/предметные запросы/маршруты; загрузка изображения AppNetworkImage разрешена.
- **Критические решения:** D-01, D-02, D-03, D-09, D-10, D-12, D-13; общие D-14/D-15: goldens разрешены без повторного вопроса, commit/push только последним действием всего редизайна.
- **Подтверждённые факты и внешние условия:** EXT-01 не блокирует эту самостоятельную работу. Опоры текущего устройства: публичные контракты применимого пакета и существующие точки входа, перечисленные в утверждённом плане; точные файлы уточняются в execution brief без новых продуктовых решений.

**Границы записи:** пакет A владеет UI Kit, home, auth, common, log_viewer, App/Runner и navigation rail; пакет B — catalog (кроме rail), anime, favorites, watch_history и изменениями протокола/DTO anistar; пакет C — player. Общие файлы и документы изменяет только назначенный владелец в последовательном окне. Не откатывать чужие правки. Запрос на изменение вне своей области передаётся координатору.

## 5. Как проверить и принять

- **Проверяемый результат после PR:** Аккаунт, подтверждение закрытия и служебные экраны согласованы.

- [ ] Проверить порядок Back, «Остаться», подтверждение Android и отсутствие программного закрытия iOS; сессия сохраняется.
- [ ] Проверить успешный logout и отказ storage без ложного выхода, поздние ответы/плеер освобождены после настоящего выхода.
- [ ] Проверить visibility журнала по build mode, доступные retry/На главную и отсутствие скрытых активных целей.
- [ ] Применимые тесты, эталоны и правила архитектуры проходят на зафиксированном пакете. TestWriter сохраняет команды/результаты и tested file hashes. Все затронутые goldens можно генерировать без вопроса пользователю; PNG/diff просматриваются, затем выполняется сравнение.
- [ ] Проверки Developer/Static Gate → TestWriter → DevReviewer идут по Factory Implement; Flutter/Gradle/codegen/общие gates запускаются последовательно в общем командном слоте. На время check/E2E/APK и генерации координатор замораживает весь проверяемый workspace и фиксирует общий снимок/хеши; для точечных тестов фиксируются пакет и потребляемые общие зависимости. DevReviewer выполняет только проверку формата и анализ без изменения production. Общие gates не дублируются после каждой внутренней задачи.

### Проверки QA после PR

- [ ] Android корневой Back и повторный запуск с restore; iPhone Simulator закрывается средствами системы.
- [ ] Реальные устройство/сеть/native fixture и пропуски отражены отдельно; offline widget/golden не выдаются за live или аппаратный TV.
