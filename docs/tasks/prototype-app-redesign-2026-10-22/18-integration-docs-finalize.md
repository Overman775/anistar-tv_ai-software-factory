## 1. Контекст и ожидаемый результат

Весь редизайн согласован, проверен и сохранён commit/push. Задача реализует соответствующую часть утверждённого плана; демонстрационные аккаунт/видео/задержки/локальные данные не становятся логикой приложения.

### Организация выполнения

Эта задача входит в крупный пакет Финал; внутренние задачи не запускают отдельную полную цепочку. Developer последовательно завершает весь пакет, выполняет Static Gate и фиксирует состав/хеши, затем передаёт весь результат TestWriter → DevReviewer → исправления по фабрике. Developer пишет рабочий код; TestWriter — тесты; документация через DocWriter/владельца окна. До передачи могут идти локальные проверки разработчика, но новый пакетный test-report не заявляется заранее. После фиксации production-код пакета не изменяется до возврата из тестирования/ревью; новая правка повторяет затронутые gates.

## 5. Как проверить и принять

- **Проверяемый результат после PR:** Весь редизайн согласован, проверен и сохранён commit/push.

- [ ] Все CAP закрыты, deferred/временные заглушки отсутствуют; хеш исходного плана неизменен, спецификации и ссылки согласованы.
- [ ] Есть свежие отчёты TestWriter/DevReviewer и последовательных check/E2E/APK с проверенными хешами; пропуски/устройства/iOS ограничения явно указаны.
- [ ] Все нужные goldens просмотрены и проходят сравнение; common test helpers не записывались одновременно.
- [ ] Применимые тесты, эталоны и правила архитектуры проходят на зафиксированном пакете. TestWriter сохраняет команды/результаты и tested file hashes. Все затронутые goldens можно генерировать без вопроса пользователю; PNG/diff просматриваются, затем выполняется сравнение.
- [ ] Проверки Developer/Static Gate → TestWriter → DevReviewer идут по Factory Implement; Flutter/Gradle/codegen/общие gates запускаются последовательно в общем командном слоте. На время check/E2E/APK и генерации координатор замораживает весь проверяемый workspace и фиксирует общий снимок/хеши; для точечных тестов фиксируются пакет и потребляемые общие зависимости. DevReviewer выполняет только проверку формата и анализ без изменения production. Общие gates не дублируются после каждой внутренней задачи.

### Проверки QA после PR

- [ ] Физический TV/пульт: читаемость/плавность/blur; phone жесты/поворот; Directional Pad эмулятора. Отсутствие устройства фиксировать, не заменять screenshot-результатом.
- [ ] Реальные устройство/сеть/native fixture и пропуски отражены отдельно; offline widget/golden не выдаются за live или аппаратный TV.
