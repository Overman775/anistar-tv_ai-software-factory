## 1. Контекст и ожидаемый результат

Постеры, горизонтальные карточки и серии используют общую геометрию. Задача реализует соответствующую часть утверждённого плана; демонстрационные аккаунт/видео/задержки/локальные данные не становятся логикой приложения.

### Организация выполнения

Эта задача входит в крупный пакет A0; внутренние задачи не запускают отдельную полную цепочку. Developer последовательно завершает весь пакет, выполняет Static Gate и фиксирует состав/хеши, затем передаёт весь результат TestWriter → DevReviewer → исправления по фабрике. Developer пишет рабочий код; TestWriter — тесты; документация через DocWriter/владельца окна. До передачи могут идти локальные проверки разработчика, но новый пакетный test-report не заявляется заранее. После фиксации production-код пакета не изменяется до возврата из тестирования/ревью; новая правка повторяет затронутые gates.

A0 — единственная ранняя передача общего фундамента перед запуском его потребителей. После его приёмки направление A продолжает пакет A1; B/C используют зафиксированный публичный API. Изменение общего API запрашивается владельцу A и выполняется в последовательном окне.

## 2. Что входит в задачу (`implemented`)

1. Развить общий MediaCard в вариантах poster/landscape/episode поверх TvFocusable/TvFocusTile, AppNetworkImage/TvPosterHero, без второго обработчика ввода или загрузчика. Параметры нейтральны: подпись, изображение, метки, доступность и обработчики действий; моделей AniStar и маршрутов здесь нет.
2. Согласовать радиусы 12/10/4, рамку, clip, масштаб фокуса 1,025 без изменения компоновки, пропорции contain/cover и одинаковую геометрию изображения/заглушки. Название списка максимум две строки с полной семантической подписью; рейтинг формата 8,7 и сердце не становятся отдельными действиями.
3. AppNetworkImage сохраняет nullable URI, DPR/decode по одной оси, кеш и fallback. Hero со стабильным ID сохраняет исходный декодированный постер на первом кадре и при раннем/позднем ответе; новая картинка ждёт decode, ошибка сохраняет исходную. Без источника/reduced motion — обычный переход.
4. Сохранить короткий OK/первый системный KeyRepeat/долгое касание, поглощение хвоста клавиши и отмену при потере фокуса. Не вводить таймер long press; карточка не делает запрос подробностей по фокусу.

## 3. Что отложено (`deferred`)

- Нет временно отложенного обязательного поведения внутри результата задачи. Остальные задачи эпика — отдельные результаты, не скрытые заглушки. Эпик нельзя объявлять завершённым до выполнения всех обязательных задач.

## 4. Архитектурный контекст

- **Область записи:** `lib/packages/ui_kit/`.
- **Переиспользование и ограничения:** Сохранить Clean Architecture: Presentation использует domain-контракты; Data преобразует публичные DTO и возвращает Result/Failure через BaseRepository. Riverpod — DI, BLoC — экранное состояние, App — маршруты. Без private src-импортов, dynamic, print, логирования HTML/cookies/credentials/signedURL; generated не менять вручную. UI Kit не знает feature-модели/предметные запросы/маршруты; загрузка изображения AppNetworkImage разрешена.
- **Критические решения:** D-01, D-02, D-07, D-09, D-12, D-13, D-16; общие D-14/D-15: goldens разрешены без повторного вопроса, commit/push только последним действием всего редизайна.
- **Подтверждённые факты и внешние условия:** EXT-01 не блокирует эту самостоятельную работу. Опоры текущего устройства: публичные контракты применимого пакета и существующие точки входа, перечисленные в утверждённом плане; точные файлы уточняются в execution brief без новых продуктовых решений.

**Границы записи:** пакет A владеет UI Kit, home, auth, common, log_viewer, App/Runner и navigation rail; пакет B — catalog (кроме rail), anime, favorites, watch_history и изменениями протокола/DTO anistar; пакет C — player. Общие файлы и документы изменяет только назначенный владелец в последовательном окне. Не откатывать чужие правки. Запрос на изменение вне своей области передаётся координатору.

## 5. Как проверить и принять

- **Проверяемый результат после PR:** Постеры, горизонтальные карточки и серии используют общую геометрию.

- [ ] Компонентные проверки всех трёх вариантов: loaded/loading/no-image/error, focus/selected/watched отдельно, выросший текст, неактивное действие.
- [ ] Hero не мигает при раннем/позднем ответе/ошибке нового изображения, обратном переходе и reduced motion.
- [ ] Короткий OK активирует один раз, удержание открывает действие до release и не активирует затем панель повторно.
- [ ] Применимые тесты, эталоны и правила архитектуры проходят на зафиксированном пакете. TestWriter сохраняет команды/результаты и tested file hashes. Все затронутые goldens можно генерировать без вопроса пользователю; PNG/diff просматриваются, затем выполняется сравнение.
- [ ] Проверки Developer/Static Gate → TestWriter → DevReviewer идут по Factory Implement; Flutter/Gradle/codegen/общие gates запускаются последовательно в общем командном слоте. На время check/E2E/APK и генерации координатор замораживает весь проверяемый workspace и фиксирует общий снимок/хеши; для точечных тестов фиксируются пакет и потребляемые общие зависимости. DevReviewer выполняет только проверку формата и анализ без изменения production. Общие gates не дублируются после каждой внутренней задачи.

### Проверки QA после PR

- [ ] Проверить геометрию карточек и читаемость на TV/телефоне по одинаковым образцам HTML.
- [ ] Реальные устройство/сеть/native fixture и пропуски отражены отдельно; offline widget/golden не выдаются за live или аппаратный TV.
