## 1. Контекст и ожидаемый результат

Мобильный плеер сохраняет контроллер при повороте и жизненном цикле. Задача реализует соответствующую часть утверждённого плана; демонстрационные аккаунт/видео/задержки/локальные данные не становятся логикой приложения.

### Организация выполнения

Эта задача входит в крупный пакет C; внутренние задачи не запускают отдельную полную цепочку. Developer последовательно завершает весь пакет, выполняет Static Gate и фиксирует состав/хеши, затем передаёт весь результат TestWriter → DevReviewer → исправления по фабрике. Developer пишет рабочий код; TestWriter — тесты; документация через DocWriter/владельца окна. До передачи могут идти локальные проверки разработчика, но новый пакетный test-report не заявляется заранее. После фиксации production-код пакета не изменяется до возврата из тестирования/ревью; новая правка повторяет затронутые gates.

## 2. Что входит в задачу (`implemented`)

1. Перенести touch-компоновку: центральные транспортные кнопки, верхние инструменты, шкала/±10 сек/серии/качество/поворот, общие иконки/состояния. Сохранять отдельный mobile profile независимо от окна, без мини-плеера/cast/PiP/новых жестов.
2. Касание видео показывает/скрывает управление по действующему контракту, semantic tap выполняет те же действия. Scrubbing удерживает idle до конца жеста; pause/completed/панель сохраняют видимость, панель исключает команды фону.
3. Поворот/изменение constraints сохраняют controller, качество, позицию и паузу. Уход в фон останавливает видео и hold-screen; возврат возобновляет лишь игравшее раньше. Back/logout/origin change освобождают listener/focus/timer/controller и восстанавливают system UI/orientation.
4. Удержание экрана остаётся только для активного foreground initialized playing без buffering/completed/error. Не менять нативный engine/канал и восстановление прежнего idle timer ради нового UI; iOS результаты ограничивать Simulator и реально выполненной нативной fixture-проверкой.

## 3. Что отложено (`deferred`)

- Нет временно отложенного обязательного поведения внутри результата задачи. Остальные задачи эпика — отдельные результаты, не скрытые заглушки. Эпик нельзя объявлять завершённым до выполнения всех обязательных задач.

## 4. Архитектурный контекст

- **Область записи:** `lib/packages/features/player/`.
- **Переиспользование и ограничения:** Сохранить Clean Architecture: Presentation использует domain-контракты; Data преобразует публичные DTO и возвращает Result/Failure через BaseRepository. Riverpod — DI, BLoC — экранное состояние, App — маршруты. Без private src-импортов, dynamic, print, логирования HTML/cookies/credentials/signedURL; generated не менять вручную. UI Kit не знает feature-модели/предметные запросы/маршруты; загрузка изображения AppNetworkImage разрешена.
- **Критические решения:** D-01, D-03, D-09, D-12, D-13; общие D-14/D-15: goldens разрешены без повторного вопроса, commit/push только последним действием всего редизайна.
- **Подтверждённые факты и внешние условия:** EXT-01 не блокирует эту самостоятельную работу. Опоры текущего устройства: публичные контракты применимого пакета и существующие точки входа, перечисленные в утверждённом плане; точные файлы уточняются в execution brief без новых продуктовых решений.

**Границы записи:** пакет A владеет UI Kit, home, auth, common, log_viewer, App/Runner и navigation rail; пакет B — catalog (кроме rail), anime, favorites, watch_history и изменениями протокола/DTO anistar; пакет C — player. Общие файлы и документы изменяет только назначенный владелец в последовательном окне. Не откатывать чужие правки. Запрос на изменение вне своей области передаётся координатору.

## 5. Как проверить и принять

- **Проверяемый результат после PR:** Мобильный плеер сохраняет контроллер при повороте и жизненном цикле.

- [ ] Portrait/landscape/узкий экран/200%: контроллер не пересоздан, действия доступны и единственны.
- [ ] Scrub/idle/pause/semantic tap/панель не конфликтуют; отсутствует pull-to-refresh в player.
- [ ] Lifecycle/rotation/dispose/late init/hold-screen и системный UI проверены fake/native применимым уровнем.
- [ ] Применимые тесты, эталоны и правила архитектуры проходят на зафиксированном пакете. TestWriter сохраняет команды/результаты и tested file hashes. Все затронутые goldens можно генерировать без вопроса пользователю; PNG/diff просматриваются, затем выполняется сравнение.
- [ ] Проверки Developer/Static Gate → TestWriter → DevReviewer идут по Factory Implement; Flutter/Gradle/codegen/общие gates запускаются последовательно в общем командном слоте. На время check/E2E/APK и генерации координатор замораживает весь проверяемый workspace и фиксирует общий снимок/хеши; для точечных тестов фиксируются пакет и потребляемые общие зависимости. DevReviewer выполняет только проверку формата и анализ без изменения production. Общие gates не дублируются после каждой внутренней задачи.

### Проверки QA после PR

- [ ] Android phone fixture: поворот/фон/возврат/seek/качество; iPhone Simulator сборки отдельно, без нативной fixture-проверки не заявлять AVFoundation/HLS/Keychain.
- [ ] Реальные устройство/сеть/native fixture и пропуски отражены отдельно; offline widget/golden не выдаются за live или аппаратный TV.
