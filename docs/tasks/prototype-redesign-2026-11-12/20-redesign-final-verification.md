## 2. Task scope (`implemented`)

1. Объединить карты покрытия до и после миграции. Для каждого затронутого PNG проверить владельца, профиль, логический размер, DPR, масштаб текста, сцену и решение по файлу. Сверить все размеры и состояния матрицы, включая покрытие уникальных состояний и компактного нативного окна. Убедиться, что удалённые ожидания TV-сетки, Hero и раскрытой карточки имеют проверенную замену. После всех записей выполнить `fvm dart run melos run test:goldens` без выборки и режима обновления.
2. На финальном дереве сверить с AC-01–AC-17 компоненты, семантику и геометрию. Проверить общее оформление запуска, интро, входа, каталога, аниме, панелей, ошибок и плеера в обоих профилях. Подтвердить рамку, свечение и различимость выбора без сдвига. Сверить `PRODUCT.md`, спецификации, ссылки и README с реализованными контрактами.
3. После миграции независимый Judge запускает применимые статические проверки после всех писателей, затем последовательно `fvm dart run melos run check`, `fvm dart run melos run test:e2e`, `fvm dart run melos run build:android:prod:apk`. Команды итоговой последовательности запускаются без выборочных селекторов. Android E2E использует фикстуры TV и телефона. Flutter, Gradle и codegen сериализованы. Judge выполняет verify, затем независимый review. Изменения после проверки требуют актуальных результатов на исправленном дереве.

## 4. Architectural context

- **Scope:** test, integration_test и проектные проверки из корня workspace.
- **Reuse:** Действующий Android fixture runner, карта AC и golden-матрица ревизии 3; проектный профиль отделяет выборочные проверки от итоговых.
- **Critical decisions:**

  - D-01. Применить визуальные роли handoff через общий UI Kit и определять нативный профиль по устройству. Размеры служат ориентирами в logical pixels. Крупный текст сохраняет действия без обрезки. У визуальных 36 для метаданных область касания 48 без пересечения соседних целей. Дополнительной внешней рамки у ролей из handoff нет.
  - D-07. Использовать действующие контракты доступа, поиска, избранного и плеера. Минимум поиска 2, порция из четырёх, 19/29 записей, специальные слова, искусственные ошибки и тестовое видео принадлежат демонстрации.
  - D-09. Обновить экранные эталоны под новый дизайн и проверять все три логических размера TV 16:9. Заменить устаревшие ожидания после подтверждения покрытия новых состояний. Мобильные и компонентные снимки используют размеры своей сцены.
  - D-10. При нехватке высоты TV сохранить ленту и доступ к действиям, разрешив прокрутку верхнего блока целиком. Сначала описание сокращается до доступных целых строк. Когда обязательные элементы всё ещё не помещаются, верхний блок получает вертикальную прокрутку к фокусу. Шрифт сохраняет системный масштаб, кнопки растут по содержимому, собственного скролла у описания нет. Полное описание доступно в подробностях. В обычной компоновке действуют геометрия и переносы handoff.

- **Verified facts and external conditions:**

  - EXT-01. На фикстурах проверить критерии, направления, изоляцию и продолжение. Многоэлементный пример и вторая страница остаются границей живого подтверждения.
  - EXT-02. Визуальное совпадение, плавность на слабом TV и нативная IME зависят от среды. При отсутствии устройства QA указывает, что осталось непроверенным.

Зафиксировать модель, профиль, logical size и DPR, включая TV 960×540, 1280×720 и 1920×1080 и телефон 360–430 в обеих ориентациях. Физические 1920×1080 при DPR 2 соответствуют 960×540 logical px.
