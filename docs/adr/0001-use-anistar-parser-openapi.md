# ADR-0001: AniStar Parser и OpenAPI-клиент

## Статус

Принято, 2026-07-18.

## Контекст

HTML AniStar и прямые player URL не являются стабильным контрактом для TV-клиента. Parser уже предоставляет типизированные данные, переписанные HLS-манифесты и короткоживущие сессии.

## Решение

Клиент использует AniStar Parser как единственную границу данных и просмотра. `openapi/anistar.openapi.json` генерирует `packages/anistar_api/`; репозитории переводят DTO в модели приложения. Перед каждым просмотром создаётся новая playback-сессия, а HLS воспроизводится через нативный `video_player`.

## Последствия

- Нет HTML/JW-скрейпинга, WebView и прямых CDN URL в клиенте.
- Контракт воспроизводимо обновляется из OpenAPI-схемы.
- Для работы приложения нужен доступный parser endpoint.
- Истёкшая HLS-сессия требует нового `getPlaybackInfo` запроса.
