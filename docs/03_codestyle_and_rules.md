# 📏 Code Style и TV UI | AniStar TV

Используйте Dart formatter и [проверки Melos](melos_tooling.md). Правила Analyzer заданы в `analysis_options.yaml` и конфигурации пакетов. Версия DCM закреплена в `dcm_global.yaml`.

## 1. Обязательные правила

Включены `strict-casts`, `strict-inference` и `strict-raw-types`. Устраняйте замечания Analyzer и DCM. Исключение требует объяснения и необходимости.

- Для неизвестного типа используйте `Object?` и явные проверки типов.
- Логируйте через `Logger`. Импортируйте публичные библиотеки пакетов.
- Реализуйте границу репозитория через `BaseRepository` и `Result`/`Failure`.
- Обновляйте generated files командой генерации из исходников.

## 2. Имена и структура

| Элемент | Формат | Пример |
| :--- | :--- | :--- |
| Тип, enum, extension | `UpperCamelCase` | `PlaybackSession` |
| Файл или каталог | `snake_case` | `playback_repository.dart` |
| Переменная, метод, константа | `lowerCamelCase` | `createSession`, `maxRetries` |
| Boolean | `is`, `has`, `can`, `should` | `hasNext` |
| Callback | `on` и действие | `onEpisodeTap` |
| Private member | Префикс `_` | `_controller` |

Называйте тип по пользовательской области и операции. Выделяйте общий контракт, когда появляется вторая реальная потребность.

### Локальная форма кода

- Допускаются короткие guard clauses и простые однострочные тела без скобок. Сохраняйте блок для нескольких операций, локальной области видимости или неоднозначного вложенного `if`/`else`.
- Пользуйтесь выводом типа, если тип очевиден. Явный тип помогает, когда уточняет смысл или контракт.
- Сохраните snapshot для повторного использования того же значения, в том числе через `await`. Читайте состояние заново, если нужен актуальный результат.
- Оставьте расположение строк и trailing commas Dart formatter.

## 3. Слои и обработка ошибок

Используйте `BaseRepository.makeApiCall` для общего маппинга ошибок. Локальный `try/catch` нужен для явного восстановления или преобразования специального контракта. Data возвращает ожидаемый отказ сайта как `Failure`, а Presentation переводит `Result` в состояние UI. Fallback допустим, если предусмотрен контрактом. Неизвестная HTML-разметка и неподтверждённое изменение избранного остаются ошибками. [Архитектура ошибок](01_architecture_principles.md#5-результаты-ошибки-и-навигация).

## 4. Async и состояние виджета

- Запускайте запросы и побочные эффекты через событие BLoC, provider/notifier или lifecycle экрана. `build()` может выполняться повторно.
- После `await` проверьте `mounted` или `context.mounted` перед обновлением состояния виджета или использованием `BuildContext`.
- Для `unawaited(...)` укажите обработку ошибок или используйте существующий общий обработчик.
- Закрывайте subscriptions, timers, focus nodes и native controllers в lifecycle владельца.

Оставляйте короткий локальный callback inline. Выделяйте helper или `Widget` для самостоятельной ответственности, повторного использования или ясного владения ресурсом. Отдельный `Widget` подходит для самостоятельного визуального блока, если упрощает rebuild и тестирование. Сама метрика длины `build()` не требует декомпозиции.

## 5. Логи и чувствительные данные

Указывайте источник события типизированным методом, например `logger.infoFor<CatalogBloc>('Catalog loading started')`. Исключайте credentials, пароли, Cookie/Set-Cookie, raw HTML, POST body, signed CDN URI и `native errorDescription`. [Допустимые сетевые метаданные](04_network_and_playback.md#5-восстановление-и-lifecycle).

## 6. TV и mobile интерфейсы

TV управляется пультом. Для layout и controls прочитайте [ADR-0008](adr/0008-youtube-tv-interaction-reference.md), [TV-контракт](specs/06_tv_interaction.md) и применимый [mobile-контракт](specs/10_mobile_interaction.md).

При изменении экрана проверьте начальный видимый focus, переходы стрелок, OK, удержание, Back и возврат focus после панели, dialog, ошибки или загрузки. Проверяйте асинхронную загрузку и системное уменьшение анимаций. Используйте TV viewport **960×540** и **1280×720** logical pixels. Для mobile берите compact и wide портретные размеры из существующих тестов.

Экранный компонент и раскладка сетки принадлежат feature до появления общего контракта. [Визуальная система](specs/11_visual_system.md), [анимации](specs/08_motion.md).

## 7. UI Kit и ресурсы

Тему предоставляет `AppTheme`. Цвета и общие роли текста берите из `colorScheme`, `textTheme`, `AppPalette` и `AppTypography`. Контентные роли карточек определяет `AppContentTypography`. Общие токены размеров, отступов, радиусов, focus и движения описаны в [UI Kit](../lib/packages/ui_kit/README.md). Для изображений и ожидания доступны `AppNetworkImage` и `TvSkeleton`.

Импортируйте ресурсы через FlutterGen exports из `package:ui_kit/assets.dart`. После изменения исходных ресурсов выполните применимую [генерацию Melos](melos_tooling.md) и проверьте diff.

## 8. Изменение правил

При изменении lint, архитектурной границы, UI-контракта или публичного API обновите правило у его владельца. Форму кода оценивайте по [ADR-0011](adr/0011-compact-code-analysis-policy.md).
