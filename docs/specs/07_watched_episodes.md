# ✅ Просмотренные серии | AniStar TV

## 1. Источник истины

История принадлежит авторизованному аккаунту AniStar. 10 октября 2026 года повторно исследована страница плеера `10938` с cookies тестового аккаунта. В авторизованном HTML `logVideoViewing()` отправляет `GET /engine/ajax/ns.php?vid={media_id}` через `new Image()`. После запроса свежий player HTML возвращает `viewing: true` у соответствующей серии. Гостевой HTML этого запроса не содержит. Прежний вывод только о localStorage основан на гостевой странице и заменён этим контрактом.

Браузер дополнительно использует localStorage для позиции и своих отметок. Клиент читает серверный `viewing`; браузерное хранилище и локальные отметки старой версии приложения не импортируются. Проверка с новым HTTP-клиентом/перезапуском приложения должна получать состояние аккаунта с сайта.

## 2. Чтение и отображение

GET `/test/player2/videoas_p2p_new.php?id={animeId}` выполняется с Cookie текущей сессии. Номер серии и `media_id` берутся из того же объекта `playlst`; порядок элементов/URL значения не имеет. Только boolean `viewing: true` означает просмотренную серию, строки `"true"` и отсутствующее поле не считаются отметкой.

`WatchedEpisodesRepository.getWatched` возвращает номера, подтверждённые этим HTML. Галочка в карточке и подпись «просмотрена ✓» в диалоге берутся из HTML либо подтверждённого состояния repository в памяти. У непросмотренной серии галочки нет. Semantics включает «просмотрена». Выбор текущего пункта диалога — отдельная отметка выбора.

## 3. Запись

1. Дождаться успешного native play: `isPlaying == true`. Загрузка карточки, HLS, выбор серии и неудачная initialization историю не меняют.
2. Получить свежий player HTML и найти выбранную серию по номеру. Если `viewing: true` уже есть, вернуть серверное состояние без mutation.
3. При отсутствии серии или строкового непустого `media_id` завершиться ошибкой. Не вычислять ID по номеру/URL и не подставлять ID соседней серии.
4. Выполнить GET `/engine/ajax/ns.php` с query `vid={media_id}`, Cookie и Referer страницы плеера этого аниме на текущем origin. Cookies не передаются CDN.
5. Повторно получить player HTML. Только `viewing: true` выбранной серии подтверждает запись. HTTP 200 и короткое тело ответа сами по себе успеха не доказывают.
6. Обновить набор подтверждённых номеров в UI. Возврат из плеера сразу показывает галочку; новый клиент получает её с сайта.

Клиент отмечает начало просмотра сразу после успешного запуска, как запрошено для приложения. Сайт вызывает `logVideoViewing()` после своего порога `timerView > 5`. Это отметка начала, а не досмотра до конца. Смена качества не создаёт дополнительную отметку уже начатой серии.

## 4. Сессия, ошибки и повтор

Анонимный клиент не читает и не записывает историю аккаунта. Смена аккаунта, logout и закрытие protected router не должны публиковать ответ прежней сессии. Cookies из Secure Storage/CookieJar определяют аккаунт на сайте; отдельного постоянного локального списка просмотренных серий больше нет. Старые ключи `anistar.watched.v1.*` игнорируются и не отправляются на сайт автоматически.

Записи сериализуются. Mutating GET исключён из автоматических transport retry; после timeout/смены зеркала запрос не переигрывается. Ручной новый запуск сначала перечитывает сайт, поэтому уже применённая отметка повторно не отправляется. Ошибка первоначального чтения не препятствует следующей явной попытке с новым чтением.

При отказе отметки UI не добавляет неподтверждённую галочку. Видео продолжает работать; действующий player показывает «Не удалось сохранить отметку просмотра». Ошибка истории не запускает refresh HLS и не повторяется на каждом native событии. Поздний результат после ухода не показывает сообщение.

Снятие отметки, сохранение позиции и процент досмотра не реализованы: подтверждённого протокола для них нет. Перенос браузерной позиции также не входит в контракт.
