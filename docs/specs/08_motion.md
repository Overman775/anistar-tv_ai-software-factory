# Анимации | AniStar TV

Спецификация определяет визуальные переходы интерфейса, общие токены и ограничения доступности движения. Она не задаёт сетевые таймауты, жесты удержания или интервалы управления воспроизведением. Цвет и типографика заданы [визуальной системой](11_visual_system.md). Ориентир характера переходов — [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md).

## 1. Общие принципы

Анимация объясняет переход между состояниями и сохраняет связь с выбранным сериалом. Без пружин, вращения, сильного zoom и последовательного появления каждой серии. Управление пультом не ждёт завершения декоративного эффекта.

Ориентир поведения и характера переходов — YouTube для телевизоров по [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md). Длительности и кривые ниже — собственные токены AniStar TV. Цвет и типографика заданы [визуальной системой](11_visual_system.md). Это не измерения стороннего приложения. Токены принадлежат UI Kit. Feature использует AppMotion, а навигация остаётся в app. Дополнительные animation-пакеты не нужны.

## 2. Длительности и кривые

| Токен | Значение / назначение |
| --- | --- |
| fast | 160 мс: масштаб карточки при focus, метка, смена раздела, controls, переход player |
| standard | 240 мс: раскрытие меню, затемнение каталога, прокрутка к focus |
| page / pageReverse | 280 / 200 мс: открытие / закрытие страницы |
| panes | 240 / 156 мс: открытие / закрытие левой или правой панели |
| focusExit | 104 мс: уход с фокусируемого элемента |
| focusBorderEnter / focusBorderExit | 280 / 200 мс: проявление / исчезновение цвета общей рамки фокуса |
| inspectorDwell | 150 мс: задержка перед сменой содержимого инспектора |
| inspectorContent | 280 мс: последовательное исчезновение старого и появление нового содержимого через два буфера |
| enterCurve / exitCurve | easeOutCubic / easeInCubic, без overshoot |
| shimmer | 1100 мс: цикл skeleton |
| durationOf / reducedOf | Учитывают disableAnimations и accessibleNavigation |

Playback timeout, refresh budget, удержание OK, ускорение seek (500 мс повтор) и idle timer controls (4 секунды) — поведение функций; это не длительности декоративных анимаций.

## 3. Переходы постера

Одинаковый TvPosterHero с тегом `anime-poster-{id}` используется в каталоге, избранном и карточке сериала. Скругление сохраняется в overlay. Прямоугольник движется напрямую, без дуги. Cached image не запускает отдельный fade для одинакового URL внутри Hero.

AnimeRoute получает выбранный AnimeSummary через временный `$extra`. TvPosterHero использует один исходный memory-cache key во всех размерах. Поэтому изменение bounds в полёте не запускает новый decode с заглушкой. Остальные AppNetworkImage сохраняют resize по layout/DPR.

Постер доступен в первом кадре AnimeSkeleton, до ответа сайта. Skeletonizer его не закрашивает. PlayerRoute передаёт тот же extra родительской карточке, чтобы постер сохранялся после возврата из player. Extra не добавляет URL постера в query и не заменяет данные repository.

Если HTML пришёл во время Hero, skeleton с постером остаётся до завершения входного route transition. Затем показываются подробности. Если у подробностей другой URL постера, исходный постер остаётся под новым изображением до его декодирования. Новое изображение проявляется за AppMotion.fast. Ошибка загрузки сохраняет исходный постер. Это правило действует и для фонового изображения hero.

Reduced motion отключает fade, но сохраняет постер во время загрузки.

Hero сохраняет декодированное изображение на каждом кадре перехода при раннем и позднем ответе HTML. Это относится к переходам из каталога и избранного; загрузка, начавшаяся во время полёта, не заменяет изображение пустой заглушкой.

Offstage layout, которым HeroController измеряет конечную позицию, не считается завершением перехода. Поздний ответ после Back не возвращает экран и не создаёт новую анимацию.

При открытии без extra используется обычный skeleton; отсутствие постера или ошибка загрузки изображения не блокируют переход. Возврат в каталог/избранное сохраняет выбранную вкладку, focus и прокрутку. Если исходная карточка уже не существует, применяется обычный переход страницы.

## 4. Переходы экранов и элементов

Карточка сериала появляется за 280 мс с fade и небольшим вертикальным сдвигом 2% высоты; обратный переход занимает 200 мс. Player использует только fade: native video не масштабируется и не участвует в Hero. Back проигрывает обратный переход.

Смена раздела Главная/Избранное даёт короткий fade-in только новому содержимому. CatalogScreen и левое меню остаются смонтированными. Ключ анимации принадлежит содержимому. Смена источника данных заменяет CatalogBloc и сбрасывает прокрутку карточек. Ширина, непрозрачность и фокус меню не сбрасываются, в том числе при быстрых переключениях.

Исходящий каталог не удерживается ради crossfade. Это исключает дублирование Hero-тегов, focus и запросов. Подтверждённое сайтом сердце плавно появляется или исчезает. Это не оптимистическое изменение избранного.

Левое меню раскрывается по фокусу: ширина 88 → 264 logical pixels, подписи проявляются, содержимое за меню затемняется. Открытие занимает 240 мс, закрытие — 156 мс. При уходе фокуса эффект идёт обратно. Используется standard и enterCurve; сетка не перестраивается на промежуточных кадрах. Смена фокуса во время перехода должна приводить к последнему запрошенному состоянию без блокировки ввода.

TvSideSheet открывается с правого края через showTvSideSheet: Offset(1, 0) → Offset.zero с enterCurve и затемнением фона за 240 мс. Закрытие занимает 156 мс. Этот переход общий для действий избранного, качества и серии. Фокус принадлежит панели всё время её работы; закрытие восстанавливает цель по правилам [TV-взаимодействия](06_tv_interaction.md).

Карточки каталога и избранного, карточки серий и строки выбора серии/качества используют общий визуальный контракт [спецификации 11](11_visual_system.md) и UI Kit для рамки и переходов focus. Карточки умеренно увеличиваются, строки выбора сохраняют размер и геометрию. Рамка и изображение сохраняют согласованный контур с учётом толщины рамки; изображение и заглушка используют одинаковое скругление, а Hero сохраняет его на обоих концах перехода. Увеличение не обрезает рамку и не перекрывает соседние элементы.

TV-инспектор ждёт 150 мс после нового фокуса на карточке, затем последовательно скрывает прежнее содержимое и показывает новое. Два текстовых буфера находятся в одном контейнере. Во время перехода контейнер сохраняет высоту большего из двух содержимых и симметричные вертикальные отступы. Высота не анимируется, а карточки сетки не перестраиваются ради смены текста. После 280 мс исходящий буфер сразу освобождает место; естественная высота нового содержимого может отличаться. Фокус сразу обновляет доступную цель. Новая карточка отменяет незавершённую задержку и переход предыдущей. Инспектор использует уже доступные сведения и не запрашивает полную карточку только из-за фокуса. Видимая и семантическая подписи не дублируют друг друга.

Общая рамка UI Kit меняет только цвет: вход занимает 280 мс с easeOutCubic, выход — 200 мс с easeInCubic. Геометрия рамки не меняется, а перемещение фокуса происходит сразу. У карточек сохраняется существующий scale. Focus-масштаб, прокрутка и controls используют свои токены durationOf; их длительности не заменяют отдельные токены рамки. При системном уменьшении анимаций декоративное движение отсутствует, а видимый focus остаётся. Эффекты не меняют выбранную серию, просмотренную серию, статус аккаунта или позицию воспроизведения.

## 5. Доступность движения

При disableAnimations или accessibleNavigation durationOf возвращает ноль; проявление и исчезновение общей рамки происходят сразу без fade; HeroMode отключает полёт постера, страницы, разделы и боковые панели переключаются сразу, shimmer заменяется статическим цветом. Видимый focus сохраняется.

## Мобильная компоновка

[Мобильный профиль](10_mobile_interaction.md) сохраняет общие AppMotion, route fade и Hero постера. Loading и ready карточки имеют согласованную геометрию постера; native video не участвует в Hero и не масштабируется декоративной анимацией.

TV-панели сохраняют выезд справа. Мобильные действия используют стандартный переход Material bottom sheet снизу, закрытие кнопкой, системным Back или штатным dismiss. Содержимое и подтверждение действия общие, а направление панели определяется профилем устройства. Системное уменьшение анимаций сохраняет команды и конечные состояния.

В нижней навигации посещённые разделы остаются смонтированными. HeroMode и TickerMode активны только в видимом разделе: скрытый каталог не создаёт второй Hero endpoint и не продолжает декоративные ticker-анимации. Переключение вкладок сохраняет прокрутку без перелёта карточек между разделами.

Верхняя мобильная шапка скрывается при прокрутке вниз и возвращается при прокрутке вверх, освобождая высоту toolbar. Нижняя навигация остаётся доступна. Переход использует fast/enterCurve, ограничен шапкой и не пересоздаёт каталог. При reduced motion смена высоты происходит сразу. accessibleNavigation сохраняет шапку видимой для стабильных целей.

Короткие списки не скрывают шапку от overscroll. Закрытая панель не оставляет невидимую цель фокуса. Blur нижней панели ограничен её прямоугольником, не анимируется и не распространяется на всю страницу.

Поворот телефона меняет компоновку controls и карточки по доступным ограничениям, сохраняя controller, качество, позицию и паузу. Он не запускает новую серию и не меняет профиль. Проверки мобильных controls и снимки portrait/landscape выполняются отдельно от неизменённых TV-goldens; результаты относятся к тестовой среде, а не физическому устройству.

Мобильный pull to refresh использует стандартное движение `RefreshIndicator` над вертикальным содержимым; отдельные анимационные токены и задержки не вводятся. Индикатор ждёт сеть, а успешные данные заменяют прежние без skeleton и crossfade. Жест от начала списка сохраняет шапку видимой и не двигает нижнюю навигацию. В landscape-карточке с закреплённым просмотром обновляется только прокручиваемая часть. В TV и плеере этого жеста нет.

Nullable poster сохраняет прежнюю заглушку и Hero tag по ID без запроса пустого URL. Смена сортировки передаёт новый неизменяемый источник через CatalogStarted; generation отсеивает позднюю выдачу. Геометрия, focus и AppMotion не изменены.

## Дополнительные правила применения AppMotion

Ряд фильтров карточки и экран жанров прокручиваются к фокусу за AppMotion.fast с учётом reduced motion. Открытие результата сохраняет исходный маршрут и фокус; обратный переход возвращает к той же метке. Контракт данных и пульта: [жанры и фильтры](09_catalog_filters.md).

Сортировка жанра использует ту же правую TvSideSheet. При применении старые карточки сразу заменяются skeleton новой первой страницы; crossfade двух выдач не используется. Возврат из панели сохраняет фокус кнопки сортировки, прокрутка строк панели использует AppMotion.fast.

Меню слева и справа, сортировка и фильтры используют общую рамку и роли поверхности спецификации 11; фокус различим относительно обычного и выбранного состояния. Текст остаётся светлым. Плашки фильтров меняют оформление за AppMotion.fast с учётом reduced motion; свечение не требует backdrop blur. Карточка аниме сохраняет масштабирование, рамку и свечение при фокусе, без дополнительного значка Play поверх постера.

Right в левом меню и Left в правой панели запускают стандартное закрытие с восстановлением фокуса; ввод не ждёт анимации. Кнопки управления player используют общий стиль выделения UI Kit. Fade controls сохраняет AppMotion.fast; скрытие по idle возвращает focus видео сразу, без ожидания fade. Reduced motion не меняет интервалы seek и idle.

При увеличенном тексте прокрутка к hero-действию использует AppMotion.fast и durationOf; в reduced motion действие становится видимым сразу. Постер при увеличении текста не растёт вместе с высотой hero. Декодирование сетевых изображений ограничивается одной осью по текущей геометрии и DPR, сохраняя пропорции и исходник дискового кеша для крупного detail/Hero. Семейство шрифта темы и общие роли принадлежат спецификации 11; они не дублируются в motion-контракте.

Typeset сохраняет длительности, кривые и направления фокуса. Высота фильтров, шапки меню и строк выбора учитывает системный текст до прокрутки; ensureVisible использует прежние fast/durationOf. Таймер player выводится табличными цифрами, чтобы изменение времени не сдвигало текст.

Harden использует fast/durationOf для раскрытия фокуса формы входа и кнопки состояния; reduced motion делает их видимыми без анимации. Переходы ошибки/повтора не добавляют отдельного эффекта и не удерживают старые данные для crossfade. Изменение числа колонок жанров вызвано системным текстом, а не анимацией.

Optimize сохраняет fade controls, focus nodes и native controller. Когда controls скрыты, обновления позиции/буфера сохраняются без перестроения PlayerView; изменения буферизации, ошибки, инициализации и aspect ratio продолжают обновлять экран. Открытие controls сразу использует текущее значение controller. Подписка снимается при его замене и dispose; интервалы idle/seek и reduced motion не меняются.

StartupScreen не задерживает переход после ответа сети ради декоративной анимации. Загрузка обозначена стандартным CircularProgressIndicator и сменой liveRegion-текста; проверка сайта/сессии имеет сетевую длительность, не таймер AppMotion. Ошибка заменяет индикатор сообщением и кнопкой без route-анимации; прокрутка к фокусу повтора использует fast с учётом reduced motion.
