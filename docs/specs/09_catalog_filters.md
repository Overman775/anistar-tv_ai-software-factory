# Жанры, метки и сортировка каталога | AniStar TV

Спецификация задаёт переходы по жанрам и меткам аниме, а также серверную сортировку выбранного каталога. Фильтр действует только в собственном маршруте и сохраняет исходный путь сайта. Правила TV focus согласованы с [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md); общие правила пагинации наследуются из [контракта загрузки страниц](03_page_loading.md).

## 1. Жанры и метки

В левом меню после «Избранное» расположен пункт «Жанры». Выбор этого пункта по OK открывает встроенный экран «Аниме по жанрам». Список загружается из блока `.block-janrs` страницы `/anime/` активного зеркала. Сайт задаёт названия и адреса. Приложение не содержит отдельный справочник переводов и не подменяет отсутствующие жанры выдуманными ссылками.

Экран показывает жанры плитками: две колонки на узком экране, три при ширине от 600, четыре от 1100 logical pixels. Все плитки доступны с пульта, включая строки за пределами экрана. Фокус прокручивает выбранную плитку в видимую область. Пока список загружается, доступен возврат. После загрузки начальный фокус получает первый жанр; после ошибки или пустого списка — «Повторить». Запрос повторяется только по действию пользователя, без автоматического цикла Riverpod.

В карточке аниме год, жанр и режиссёр становятся самостоятельными фильтрами только при наличии пригодной исходной ссылки, поддержанной проверенным протоколом EXT-01. Категории и ранее поддержанные метки сохраняются. Повторяющиеся адреса и названия без учёта регистра убираются. При совпадении названия категории и жанра приоритет получает первая ссылка в документе. Без пригодной ссылки метаданные остаются текстом. URL не строится по видимому названию и не изменяется локальной нормализацией.

Выбор жанра, года, режиссёра или метки открывает отдельный каталог с названием выбранного фильтра. Отображаются результаты сайта, а не локальная выборка уже загруженных карточек. Одновременно применяется один подтверждённый адрес каталога; сочетания нескольких фильтров не создаются. Сортировка применяется сервером ко всей выдаче выбранного адреса.

## 2. Навигация и возврат

Жанры и метки остаются доступными на 960×540, 1280×720 и 390×844. Горизонтальный список меток прокручивается до focus и сохраняет полный набор ссылок.

| Контекст | Действие |
| --- | --- |
| Левое меню | Up/Down перемещают фокус; OK на «Жанры» открывает экран. Сам фокус не выполняет запрос раздела. |
| Список жанров | Left/Right — соседняя плитка в строке без переноса; Up/Down — соседняя строка. В неполной последней строке Down выбирает последнюю плитку. |
| Верхний ряд жанров | Up переводит на «Назад»; Down с «Назад» возвращает к первой плитке. |
| Плитка жанра | OK/Enter/Space/gameButtonA и touch открывают один и тот же каталог. Удержание не имеет отдельного действия. |
| Кнопки «Смотреть» / избранное в карточке | Up переводит к последней выбранной метке, при первом входе — к первой. |
| Ряд меток | Left/Right перемещают фокус и прокручивают ряд; край останавливает движение. Down возвращает к основному действию. Up — к возврату в AppBar. |
| Возврат в AppBar карточки | Down ведёт к запомненной метке; без ссылок — к основному действию, как прежде. |
| Отфильтрованный каталог | Обычная сетка каталога и пагинация. Left на первой карточке ряда открывает левое меню с возвратом, жанрами и обновлением. |
| Back | Сначала сворачивает раскрытое меню. Следующий Back закрывает каталог и возвращает к исходной метке или жанру. Возврат из карточки восстанавливает карточку и прокрутку списка. |

Начальный фокус карточки аниме остаётся на «Смотреть» (при отсутствии серий — на избранном). Новые метки его не перехватывают. Горизонтальный ряд показывает все доступные ссылки, не обрезая набор до трёх; сфокусированная метка видна целиком. В мобильном профиле крупный постер расположен над сведениями и действиями и остаётся видимым при загрузке. Компоновка не заменяет его компактным постером рядом с метаданными.

Маршруты `/genres` и `/browse` открываются поверх источника. `/browse` содержит `path` и `title`; новый адрес получает отдельный экземпляр каталога и Bloc. Карточка и player открываются поверх текущего маршрута, чтобы не терять цепочку возврата. Сам фильтр не сохраняется как глобальное состояние главной страницы.

## 3. Источники каталога и загрузка

Наблюдение сайта 2026-10-11: [каталог](https://v30.astar.bz/anime/), [комедия](https://v30.astar.bz/comedy/), [категория комедии](https://v30.astar.bz/anime/comedy/), [онгоинги](https://v30.astar.bz/new/). В меню используются короткие пути вроде `/comedy/`, а пагинация той же страницы может содержать `/anime/comedy/page/2/`. Жанры в `ul.head` могут вести на `/filter/janrs/%EA%EE%EC%E5%E4%E8%FF/`: это исходные percent-encoded байты Windows-1251, а не UTF-8.

Приложение сохраняет исходный path. Оно не декодирует и не перекодирует его. Origin берётся из текущего AnistarClient. Для ссылок HTML проверяются origin и форма пути. Проверяется также отсутствие query и fragment. Ссылки на сторонние домены и служебные поля не становятся метками.

Перед запросом приложение отдельно проверяет форму path. Полные URL, переходы между каталогами через `..`, encoded slash/dot и query не принимаются.

Первая страница загружается по исходному пути, следующие — с `page/N/`. Наличие следующих страниц определяется по навигации `.pages` / `.navigation` того же origin; это поддерживает короткие псевдонимы категорий сайта. Для обычного каталога и избранного остаются прежние правила. Защита повторных запросов, дедупликация ID, отказ от поздних ответов и ручной повтор следующей страницы наследуются от [пагинации](03_page_loading.md).

Refresh и retry сохраняют фильтр. Каждый новый фильтр начинает с первой страницы. Ошибка не заменяет результаты обычной главной страницей. Пустая успешная выдача показывает пустой каталог с доступным возвратом. Если HTML не содержит карточек и не подтверждает успешную пустую выдачу, это ошибка разбора: в частности, сообщение AniStar «публикаций не найдено, либо нет доступа» не считается доказанным пустым результатом.

## 4. Подтверждённый протокол сортировки

Исследование живого зеркала `https://v30.astar.bz` выполнено 2026-10-11 (Asia/Yekaterinburg), до реализации. Проверены гостевые HTTP-запросы с User-Agent `AniStarTV/1.0`; cookies авторизации в исследовании не использовались. Авторизованный путь проверяется изолированными HTTP-тестами и Android fixture E2E.

На [странице комедии](https://v30.astar.bz/comedy/) форма `news_set_sort` отправляется POST на текущий URL, `action=""`. `dle_change_sort(sort,direction)` меняет два hidden-поля и вызывает `frm.submit()`.

| Поле формы | Значение |
| --- | --- |
| dlenewssortby | date / rating / news_read / comm_num / title |
| dledirection | asc / desc |
| set_new_sort | dle_sort_cat |
| set_direction_sort | dle_direction_cat |

POST устанавливает cookies `dle_sort_cat`, `dle_direction_cat`, `dle_no_cache=1`; у зеркала domain `.astar.bz`, path `/`, HttpOnly, Max-Age 33264000. Эти cookies общие для категорий: после title/desc переход в `/drama/` сохраняет алфавитный порядок. GET-параметры с именами полей формы порядок не меняют. Hidden-поля ответа остаются `date` / `DESC` даже при выбранном алфавите: читать из них текущую сортировку нельзя.

Первый POST date/asc в свежей гостевой сессии показал активный индикатор asc, но ещё вернул карточки date/desc. Последующий GET с явно установленными cookies и `dle_no_cache=1` дал старые публикации. Поэтому приложение не использует ответ POST как выдачу и не выполняет POST для смены порядка.

GET с request-local cookies работает без предварительного POST и PHP-сессии. Все 10 сочетаний проверены на страницах 1 и 2 для `/comedy/` и `/filter/janrs/%EA%EE%EC%E5%E4%E8%FF/`. У второго пути форма использует `dle_sort_xfsearch` и `dle_direction_xfsearch`: cookies `_cat` для него игнорируются. Полный `/anime/comedy/` и короткий `/comedy/` принимают `_cat`; короткий `/comedy/page/2/` работает, хотя ссылки пагинации указывают на `/anime/comedy/page/2/`. Исходные percent-encoded байты сохраняются.

Ниже первые три ID **карточек** каждой страницы `/comedy/`, извлечённые из `.title_left > a` при проверке (2026-10-11). Они фиксируют наблюдение, не являются постоянными данными приложения.

| Критерий | Направление | Страница 1 | Страница 2 |
| --- | --- | --- | --- |
| date | asc | 646, 772, 782 | 142, 1067, 1083 |
| date | desc | 11083, 11084, 11082 | 10984, 11104, 11056 |
| rating | asc | 2801, 3251, 3440 | 3434, 3435, 3439 |
| rating | desc | 3274, 6267, 4681 | 5674, 6216, 5663 |
| news_read | asc | 1167, 11044, 11065 | 10845, 11083, 11104 |
| news_read | desc | 3274, 6261, 6267 | 6144, 5200, 5674 |
| comm_num | asc | 4096, 3841, 3074 | 3605, 4119, 3096 |
| comm_num | desc | 3274, 4619, 6267 | 5200, 6216, 5064 |
| title | asc | 3171, 3185, 3184 | 1053, 6508, 4623 |
| title | desc | 5362, 5018, 142 | 3234, 3879, 10825 |

Повторить чтение можно без учётной записи:

```sh
curl --fail --silent --show-error \
  -H 'User-Agent: AniStarTV/1.0' -H 'Cache-Control: no-cache' \
  -H 'Cookie: dle_sort_cat=title; dle_direction_cat=asc; dle_no_cache=1' \
  'https://v30.astar.bz/comedy/page/2/'
```

Ответ — Windows-1251. Активная ссылка `form#news_set_sort a.sort-actv` содержит текущий критерий, но **противоположное** направление для следующего клика. Для title/asc это `dle_change_sort('title','desc')`. Приложение проверяет это подтверждение перед разбором карточек каждой страницы; несовпадение или отсутствие формы — явная ошибка, без подмены выдачи. Порядок и сравнение названий принадлежат AniStar; приложение не вычисляет рейтинг, не нормализует алфавит и не сортирует загруженные карточки локально.

## 5. Состояние и изоляция сортировки

Каждый маршрут фильтра начинает с date/desc («По дате · Сначала новые»). Его делегат `FilteredCatalogRepository` получает final filter/sort при создании. Применение сортировки передаёт новый делегат через `CatalogStarted`; BLoC заменяет источник, увеличивает generation и сбрасывает выдачу вместе. Каждая загрузка захватывает repository/page/generation до await. Выбор живёт до закрытия маршрута: переход в карточку и Back сохраняет порядок, индекс, scroll и уже загруженные страницы. Новый маршрут начинает со значения по умолчанию.

`AnistarClient` через внутренний HTML-адаптер передаёт cookies через metadata запроса; session interceptor добавляет их поверх cookies аккаунта только для этого запроса на принадлежащий сессии origin. Значения из сохранённой сессии с теми же именами заменяются, дубликатов нет. Ответ такого запроса не записывает соответствующие cookies сортировки в общий jar, остальные cookies обрабатываются как прежде. В запросы главной, избранного, деталей и другого маршрута выбранный порядок не попадает. Существующие cookies аккаунта и правила generation/origin остаются в силе. Это не требует нового ADR: сохраняется прямой HTTP-доступ и существующая граница инфраструктуры.

«Применить» с новым выбором удаляет прежние карточки, сбрасывает индекс/scroll и запускает `CatalogStarted` с первой страницы. Старые ответы первой страницы и пагинации отбрасываются generation-защитой `CatalogBloc`. Пока идёт загрузка, дозагрузка недоступна. Refresh и retry сохраняют выбранный порядок; повтор страницы 2 не превращается в страницу 3 после ошибки. Применение того же выбора и отмена не делают запросов.

### Маршруты года и режиссёра

Публичная проверка `https://v31.astar.bz` от 2026-10-22 подтвердила исходные ссылки года и режиссёра в группе `xfsearch`. Ссылка года `/filter/year/2023/` получена из [карточки «Фрирен»](https://v31.astar.bz/9576-provozhayuschaya-v-posledniy-put-friren-sousou-no-frieren.html). Ссылка режиссёра получена из [карточки 11072](https://v31.astar.bz/11072-o-moem-pererozhdenii-v-mech-2-sezon-tensei-shitara-ken-deshita-ii.html) и сохраняет исходное CP1251 percent-encoding и `+`: `/filter/director/%C8%F1%E8%F5%E8%F0%E0+%D1%E8%ED%E4%E7%E8/`. Страница 2 сохраняет этот путь и добавляет `/page/2/`.

Для обоих типов маршрутов форма сайта использует `dle_sort_xfsearch` и `dle_direction_xfsearch`. Группа сортировки `cat` игнорируется. Не декодируйте исходный путь, не формируйте его по видимой подписи метаданных и не заменяйте кодировку нормализованным названием. Сортировка `xfsearch`, заданная на один запрос, должна оставаться изолированной от категорийных маршрутов и cookie jar аккаунта.

Публичная матрица включала пять критериев сортировки, оба направления и страницы 1 и 2 одного маршрута года и одного маршрута режиссёра: всего 40 ответов. Каждый ответ вернул HTTP 200, Windows-1251 и подтверждение активной сортировки; на каждой странице было десять карточек, а страницы не пересекались в проверенных парах. Наблюдение не доказывает авторизованный путь или конкурентную изоляцию origin и аккаунта. Реализация также должна пройти HTTP fixtures и Android fixture E2E для cookies, изоляции групп, generation, поздних ответов и границ origin. Эти проверки не требуют живого аккаунта.

## 6. Сортировка: фокус, отмена и восстановление

У названия фильтра расположена кнопка с текущим критерием и направлением. На узком экране кнопка переносится под название. Во время первой загрузки фокус находится на сортировке. После успеха фокус переходит к первой карточке, если пользователь ещё не начал управлять экраном. Открытая панель и выбранный пользователем фокус не перехватываются.

Up из первого ряда ведёт на сортировку. Down возвращает к последней доступной карточке. После применения Down ведёт к первой карточке. Left с кнопки открывает левое меню. Right и Up на кнопке останавливаются.

Кнопка доступна во время загрузки, ошибки и пустой выдачи. Если карточек и действий состояния нет, Right из меню ведёт на сортировку. Back из пустого каталога сохраняет прежний маршрут возврата.

OK открывает общую правую `TvSideSheet`. Начальный фокус — текущий критерий. Пять критериев, два направления и «Применить» / «Отмена» образуют один вертикальный список с прокруткой к фокусу.

Up/Down идут по строкам без перехода через края; Left/Right остаются на строке. OK/Enter/Space/gameButtonA выбирает черновик, запрос выполняется только после «Применить». Смена критерия сохраняет выбранное направление. Для даты подписи «Сначала новые/старые», для алфавита «Я → А / А → Я», для числовых критериев «По убыванию/возрастанию».

Текущий черновик отмечен галочкой и Semantics selected. Фокус отдельно от выбора отмечается общим стилем UI Kit по [визуальной системе](11_visual_system.md). Left и Right остаются в строке и перемещают фокус по вариантам. Back/Escape, наружное касание и «Отмена» отбрасывают черновик. Закрытие возвращает фокус кнопке сортировки. После применения фокус остаётся на кнопке во время загрузки и после успеха. Down переводит фокус в новую выдачу.

При ошибке фокус получает «Попробовать снова». Up с повтора ведёт на сортировку, а Down возвращает к повтору. При пустой выдаче фокус получает доступное действие левого меню. Оттуда Right открывает доступ к сортировке. Ошибка подтверждения порядка показывается как ошибка каталога/пагинации с ручным повтором.

Переход и прокрутка используют `showTvSideSheet` и `AppMotion` по [спецификации анимаций](08_motion.md); reduced motion сохраняет управление и отключает движение. Отдельной анимации смешивания старой и новой сетки нет.
