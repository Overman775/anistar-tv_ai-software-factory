# Воспроизведение | AniStar TV

Эта спецификация задаёт получение источника, запуск и управление online HLS через native player. Интерфейс плеера следует [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md): ориентир — YouTube для телевизоров, с адаптацией под AniStar TV. Контракт кнопок, шкалы и фокуса находится в [TV-взаимодействии](06_tv_interaction.md#3-управление-player), переходы — в [анимациях](08_motion.md). Изменение внешнего вида не меняет описанные ниже правила HLS и lifecycle.

## Источник и playback session

Поддерживается только онлайн HLS через Flutter `video_player` и native player: Android использует Media3, iOS — AVFoundation. Chrome, WebView, parser-сервер, proxy, MP4 download и offline playlist не участвуют. Наличие iOS runner и успешная Simulator-сборка сами по себе не подтверждают работу HLS; для этого нужен выбранный iOS native fixture E2E.

Перед открытием источника repository получает свежий player HTML. Выбранная серия определяется номером, качество — files её объекта. Поддерживаемые значения качества — `360` и `720`; доступный поток любого из них открывается native player как HLS независимо от суффикса URL. Если запрошенного качества нет, выбирается наибольшее доступное для этой серии; `requestedQuality` и `selectedQuality` хранятся раздельно. Отсутствующие серия или поток дают Failure.

Session содержит `manifestUri`, заголовки, доступные серии/качества и необязательный `expiresAt`. Signed URL сохраняется полностью, включая `+`, запятые, path и query. Клиент не генерирует Key. `end` разбирается как Unix seconds, если значение поддерживается DateTime. Неверный или слишком большой timestamp не мешает открыть целый URI.

Поле `expiresAt` — только metadata. Оно не гарантирует срок действия ссылки и не запускает отдельный таймер refresh.

UI сортирует копию списка серий по убыванию числового номера, поэтому последняя серия отображается сверху. Исходный порядок repository/session и привязка номера к потоку не меняются. В диалоге focus и начальная прокрутка определяются выбранным номером, а не первым элементом.

## Запросы native player

Controller использует `VideoFormat.hls` независимо от суффикса URL: `.mp4` у 720p может возвращать manifest с `#EXTM3U`. Фильтрация только по расширению запрещена.

Referer — URL player page текущего origin с animeId. Заголовок передаётся master, вложенным playlists и всем segments, включая другой CDN. Cookies сайта не передаются CDN. Относительные media URI разрешаются относительно соответствующего manifest, а не зеркала AniStar.

Работа Range и MPEG-TS, relative/absolute segments и Referer проверяется через HTTPS fixture с настоящим native player. Проверка только manifest или первого segment не подтверждает запуск/seek всей цепочки.

## Открытие, смена источника и завершение

Инициализация controller ограничена 35 секундами. Новый controller создаётся после освобождения прежнего. Идентификатор операции защищает от запоздавших результатов при Back, смене route, серии и качества. Результат уже закрытой операции не обновляет UI и не запускает проигрывание.

Первое открытие начинает серию с начала и запускает воспроизведение после initialization; во время воспроизведения позиция продвигается по состоянию native player. Смена качества сохраняет позицию и playing/paused state. Смена серии начинает с нуля. Изменение animeId/episode в route открывает новый источник с нуля.

После успешной инициализации native player кнопка качества показывает `selectedQuality`: `360p` обозначается как SD, `720p` — как HD. `requestedQuality` описывает запрос и не подтверждает открытие; при успешном выборе доступной замены кнопку определяет `selectedQuality`. До успешной инициализации интерфейс не объявляет запрошенное качество применённым. Ошибка открытия оставляет действующими общий recovery и ручной повтор.

Выбор содержит только значения из `availableQualities` открытой session: «SD 360p» и «HD 720p». Текущий вариант отмечен. Единственный доступный вариант остаётся в панели; отмена и выбор текущего значения не открывают источник повторно. Выбор другого значения использует обычное открытие качества и сохраняет позицию и playing/paused state.

Pause/play выполняет native команду; ошибка следует общему recovery. Отдельные mediaPlay / mediaPause устанавливают playing/paused state без переключения при повторе команды. Native pause или завершение серии показывают controls и не скрывают их, пока видео остановлено. Seek ограничивает позицию диапазоном 0…duration.

Back, logout или смена origin закрывают экран и освобождают controller/listener/timer/focus. При уходе системный UI возвращается к режиму, ожидаемому приложением.

## Перемотка и controls

На TV Left/Right по видео и шкале меняют только черновую цель. KeyDown сразу добавляет к ней шаг ±10 секунд; native seek не вызывается до KeyUp активного направления, в том числе при коротком нажатии. Время и шкала показывают черновую цель. События позиции native player её не перезаписывают. Цель ограничена диапазоном 0…duration.

Повтор чернового шага начинается через 500 мс и продолжается каждые 500 мс. Шаг зависит от времени с начала текущего удержания:

| Длительность удержания | Шаг |
| --- | --- |
| Менее 2 секунд | 10 секунд |
| От 2 до менее 4 секунд | 20 секунд |
| От 4 до менее 6 секунд | 30 секунд |
| От 6 до менее 8 секунд | 60 секунд |
| От 8 секунд | 120 секунд |

Системный KeyRepeat не добавляет шагов. Смена направления продолжает черновик, добавляет шаг нового направления и сбрасывает время ускорения. KeyUp прежнего направления игнорируется. KeyUp текущего направления передаёт одну конечную цель в очередь native seek. Если цель совпадает с последней запрошенной позицией, дополнительный seek не отправляется.

Для текущего controller одновременно выполняется не более одной native seek-команды. Пока команда ожидается, очередь сохраняет последнюю запрошенную цель как базу новых относительных шагов; ожидающие цели объединяются в последнюю. Быстрые законченные жесты также продолжаются от последней запрошенной позиции, а при отсутствии ожидающей команды — от подтверждённой позиции. Позднее завершение команды прежнего controller не запускает seek нового потока. Ошибка следует существующему ограниченному recovery.

Потеря фокуса видео или шкалы, другая команда, панель, переход в фон, ошибка, смена controller, Back и dispose отменяют черновик и его таймер. UI возвращается к актуальной позиции. Поздние KeyUp, timer и результат прежнего controller не меняют новый поток. Отмена не меняет ограниченное восстановление и ручной повтор.

Controls остаются видимыми во время выбора цели и получают новый отсчёт в 4 секунды после отпускания. Controls скрываются после 4 секунд бездействия во время воспроизведения независимо от focus кнопок/шкалы и возвращают focus видео. Pause/native stop/completed сохраняют видимое управление, resume начинает новый отсчёт. Seek-жест не добавляет команд pause/play; пауза lifecycle при уходе в фон сохраняется. Открытая панель качества/серий сохраняет свой focus и исключает команды фоновому player.

Отдельные кнопки ±10 секунд сохраняют прямой seek. Мобильные кнопки и scrubbing сохраняют [контракт мобильного плеера](10_mobile_interaction.md#5-мобильный-плеер).

Кнопки предыдущей и следующей серии выбирают ближайший доступный номер ниже/выше текущего, включая пропуски нумерации. На границе списка недоступная кнопка скрыта и исключена из фокуса. Переключение использует обычную смену серии: позиция сбрасывается, качество сохраняется, прежний native controller освобождается. Кнопки player используют общий AppFocusStyle. Left в правой панели закрывает её без применения черновика и восстанавливает исходный фокус (в player — фокус видео). Right в левом меню сворачивает его, возвращая последнюю доступную карточку или действие содержимого.

## Удержание экрана и lifecycle

`PlayerScreen` управляет удержанием через локальный MethodChannel. Удержание включено только у активной страницы плеера в `resumed`, когда controller инициализирован, `isPlaying == true`, нет буферизации, завершения и ошибки. Позиция и видимость controls не являются условиями удержания. Открытая панель качества/серий не отменяет удержание, пока видео играет.

Pause и native stop немедленно снимают флаг через listener. Play/resume включает его снова при выполнении условий. Завершение, runtime/command error, смена источника, повторная загрузка и dispose снимают флаг. Back снимает его в начале обратного перехода, до dispose. Обычная страница поверх player снимает удержание; возврат к играющему player восстанавливает его. Каталог, вход и остальные обычные экраны не включают флаг.

Экран сам владеет lifecycle pause/resume. Любой выход из `resumed` снимает флаг и ставит видео на паузу; возвращение возобновляет только видео, игравшее перед уходом. Пользовательская пауза сохраняется. Поздняя initialization в фоне не запускает видео и не включает удержание. Native Activity дополнительно очищает флаг при `onPause`, удалении Flutter engine и уничтожении Activity; запоздалая команда включения в фоне отклоняется.

Android использует только флаг текущего окна, без `WAKE_LOCK`, изменения системного timeout, `SHOW_WHEN_LOCKED`, `TURN_SCREEN_ON` или отключения keyguard. Ручная блокировка устройства сохраняется. Этот механизм рекомендован Android для активного видео и предотвращения TV Ambient Mode: [Keep the screen on](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on).

iOS adapter управляет `UIApplication.shared.isIdleTimerDisabled` через тот же MethodChannel. Он сохраняет прежнее значение при первом захвате и восстанавливает его при остановке, уходе сцены из foreground и detach. После возврата сцены timer повторно захватывается только после свежей Dart-команды. `video_player` не получает второй механизм удержания. Поведение AVFoundation/Keychain и HLS требует отдельного native fixture E2E; без его запуска оно остаётся непроверенным.

## Восстановление воспроизведения

Для выбранного источника допускается **один автоматический refresh**. Бюджет общий для initialization failure, runtime error и ошибки native команды. Refresh повторно получает HTML, создаёт controller и восстанавливает последнюю позицию и paused state.

Успех refresh не обнуляет бюджет. Следующая ошибка этого же источника показывает понятный error/retry. Ручной retry или явная смена серии/качества начинают новый бюджет. Пользовательский повтор не переиспользует старую подписанную ссылку без нового HTML.

Ошибка CDN не запускает перебор зеркал. Если отказал сам запрос player HTML, применяется [контракт зеркал](05_mirrors.md), который может закрыть protected router до подтверждения новой сессии.

Отметка начала просмотра и история описаны отдельно: [Просмотренные серии](07_watched_episodes.md). Ошибка сохранения отметки не превращается в ошибку HLS и не запускает refresh источника.

HTML и native `errorDescription` с signed URL не попадают в UI или логи.
