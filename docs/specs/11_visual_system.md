# Визуальная система | AniStar TV

Спецификация задаёт общий визуальный контракт приложения и повторно используемых компонентов UI Kit. Она не задаёт маршруты фокуса или точные длительности анимации: эти правила принадлежат спецификациям [TV-взаимодействия](06_tv_interaction.md), [мобильного взаимодействия](10_mobile_interaction.md) и [анимаций](08_motion.md).

Каталог использует статичный графитовый эллиптический фон с горизонтом `#1C2024`, без малинового свечения. Плеер сохраняет отдельные роли поверх видео: фон `#050606`, поверхность управления `#191D20`, текст `#F1F3F4`, приглушённый текст `#B7BABD` и затемнения сверху/снизу.

Основной акцент — приглушённый малиновый `#D986A6`; текст на нём — `#24141C`. Состояние наведения использует `#E6A2BC`. Ошибка использует `#FFB7B0`. Подсветка фокуса использует поверхность `#30373A`, рамку акцентного цвета и мягкое свечение. Фокус обязан оставаться различимым относительно соседней поверхности. Не используйте цвет как единственный признак состояния.

Основной шрифт — Manrope с начертаниями 400, 500, 600, 700 и 800. Он поставляется локально с лицензией OFL. Системный текст остаётся системным и масштабируется настройками устройства. Размер, вес и цвет выбираются через общие типографические роли UI Kit, а не дублируются локально в feature.

## Значки и общие визуальные элементы

Lucide используется через общий типизированный вход `AppIcon`. `AppIconType` содержит 37 локальных SVG-иконок, включая стрелки сортировки и системное действие «Поделиться». Feature выбирает только предусмотренный значок и размер; она не задаёт произвольный стиль для каждого экземпляра. Значки действий должны иметь доступное семантическое имя.

Общие визуальные примитивы UI Kit задают геометрию и состояния. Цветовая палитра, Manrope и Lucide сохраняются общими для TV и телефона. Общая рамка фокуса меняет цвет без изменения размеров; её время и reduced-motion поведение задаёт [спецификация анимаций](08_motion.md). Карточка в фокусе масштабируется до 1,025; строки выбора сохраняют размер. Радиусы карточек, элементов управления, малых элементов и прямой кромки составляют соответственно 12, 10, 4 и 0 logical pixels. Feature передаёт содержимое, доступные подписи, данные и callbacks. Публичный README UI Kit описывает фактические точки входа и способы их использования; эта спецификация остаётся владельцем визуальных ролей.

MediaCard использует один визуальный контракт для каталога, избранного и панели сведений. Карточка сохраняет одинаковые пропорции постера, радиус и рамку на соответствующей платформе. Геометрия изображения не меняется при загрузке: skeleton, ошибка и загруженный постер занимают одинаковую область. Hero изображения сохраняет пропорции и не растягивает постер. Вариант каталога может скрыть подпись поверх постера, сохранив изображение, метки и доступное имя. Мобильные карточки каталога и избранного показывают название и год поверх постера; отдельное touch-действие размещается над изображением.

| Вариант карточки | Отношение сторон изображения |
| :--- | :--- |
| Постер | `2:3` |
| Горизонтальная карточка | `219:92` |
| Карточка серии | `16:9` |

Изображение и fallback занимают одинаковую геометрию. Заголовок карточки ограничен двумя визуальными строками; подпись серии также ограничена двумя строками. Полные значения остаются доступны через Semantics: карточка сохраняет переданный `semanticLabel`, а без него включает полные `label` и `caption`. На полной карточке название не обрезается. Рамка совпадает с контуром изображения; изображение сохраняет пропорции при `contain` или `cover` и не растягивается.

В узкой карточке серии при ограниченной высоте превью может уменьшаться в доступной области, сохраняя отношение сторон `16:9`. Без ограничения высоты превью сохраняет естественную геометрию. Системный масштаб текста не ограничивается.

Общие размеры управления составляют 56 logical pixels для TV и 48 для touch. Правая TV-панель имеет ширину 440 logical pixels; максимальная ширина нижней мобильной панели — 640. Feature использует эти роли вместо локальных копий размеров.

Область действий мобильной карточки каталога имеет размер 48 logical pixels и находится поверх постера. Её кнопка не заменяет нажатие карточки или поддерживаемое удержание. В TV-сетке используется ширина области содержимого после левого меню: четыре колонки при ширине 1280 logical pixels и пять, когда доступная область достигает 1352 logical pixels. Native TV 960×540 сохраняет четыре колонки. Высота инспектора каталога определяется содержимым с одинаковым верхним и нижним отступом. При смене карточки два буфера сохраняют большую высоту только на время перехода; высота не анимируется. Точный контракт перехода находится в [спецификации анимаций](08_motion.md), а фокус и точки возврата меню — в [TV-взаимодействии](06_tv_interaction.md).

Закладка и рейтинг являются разными метками. Подтверждённое избранное отображается сердцем только в аккаунтном контексте; рейтинг использует звезду и значение. В выборе серии текущий номер имеет отдельную метку selected; она не подменяет фокус или подтверждённую отметку просмотра. Такие метки не становятся отдельными целями фокуса. Семантические подписи передают полное значение метки. Правила подтверждения статуса избранного принадлежат [спецификации избранного](02_favorites.md).

## Состояния общих компонентов

Компоненты различают обычное, наведение, фокус, нажатие, выбранное, недоступное и занятое состояния, если состояние применимо к данному компоненту. Точный стиль берётся из общей палитры и UI Kit. TV-фокус визуально различим от выбранного пункта.

Скелетон сохраняет конечную геометрию содержимого и не объявляет декоративные блоки как интерактивные. Состояния загрузки, пустого результата и ошибки используют общую структуру служебной поверхности, но сохраняют относящиеся к операции текст и действие повтора. Анимация учитывает настройку уменьшения движения согласно [спецификации анимаций](08_motion.md).

Существующие брендовые ресурсы AniStar TV сохраняются. Эта спецификация не вводит новую генерацию логотипа, баннера или launcher-иконки.

## Источники экранов и состояний

Основной визуальный источник редизайна — `prototype/index.html`, `prototype/app.js`, `prototype/app.css` и `prototype/responsive.css` в версии прототипа `1b1d143`. HTML является демонстрацией компоновки и состояний, а не источником API, данных, авторизации или сетевого поведения. Demo-данные, демонстрационные ошибки, фиктивный вход, видео и `localStorage` не переносятся в приложение.

Чтобы открыть прототип, запустите локальный статический сервер из корня репозитория командой `python3 -m http.server 8766 --directory prototype`, затем откройте `http://127.0.0.1:8766/`.

Прототип показывает компактную оболочку до 1023 CSS px; внутри неё ширина до 767 CSS px использует телефонную панель, а 768–1023 CSS px — более широкую компактную панель. TV-подобная оболочка начинается от 1024 CSS px. Это только правило HTML-прототипа. Роль приложения задаёт платформа: Android TV сохраняет native TV-компоновку, а Android/iOS phone сохраняют мобильную компоновку независимо от ширины окна. Для сравнения используются TV 1280×720 CSS px и мобильные 360×800, 390×844 и 430×932 CSS px, включая подходящее альбомное окно. Фиксируйте CSS viewport, zoom и DPR. Native TV 960×540 сравнивается с TV-компоновкой, а не с компактной версией HTML.

Переход между сценами и их демонстрационные данные не задают production routes и protocols. Состояние, которого нет в HTML-прототипе, должно быть определено согласованной спецификацией и реальным поведением приложения. Не выводите новое поведение только из отсутствующей сцены.

## Доступность и адаптация

Текст и интерактивные состояния должны оставаться читаемыми при системном масштабировании. Иконки и цветные метки не заменяют доступное имя. Нажимаемая область и фокусируемая область соответствуют правилам платформенного взаимодействия в спецификациях 06 и 10.

Проверяйте цветовую пару с её фактическим фоном и не используйте цвет как единственный носитель различия. Выбор и фокус остаются визуально разными состояниями. Системные элементы и системный текст сохраняют системное оформление.
