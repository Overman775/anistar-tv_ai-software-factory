# Поиск | AniStar TV

Поиск открывает публичную выдачу AniStar для гостя и аккаунта. Эта спецификация описывает ввод, выдачу, локальную историю и сохранение контекста. HTTP-форма, кодировка, парсинг и поля пагинации заданы в [спецификации загрузки страниц](03_page_loading.md#поиск), а TV-управление — в [спецификации TV-взаимодействия](06_tv_interaction.md#поиск-и-редактирование-с-пульта) и [мобильного взаимодействия](10_mobile_interaction.md#2-основная-навигация).

## Термины и ответственность

- **Термины:** [аниме, каталог и поиск](../01_01_domain_glossary.md#2-аниме-каталог-и-поиск); [доступ, аккаунт и зеркало](../01_01_domain_glossary.md#1-доступ-аккаунт-и-зеркало).
- **Владелец:** [search](../01_02_feature_responsibilities.md#1-владельцы-поведения) — запрос, выдача и локальная история.
- **Участники:** catalog предоставляет модели выдачи; auth и app задают область гостя/аккаунта и origin; AniStar выполняет запрос сайта; app открывает карточку anime.

## Отправка запроса

Пользователь запускает поиск кнопкой «Найти» или действием Search экранной клавиатуры. Изменение текста не отправляет запрос. Подсказка «Название аниме» скрывается при фокусе; кнопка очистки находится внутри поля справа и недоступна при пустом поле. На телефоне поле и «Найти» остаются в одной строке. Поле ограничено 120 символами. Правило `SearchRules` считает длину в Unicode code points (`String.runes`), а не UTF-16 code units. Пробелы по краям удаляются при отправке. Запрос длиной 1–3 code points получает сообщение о минимальной длине без HTTP; текст длиннее предела не отправляется. Пустой запрос остаётся локальным и показывает «Ничего не найдено».

Новая отправка отменяет предыдущий запрос. Закрытие SearchScreen отменяет принадлежащую ему сетевую операцию. Поздний ответ отменённого запроса не заменяет текущую выдачу.

Во время запроса экран показывает загрузку. Первый успешный ответ отображает до 10 карточек. Следующая страница запрашивается при прокрутке ближе чем на 400 logical pixels к концу выдачи или когда TV-фокус достигает последних двух рядов. Последующая выдача добавляется только при подтверждённой пагинации сайта; запрос содержит исходную строку поиска. Реальный сетевой контракт и запрет автоматического повтора POST описаны в [спецификации загрузки страниц](03_page_loading.md#поиск).

## Пустая выдача и ошибки

Подтверждённая пустая выдача и ошибка первой страницы имеют отдельные состояния и сообщения. `SearchError.validation` обозначает ошибку длины запроса, `SearchError.request` — ошибку запроса. Валидация длины показывается рядом с полем. После отправки поле получает фокус; завершение запроса не переносит его. Если пользователь сам переместил фокус до ответа, пустой результат или ошибка не забирают его обратно. Повтор поиска выполняется явным действием «Найти».

При ошибке следующей страницы уже загруженные карточки остаются на экране. Рядом с сообщением доступно «Повторить загрузку». TV-пользователь переводит фокус с последнего ряда на это действие, активирует его OK и возвращает фокус к карточке стрелкой Up. На телефоне действие доступно касанием. Только явная активация повтора запрашивает ту же неудачную страницу; ошибка, прокрутка и навигация не запускают автоматический повтор POST.

## История запросов

Успешно проверенный по длине запрос добавляется в локальную историю до получения сетевого результата. История содержит не более восьми строк длиной до 120 Unicode code points. При сохранении убираются внешние пробелы; повторная строка перемещается в начало, а сравнение не учитывает регистр и заменяет `ё` на `е`. Пользователь может повторить строку из истории, удалить одну запись или очистить историю.

История хранится отдельно для каждого origin и контекста: `guest` или `account:<имя аккаунта>`. Запросы гостя не показываются в аккаунте и наоборот. Ошибка чтения истории показывает пустую историю; ошибка сохранения не блокирует поиск.

## Возврат из карточки

Открытие карточки из выдачи сохраняет экран поиска и его состояние. При возврате остаются черновой ввод, отправленный запрос, результаты, позиция прокрутки и выбранный постер. Возврат не отправляет запрос повторно.

## Управление

При новом входе в раздел Поиск из другого раздела поле получает focus, включается режим редактирования и приложение запрашивает системную IME. На TV и телефоне появляется системная экранная клавиатура. Возврат из карточки и повторный выбор уже активного Поиска восстанавливают контекст без повторного запроса IME. TV-поле, очистка и отправка образуют фокусный ряд; пустая очистка пропускается. Во время редактирования Left/Right остаются у текстового редактора. Первый Back завершает редактирование и скрывает IME; затем Left открывает меню на «Поиск». Сам ввод не отправляет запрос. Стрелки в меню только меняют фокус, OK выбирает раздел. Детальный порядок переходов находится в [спецификации TV](06_tv_interaction.md#поиск-и-редактирование-с-пульта) и [спецификации mobile](10_mobile_interaction.md#2-основная-навигация). Для TV видимость клавиатуры подтверждается состоянием нативного окна ОС; нулевые Flutter insets не доказывают её отсутствие.
