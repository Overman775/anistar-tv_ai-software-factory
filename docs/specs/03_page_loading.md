# Загрузка страниц | AniStar TV

Спецификация задаёт HTTP-контракт и преобразование данных для каталога, поиска, избранного, карточки сериала и списка серий, а также состояния пагинации. Общий контракт страниц применяется этими функциями; отдельные правила избранного описаны в [спецификации избранного](02_favorites.md).

## HTTP и преобразование данных

Каталог, detail и серии загружаются прямым Dio HTTP на текущем зеркале. JavaScript и браузерный DOM не используются. Cookies добавляет session interceptor только для собственного origin.

| Данные | Путь |
| :--- | :--- |
| Первая страница каталога | `/anime/` |
| Следующая страница каталога | `/anime/page/{page}/` |
| Первая страница поиска | `POST /` с `do=search`, `subaction=search`, `story` |
| Следующая страница поиска | `POST` на action формы `#fullsearch` с `search_start`, `result_from`, `full_search=0` и исходным `story` |
| Detail | `/{slug}.html` |
| Серии и media URL | `/test/player2/videoas_p2p_new.php?id={animeId}` |
| Избранное | `/index.php?do=favorites&cstart={page}` |

Source запрашивает bytes и передаёт `Accept: text/html`, `User-Agent: AniStarTV/1.0`, `Cache-Control: no-cache`. Content-Type определяет декодирование: Windows-1251/CP1251 либо строгий UTF-8 по умолчанию. Некорректный UTF-8 даёт Failure; случайно угаданная кодировка не подставляется.

Connect/send timeout — 8 секунд, receive — 20 секунд. Transport допускает два повтора идемпотентных запросов при сетевом отказе, HTTP 408/429/5xx. POST и [mutating GET](02_favorites.md) не повторяются. HTTP 403 не имеет transport retry. Эти повторы не заменяют отдельные бюджеты поиска зеркал и player refresh.

Source и парсер возвращают DTO либо бросают Failure. Feature repository преобразует DTO в domain и через BaseRepository возвращает Result. Ошибка или защитная HTML-страница не должны становиться успешным пустым ответом.

## Каталог и карточки

Парсер читает `.news` и `.plash`; title/link берёт из `.title_left a` или первого `a[href]`, mobile title — `.title-top`. Допустим путь `/{numericId}-{slug}.html` с host текущего зеркала и непустым title. Неподходящие отдельные карточки пропускаются.

Относительные ссылки разрешаются от baseUri. ID **9493** исключается независимо от названия или позиции рекламы. Повторяющиеся ID внутри страницы сохраняются один раз в порядке первого появления. Poster, year, rating, description, genre text, update message, publication date и favorite status необязательны. Отсутствующие значения остаются nullable; парсер не подставляет выдуманные данные. Rating допускает значения от 0 до 10 включительно; некорректное или выходящее за пределы значение становится null.

Обычный каталог без пригодных карточек — ошибка разметки. Для избранного действует только специальное подтверждение пустого списка из [контракта избранного](02_favorites.md). В текущем парсере poster/page URI могут иметь HTTP или HTTPS; native release запрещает cleartext, а HLS принимает только HTTPS. Поддержка HTTP URI не гарантирует их загрузку.

`hasNext` определяется ссылкой того же origin с номером больше текущего: `/anime/page/N/`, для избранного — `cstart` либо `/favorites/page/N/`. Это признак продолжения, а не номер следующего запроса: наличие ссылки на страницу 690 не означает переход сразу на 690.

## Поиск

Пользовательский контракт поиска и истории находится в [спецификации поиска](13_search.md). Здесь описаны HTTP-запрос, декодирование и проверка разметки AniStar.

Первая страница отправляется POST на текущий HTTPS origin по форме сайта с полями `do=search`, `subaction=search` и `story`. Кодировка берётся из Content-Type формы; проверенное зеркало использует Windows-1251. Ответ разбирается как отдельный тип страницы поиска. Подтверждённая выдача без совпадений отличается от ошибки и неизвестной разметки. Обычный парсер каталога не трактует произвольную пустую страницу как пустую выдачу.

Страница содержит до 10 результатов. Продолжение отправляется POST на action подтверждённой формы `#fullsearch`; action, hidden fields и кодировка берутся из этой формы. Для подтверждённого номера страницы `N` запрос задаёт `search_start=N`, `result_from=1+(N-1)*10` и `full_search=0`. Переход разрешён только по подтверждённой пагинации. POST не повторяется автоматически. Поздний ответ после отмены запроса или смены поколения не изменяет выдачу. Неизвестная разметка остаётся ошибкой протокола; parser/source fixture-регрессии проверяют реальные формы и ответы.

## Пагинация каталога

`CatalogStarted` начинает новый generation, переводит список в Loading, запрашивает `page=1` и сбрасывает прежний список. Для `Mobile CatalogStarted(preserveContent: true)` создаётся новый generation, состояние становится Refreshing с прежними items/hasMore, затем запрашивается page=1. Дубликат запроса игнорируется.

Переходы первой страницы и пагинации:

| Состояние/событие | Результат |
| :--- | :--- |
| Успешная первая страница | `Ready(items, hasMore)` |
| Ошибка первой страницы | Failure без items; доступен ручной повтор |
| Mobile refresh с ошибкой | `Failure(isRefreshFailure)` с прежними items/hasMore и номером последней страницы; UI сохраняет содержимое и позволяет повторить жест |
| More при `hasMore` и непустом списке | Переход в `Ready` с прежними items и `isLoadingMore`; запрос текущей `page+1` |
| Успешная следующая страница | Новые ID добавляются по порядку; обновляются page/hasMore |
| Ошибка следующей страницы | Failure с прежними items и hasMore; page не увеличивается |
| More после ошибки пагинации без `retry=true` | Игнорируется; scroll/focus не создают цепочку повторов |
| Ответ прежнего generation / закрытого BLoC | Игнорируется |

Дубликаты ID между страницами не добавляются. Ответ только с известными ID всё равно обновляет page/hasMore. После ошибки ручной retry запрашивает ту же неуспешную страницу.

More игнорируется при пустом списке, отсутствии hasMore или уже выполняющейся дозагрузке. Во время mobile Refreshing More игнорируется, а прежняя дозагрузка отбрасывается по generation. Успешный refresh заменяет выдачу первой страницей. Ошибка refresh не сбрасывает номер ранее загруженной страницы и не мешает дальнейшей пагинации. Индикатор ждёт терминального состояния после Refreshing либо закрытия экрана/BLoC.

Scroll и focus около конца сетки могут запросить дозагрузку. Refresh и смена раздела начинают новый список; старый фоновый запрос не должен вернуть прежние items.

## Detail и серии

Slug должен соответствовать `^\d+-[^/?#]+$`; animeId и page должны быть положительными. Repository параллельно запрашивает detail HTML и player HTML через Future.wait, сохраняя исходную Failure. Успех требует обеих частей и совпадения detail ID с выбранным ID.

Detail требует непустой `h1[itemprop=name]` и `ul.head`. Metadata берётся из строк «Год выпуска», «Жанр», «Озвучка», «Серии» и «Режиссёр»/«Режиссер»; описание — `.descripts`, категория — `.ful-cat`/`.tags`. Парсер копирует описание и удаляет вложенные `.title_spoiler`, `.text_spoiler`, `.reason`, `script` и `style`; HTML не исполняется. Обновление читается из `.reason`, исходная дата публикации — из `.date-icon`. Эти поля остаются nullable и сохраняют исходный текст; парсер не восстанавливает сообщение об обновлении из произвольного текста и не преобразует дату в `DateTime` или часовой пояс. Жанровая подпись карточки разбирается в строки по запятым; полная detail отдельно сохраняет список жанров и пригодные исходные href фильтров. Текст режиссёра сохраняется независимо от наличия фильтрующей ссылки; без пригодной ссылки он не становится кнопкой. Данные плитки могут включать только доступные сведения выдачи; фокус карточки не запускает запрос полной детали. Необязательные блоки могут отсутствовать. Favorite status остаётся nullable.

Год, жанр и режиссёр могут включать исходную ссылку сайта. Парсер сохраняет URL, исходное percent-encoding и кодировку; он не строит адрес по видимому названию. Метаданные без пригодной ссылки остаются текстом. Проверка поддержанных путей и сетевое применение фильтра описаны в [спецификации фильтров](09_catalog_filters.md).

Порядок частей извлекается из относящихся к нему блоков `.title_spoiler` и `.text_spoiler` внутри `.news_text`, включая скрытое содержимое. Парсер сохраняет порядок документа, полную подпись и исходную ссылку. Внутренний переход доступен только для безопасной ссылки текущего origin с путём `/{numericId}-{slug}.html`; суффикс slug после дефиса может быть пустым. Идентификатор и slug иначе остаются nullable, а неподдерживаемая ссылка показывается только как подпись. Отсутствие необязательного блока порядка не является ошибкой detail. Если обязательная разметка повреждена, результат остаётся ошибкой, а не успешной пустой карточкой. Выбор части, признак «Открыто» и возврат описаны в [спецификации карточки аниме](12_anime_details.md).

PlaylistLiteral извлекает сбалансированный массив `playlst`, учитывая строки, escapes и комментарии. JSON5 читается как данные; eval запрещён. Серия получает номер из title своего объекта, качество/URL — из его files. Нельзя сопоставлять серии и качества по порядку независимых URL.

Повторные номера серий исключаются по первому объекту, список сортируется по номеру. Принимаются строковые качества `360`/`720` и HTTPS URL из files. Signed URI сохраняется без изменения. `previewUri` и изображения жанров остаются nullable ресурсами, если исходная разметка предоставляет подходящую ссылку; изображения жанров не используются как кадры эпизодов. Серия без пригодного HLS может оставаться в списке; попытка воспроизведения должна вернуть Failure отсутствующего потока. `files_mp4`/`files_as` не используются. Пустой пригодный список серий — ошибка, а не успешная пустая detail.
