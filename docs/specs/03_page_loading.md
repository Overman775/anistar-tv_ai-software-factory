# Загрузка страниц | AniStar TV

Спецификация задаёт HTTP-контракт и преобразование данных для каталога, поиска, избранного, карточки сериала и списка серий, а также состояния пагинации. Общий контракт страниц применяется этими функциями; отдельные правила избранного описаны в [спецификации избранного](02_favorites.md).

## Термины и ответственность

- **Термины:** [аниме, каталог и поиск](../01_01_domain_glossary.md#2-аниме-каталог-и-поиск).
- **Владелец:** [AniStar](../01_02_feature_responsibilities.md#2-композиция-и-инфраструктура) — HTTP/parser-контракт; [фичи-потребители](../01_02_feature_responsibilities.md#1-владельцы-поведения) — преобразование данных и состояние своих сценариев.
- **Участники:** catalog, search, favorites и anime используют общий контракт страниц в пределах своей ответственности.

## HTTP и преобразование данных

Каталог, detail и серии загружаются прямым Dio HTTP на текущем зеркале. JavaScript и браузерный DOM не используются. Cookies добавляет session interceptor только для собственного origin.

| Данные | Путь |
| :--- | :--- |
| Первая страница каталога | `/anime/` |
| Следующая страница каталога | `/anime/page/{page}/` |
| Первая страница поиска | `GET /` для чтения формы, затем `POST /` с `do=search`, `subaction=search`, `story` |
| Следующая страница поиска | `POST /index.php?do=search` по action формы `#fullsearch` с `search_start`, `result_from`, `full_search=0` и исходным `story` |
| Detail | `/{slug}.html` |
| Серии и media URL | `/test/player2/videoas_p2p_new.php?id={animeId}` |
| Избранное | `/index.php?do=favorites&cstart={page}` |

Source запрашивает bytes и передаёт `Accept: text/html`, `User-Agent: AniStarTV/1.0`, `Cache-Control: no-cache`. Content-Type определяет декодирование: Windows-1251/CP1251 либо строгий UTF-8 по умолчанию. Некорректный UTF-8 даёт Failure; случайно угаданная кодировка не подставляется.

Connect/send timeout — 8 секунд, receive — 20 секунд. Transport допускает два повтора идемпотентных запросов при сетевом отказе, HTTP 408/429/5xx. POST и [mutating GET](02_favorites.md) не повторяются. HTTP 403 не имеет transport retry. Эти повторы не заменяют отдельные бюджеты поиска зеркал и player refresh.

Source и парсер возвращают DTO либо бросают Failure. Feature repository преобразует DTO в domain и через BaseRepository возвращает Result. Ошибка или защитная HTML-страница не должны становиться успешным пустым ответом.

## Каталог и карточки

Парсер читает `.news` и `.plash`. Ссылку берёт из `.title_left a` или первого `a[href]`, заголовок — из `.title-top` либо из текста ссылки. Допустим путь `/{numericId}-{slug}.html` того же origin с положительным ID и непустым заголовком. Суффикс после дефиса может быть пустым, как в `/10686-.html`. Ссылки с query, fragment, userinfo, обратной косой чертой или закодированными разделителями пути отклоняются. Неподходящие карточки пропускаются.

Относительные ссылки разрешаются от baseUri. ID **9493** исключается независимо от названия или позиции рекламы. Повторяющиеся ID внутри страницы сохраняются один раз в порядке первого появления. Poster, year, rating, description, genre text, update message, publication date и favorite status необязательны. Отсутствующие значения остаются nullable; парсер не подставляет выдуманные данные. Rating допускает значения от 0 до 10 включительно; некорректное или выходящее за пределы значение становится null.

Обычный каталог без пригодных карточек — ошибка разметки. Для избранного действует только специальное подтверждение пустого списка из [контракта избранного](02_favorites.md). В текущем парсере poster/page URI могут иметь HTTP или HTTPS; native release запрещает cleartext, а HLS принимает только HTTPS. Поддержка HTTP URI не гарантирует их загрузку.

`hasNext` определяется ссылкой того же origin с номером больше текущего: `/anime/page/N/`, для избранного — `cstart` либо `/favorites/page/N/`. Это признак продолжения, а не номер следующего запроса: наличие ссылки на страницу 690 не означает переход сразу на 690.

## Поиск

Пользовательский контракт поиска и истории находится в [спецификации поиска](13_search.md). Здесь описаны HTTP-запрос, декодирование и проверка разметки AniStar.

Источник сначала читает форму через `GET /` на текущем HTTPS origin. Затем отправляет её скрытые поля и `story` через `POST /`. Кодировка запроса берётся из `accept-charset` формы или Content-Type HTML-ответа. Поддерживаются Windows-1251 и UTF-8. Неподдерживаемая кодировка формы или символ, который нельзя в ней передать, дают ошибку до POST. GET формы и POST выполняются без автоматического повтора и перехода по редиректу.

Парсер ищет карточки `.short.news`. Пустая выдача требует сообщения «поиск по сайту не дал никаких результатов» в `.berrors`. Для непустой страницы обязательна форма `#fullsearch` с исходным запросом и параметрами продолжения. Пагинация сайта использует порции до 10 результатов. Парсер возвращает все пригодные карточки ответа и отдельно не ограничивает их число.

Следующая страница доступна при наличии `list_submit(N)` для номера сразу после текущего. Источник использует action, скрытые поля и кодировку подтверждённой формы `#fullsearch`. Для страницы `N` передаёт `search_start=N`, `result_from=1+(N-1)*10` и `full_search=0`. Поздний ответ после отмены или смены поколения не меняет выдачу. Неизвестная разметка остаётся ошибкой протокола.

## Пагинация каталога

`page` должен быть положительным.

`CatalogStarted` начинает новый generation, переводит список в Loading, сбрасывает прежний список и запрашивает `page=1`. При обновлении с `preserveContent: true` состояние Refreshing сохраняет прежние items/hasMore. Мобильный pull-to-refresh запрашивает первую страницу и может заменить уже начатое автоматическое обновление. Пока ручное обновление активно, повторное обновление с сохранением содержимого игнорируется.

Переходы первой страницы и пагинации:

| Состояние/событие | Результат |
| :--- | :--- |
| Успешная первая страница | `Ready(items, hasMore)` |
| Ошибка первой страницы | Failure без items; доступен ручной повтор |
| Обновление с сохранением содержимого завершилось ошибкой | `Failure(isRefreshFailure)` с прежними items/hasMore и номером последней страницы. Доступен ручной повтор. |
| More при `hasMore` и непустом списке | Переход в `Ready` с прежними items и `isLoadingMore`; запрос текущей `page+1` |
| Успешная следующая страница | Новые ID добавляются по порядку; обновляются page/hasMore |
| Ошибка следующей страницы | Failure с прежними items и hasMore; page не увеличивается |
| More после ошибки пагинации без `retry=true` | Игнорируется; scroll/focus не создают цепочку повторов |
| Ответ прежнего generation / закрытого BLoC | Игнорируется |

Дубликаты ID между страницами не добавляются. Ответ только с известными ID всё равно обновляет page/hasMore. После ошибки ручной retry запрашивает ту же неуспешную страницу.

More игнорируется при пустом списке, отсутствии hasMore, активной дозагрузке или Refreshing. Ответ дозагрузки прежнего generation отбрасывается. Успешный pull-to-refresh заменяет выдачу первой страницей. Индикатор ждёт окончания этого обновления или закрытия экрана. Возврат из другого раздела на уже открытую главную или в избранное запускает обновление с `preservePages: true`. Страницы перечитываются от первой до последней загруженной или до конца выдачи и заменяют список одним результатом. Ошибка обновления оставляет прежний список и номер страницы, с которого продолжается пагинация.

В TV-ленте появление первого незагруженного слота в viewport может запросить дозагрузку. Мобильная сетка использует вертикальную прокрутку. При смене раздела каталоги сохраняют собственные списки. Старый фоновый запрос не должен заменить содержимое активного раздела.

## Detail и серии

Полное значение slug без `.html` содержит положительный ID, дефис и суффикс без разделителей пути, query и fragment. Суффикс может быть пустым, как в `10686-` и `/10686-.html`. Repository параллельно запрашивает detail HTML и player HTML через Future.wait, сохраняя исходную Failure. Успех требует обеих частей и совпадения detail ID с выбранным ID. Парсер берёт detail ID из slug адреса, а название — из HTML.

Ссылки порядка просмотра могут вести на короткий slug. При чтении карточки адаптер вручную обрабатывает до трёх перенаправлений HTTP 301, 302, 303, 307 или 308. Ответ должен содержать один `Location` с путём `/{numericId}-{slug}.html` того же HTTPS origin и с тем же числовым ID. Query, fragment, userinfo и закодированные разделители пути отклоняются. Цикл, повреждённый `Location` и превышение лимита дают Failure. Карточка возвращает slug конечного адреса. Серии по-прежнему запрашиваются по исходному ID. Обработка применяется к чтению detail, в том числе при проверке избранного через detail. Область доступа проверяется на каждом шаге. Промежуточный 3xx сам по себе не считается признаком истечения сессии.

Detail требует непустой `h1[itemprop=name]` и `ul.head`. Metadata берётся из строк «Год выпуска», «Жанр», «Озвучка», «Серии», «Режиссёр»/«Режиссер» и «Автор»; описание — `.descripts`, категория — `.ful-cat`/`.tags`. Парсер копирует описание и удаляет вложенные `.title_spoiler`, `.text_spoiler`, `.reason`, `script` и `style`; HTML не исполняется. Обновление читается из `.reason`, исходная дата публикации — из `.date-icon`. Эти поля остаются nullable и сохраняют исходный текст; парсер не восстанавливает сообщение об обновлении из произвольного текста и не преобразует дату в `DateTime` или часовой пояс. Жанровая подпись карточки разбирается в строки по запятым; полная detail отдельно сохраняет список жанров и пригодные исходные href фильтров. Текст режиссёра и автора сохраняется независимо от наличия фильтрующей ссылки; без пригодной ссылки значение не становится кнопкой. Одинаковые имена разных ролей не смешиваются. Данные плитки могут включать только доступные сведения выдачи; фокус карточки не запускает запрос полной детали. Необязательные блоки могут отсутствовать. Favorite status остаётся nullable.

Год, жанр, режиссёр и автор могут включать исходную ссылку сайта. Парсер сохраняет URL, исходное percent-encoding и кодировку; он не строит адрес по видимому названию. Метаданные без пригодной ссылки остаются текстом. Проверка поддержанных путей и сетевое применение фильтра описаны в [спецификации фильтров](09_catalog_filters.md).

Порядок частей извлекается из относящихся к нему блоков `.title_spoiler` и `.text_spoiler` внутри `.news_text`, включая скрытое содержимое. Парсер сохраняет порядок документа, полную подпись и исходную ссылку. Внутренний переход доступен только для безопасной ссылки текущего origin с путём `/{numericId}-{slug}.html`, где полное значение slug без `.html` соответствует `^\d+-[^/?#]*$`; суффикс после дефиса может быть пустым. Идентификатор и slug иначе остаются nullable, а неподдерживаемая ссылка показывается только как подпись. Отсутствие необязательного блока порядка не является ошибкой detail. Если обязательная разметка повреждена, результат остаётся ошибкой, а не успешной пустой карточкой. Карточка связанной части использует slug ссылки для detail и её собственный ID для запроса серий. Выбор части, признак «Открыто» и возврат описаны в [спецификации карточки аниме](12_anime_details.md).

PlaylistLiteral извлекает сбалансированный массив `playlst`, учитывая строки, escapes и комментарии. JSON5 читается как данные; eval запрещён. Серия получает номер из title своего объекта, качество/URL — из его files. Нельзя сопоставлять серии и качества по порядку независимых URL.

Повторные номера серий исключаются по первому объекту, список сортируется по номеру. Принимаются строковые качества `360`/`720` и HTTPS URL из files. Signed URI сохраняется без изменения. `previewUri` и изображения жанров остаются nullable ресурсами, если исходная разметка предоставляет подходящую ссылку; изображения жанров не используются как кадры эпизодов. Серия без пригодного HLS может оставаться в списке; попытка воспроизведения должна вернуть Failure отсутствующего потока. `files_mp4`/`files_as` не используются. Пустой пригодный список серий — ошибка, а не успешная пустая detail.
