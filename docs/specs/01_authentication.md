# Вход и сессия | AniStar TV

Auth владеет единым типизированным состоянием доступа через Riverpod DI. `authAccessProvider` предоставляет потребителям проекцию `AuthAccess`; `AuthController` остаётся владельцем переходов. Взаимоисключающие режимы — `UnknownAccess`, `UnauthenticatedAccess`, `AnonymousAccess` и `AuthenticatedAccess(account)`. `AuthSessionState` хранит access и намерение открыть форму (`loginRequested`), а также `AuthOperation` (`idle`, `signingIn`, `cancellingSignIn` или `cancellationFailed`) и раздельные отказы входа (`signInFailure`) и отмены (`cancellationFailure`). Riverpod `AsyncValue` отражает загрузку и ошибку запуска/restore, а не дополнительный режим доступа. Начальное неизвестное состояние не означает ни гостя, ни аккаунт. На старте App проверяет доступность сайта, затем сохранённую сессию. Восстановленная сессия открывает главную аккаунта. Если сессии нет, App показывает отдельное интро с действиями «Войти» и «Продолжить без входа»; интро не содержит полей. Ошибка запуска остаётся на StartupScreen с повтором.

| Состояние доступа | Значение и переход |
| :--- | :--- |
| Неизвестно | Стартовая проверка ещё не завершена. Ошибка запуска остаётся отдельным состоянием операции и не открывает каталог. |
| Неавторизован | Подтверждённой сессии нет. Интро предлагает войти или явно выбрать гостевой режим. |
| Анонимный | Пользователь явно выбрал гостевой доступ после успешной проверки сайта. Состояние действует до завершения процесса и не является сессией. |
| Авторизован | Сайт подтвердил аккаунт и его защищённая сессия сохранена. Аккаунтный контекст изолирован по origin. |

Успешный вход переводит неавторизованное или анонимное состояние в подтверждённый аккаунт. Отмена входа возвращает гостевое состояние и контекст только после подтверждённой очистки отменённой сессии; при ошибке форма остаётся открытой для явного retry. Выход и истечение переводят авторизованное состояние в неавторизованное; они не выбирают гостя за пользователя. Новый запуск проверяет сохранённую сессию заново и не восстанавливает прежний гостевой выбор.

| Событие | Итог состояния и контекста |
| :--- | :--- |
| Запуск или смена origin | `unknown` до проверки нового origin; прежние ответы и данные не публикуются. |
| Восстановлен аккаунт | `authenticated(account)` с новым origin-bound контекстом. |
| Сессии нет | `unauthenticated`; открыто интро с выбором входа или гостевого режима. |
| Ошибка зеркала, сети или Secure Storage | Доступ не считается гостевым; стартовая ошибка и ручной повтор. |
| Выбран «Продолжить без входа» | `anonymous` текущего процесса без записи сессии или гостевого признака на диск. |
| Гость открыл вход / отмена подтверждена | Доступ остаётся `anonymous`; форма закрывается и восстанавливается контекст, поздний ответ не подтверждает аккаунт. |
| Очистка отменённой сессии не подтверждена | Форма остаётся открытой с ошибкой и явным retry; новая попытка входа или закрытие в гостевой контекст заблокированы до подтверждённой очистки. |
| Вход подтверждён и сохранён | `authenticated(account)` с новым контекстом; отменённое защищённое действие не повторяется. |
| Выход или доказанное истечение | `unauthenticated`; account-bound маршруты закрываются, гостевой режим не включается. |

| Доступ | Разрешённые поверхности и действия |
| :--- | :--- |
| Неизвестно | Только запуск и безопасная ошибка/повтор проверки. |
| Неавторизован | Интро; форма входа открывается отдельным действием. |
| Анонимный | Публичные каталог, поиск, жанры, карточки и доступное сайтом воспроизведение. Без избранного и аккаунтной истории просмотра. |
| Авторизован | Публичные функции и аккаунтные операции, подтверждённые сайтом. |

Проверка доступа выполняется в UI и на границе защищённой операции. Скрытая кнопка не заменяет проверку операции. Отменённые или запрещённые аккаунтные действия не повторяются автоматически после последующего входа.

AuthController / AuthRepository принадлежат feature Auth. AnistarClient, внутренний AnistarAuthService, AnistarAuthHtml, AnistarSession и interceptor принадлежат infrastructure/anistar. SecureStorage принадлежит infrastructure/storage. Нейтральный networking не знает DLE.

Пароль не сохраняется. Сохранённая сессия проверяется без повторного POST.

## Сессия и изоляция origin

Ключ записи: `anistar.session.v1.<Uri.encodeComponent(origin.origin)>`. JSON record содержит `version=1`, origin, account и host/domain cookies. Зеркала и порты изолированы. Android dev/prod используют разные application IDs. На iOS bundle ID задаёт отдельные preferences и default Keychain group; `SecureStorage` дополнительно задаёт `accountName` `com.anistar.tv.dev` для dev и `com.anistar.tv` для prod. Сессии flavors не пересекаются. Android backup выключен, чтобы запись cookies не восстанавливалась отдельно от ключа шифрования.

Cookie jar применяет domain/path/secure policy. Дополнительно исключаются истёкшие Secure cookies. Cookies прикрепляются только к текущему HTTPS origin. На чужом origin header Cookie удаляется. Native HLS не получает cookies сайта.

Изменения session сериализованы. Повреждённый JSON, несовпадающий origin/version или некорректные cookies удаляют повреждённую запись. Ошибка Secure Storage не маскируется под отсутствие аккаунта. Реальное восстановление iOS Keychain должно подтверждаться отдельным native fixture E2E; сборка или widget test этого не доказывает.

При смене origin router идентифицируется аккаунтом и зеркалом. Состояние навигации предыдущего зеркала не переносится даже при одинаковом имени аккаунта. Logout текущего origin не удаляет записи других зеркал.

## Вход

1. Trim применяется только к логину. Пустые логин или пароль отклоняются до запроса. Пароль передаётся без trim.
2. Перед входом подтверждается доступность [зеркала](05_mirrors.md). Затем прежняя сессия текущего origin очищается. Операция запоминает generation.
3. GET `/anime/` загружает форму. Форма должна содержать `input[name=login_password]` и иметь `method=post`. Ближайший родитель form определяет action. Отсутствующая или изменённая форма даёт ошибку протокола.
4. Action разрешается относительно URL страницы и должен принадлежать текущему HTTPS origin без userinfo. Пароль нельзя отправлять на другой домен.
5. Сохраняются hidden inputs с name. Значения дополняются `login_name`, `login_password`, `login=submit`. Тело — `application/x-www-form-urlencoded`, не JSON. Charset тела определяется Content-Type формы: Windows-1251/CP1251 либо UTF-8. Пробел кодируется `+`, остальные байты — percent encoding. Символ, непредставимый в CP1251, даёт ошибку до POST; заменять его вопросительным знаком нельзя.
6. POST передаёт Referer страницы формы и не имеет автоматического transport retry. Автоматическое следование redirects выключено. Поддерживаются 301/302/303 внутри origin: следующий запрос — GET, тело POST не повторяется. Допустимы максимум три перехода; четвёртый redirect завершает попытку ошибкой. 307/308 не используются для переноса тела.
7. Cross-origin redirect может запустить поиск нового зеркала. Исходный POST не повторяется; новая сессия подтверждается отдельно. Неизвестный action/redirect нельзя считать разрешением переслать credentials.
8. Успех требует ссылки текущего origin с query `action=logout` и непустого cookie header для страницы каталога. HTTP 200, произвольный текст «успешно» или отсутствие формы сами по себе успех не подтверждают. Имя аккаунта в записи берётся из введённого логина; отдельное сопоставление имени по HTML сейчас не выполняется.
9. При поиске logout-ссылки игнорируются `javascript:`, `mailto:`, `data:`, malformed URI/query, чужой host/port, cleartext HTTP и URI с userInfo. Нельзя читать `Uri.origin` у произвольного href: Dart бросает StateError для схем без HTTP-origin.
10. Cookies и имя аккаунта сохраняются одной encrypted записью. Ошибка записи отменяет подтверждение входа и очищает cookies в памяти. UI открывает каталог только после успешного сохранения.

### Отмена входа из гостевого режима

Закрытие формы входа поверх гостевого контекста или действие «Продолжить без входа» во время отправки вызывает `AuthRepository.cancelSignIn(RequestCancellation)`, который передаёт отмену в `AnistarClient.cancelSignIn`. Отмена HTTP-запроса сама по себе не завершает операцию: интерфейс ждёт подтверждённой очистки сохранённой сессии. Пока очистка выполняется, форма остаётся открытой и показывает «Отменяем вход…».

При подтверждённой очистке форма закрывается, а приложение возвращается к прежнему гостевому контексту. При отказе Secure Storage или неподтверждённом удалении форма остаётся открытой с видимой ошибкой и действием «Повторить отмену». До успеха повтор запрещён для входа, выхода в гостевой режим и обхода этой отмены; явный retry повторяет только очистку отменённой попытки. Новый вход и возврат в гостевую оболочку разрешаются после подтверждённой очистки.

Зашифрованная session-запись содержит случайный `recordId`. Отмена запоминает идентификатор записи именно этой попытки. Если хранилище всё ещё содержит её запись, session сначала записывает и проверяет tombstone с `cancelled: true` и тем же `recordId`, затем удаляет его и проверяет удаление. Tombstone не содержит логин, пароль или cookies. Если запись уже заменена другой сессией либо принадлежит другому `recordId`, отмена сохраняет её и не удаляет. При следующем запуске найденный tombstone очищается до восстановления аккаунта; ошибка очистки остаётся ошибкой запуска с ручным retry. Значения credentials, cookies и содержимое ответов не попадают в логи.

## Проверка сохранённой сессии

Если записи нет, состояние остаётся неавторизованным до явного выбора гостевого режима или входа. App показывает интро; форма открывается только после действия «Войти». Если запись есть, GET каталога должен подтвердить logout marker.

Явная гостевая форма очищает сессию. Если не найдены ни logout marker, ни гостевая форма, проверка завершается ошибкой и сохраняет запись. Ошибка сети также не удаляет запись. Ошибка восстановления оставляет запись для ручного retry; каталог не открывается.

Гостевая форма вместо authenticated HTML удаляет запись, публикует событие expired, закрывает protected router и player. HTTP 403 не доказывает expiry и обрабатывается как возможный отказ зеркала. Player HTML без login/logout marker не используется как доказательство гостевой сессии.

## Выход и конкурирующие операции

Logout локально удаляет запись текущего origin и cookies в памяти; серверный logout не вызывается. Если запись удалить не удалось, операция возвращает ошибку и UI не объявляет успешный выход.

Ответ старой generation не сохраняет cookies и не подтверждает вход. После expiry или смены repository AuthController operation guard не позволяет старому signIn восстановить прежний аккаунт.

Истечение сессии во время restore отменяет результат прежней операции и перепроверяет гостевое состояние. Поздний ответ не открывает каталог.

## Старт и экран входа

До формы входа App показывает StartupScreen с общим AnistarLogo, индикатором загрузки и Semantics liveRegion текущего этапа. Сначала проверяется доступность зеркала по контракту поиска vN, затем читается и проверяется сохранённая сессия. Реальный AnistarClient сообщает начало проверки сессии только после успешной проверки зеркала; UI не запускает отдельные HTTP-запросы.

Отсутствующая или отвергнутая сайтом сессия открывает интро. Действующая сессия открывает главную аккаунта напрямую. Недоступность сайта, отказ storage и неподтверждённый ответ проверки сессии оставляют App на StartupScreen: индикатор скрывается, под состоянием появляется безопасное сообщение и «Попробовать снова» с начальным фокусом. Неожиданное исключение не показывает технические подробности. Ошибка сети не означает гостевую сессию.

«Попробовать снова» запускает тот же restore, скрывает прежнюю ошибку и кнопку на время проверки. Ошибка восстановления оставляет запись для следующей ручной попытки. Параллельный restore не запускается; автоматические retries Riverpod отключены, cooldown поиска зеркал сохраняется.

Интро предлагает «Войти» и «Продолжить без входа». Гостевой выбор открывает публичные разделы только после успешной проверки сайта, действует до завершения процесса и не записывается как сессия. Вход из интро, меню аккаунта, мобильного аккаунта или защищённого действия открывает форму напрямую. Back после безопасной отмены возвращает к экрану и доступному действию, открывшим форму; успешный вход открывает главную аккаунта.

Форма отвечает за валидацию и отправку логина/пароля. Во время отправки она блокирует поля и показывает «Проверяем вход…». При типизированном отказе из-за неверных учётных данных вход не подтверждается, логин сохраняется, пароль очищается, а фокус получает поле пароля. При транспортной или серверной ошибке оба поля сохраняют введённые значения; текст ошибки не определяет её тип. Проверка сохранённой сессии из формы убрана.

Истечение уже открытой сессии и успешный выход закрывают защищённую навигацию и возвращают пользователя к интро. Они не включают гостевой режим автоматически. Сбой проверки сайта или Secure Storage остаётся ошибкой запуска и не включает гостевой режим. Поздний ответ отменённого входа не должен сохранять cookies или подтверждать аккаунт.

В подтверждённом аккаунтном контексте левое меню показывает имя. Если проверенный URI изображения передан меню, оно показывает картинку; иначе отображает инициалы. Сейчас источник и безопасный способ доставки личного изображения не подтверждены, а профильный provider не возвращает URI. Гостю доступны вход и публичные разделы; аватар и выход не показываются. Доступ к аккаунтным операциям проверяется на границе операции, а не только скрытием кнопки. Матрица разделов и действий описана в [спецификации TV](06_tv_interaction.md) и [избранного](02_favorites.md). Внешний вид StartupScreen и формы входа задан [визуальной системой](11_visual_system.md). Такое разделение интро, формы входа и protected router закреплено в [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md).

На интро начальный focus получает «Войти». В форме начальный focus получает логин; после отказа входа — очищенное поле пароля. При закрытой экранной клавиатуре Down проходит по доступным целям формы; Up проходит в обратном направлении. Удержание стрелки обрабатывает KeyRepeat; Left/Right сохраняют редактирование текста. Действия экранной клавиатуры Next/Done переходят в пароль / отправляют форму. Гостевой выбор доступен на интро, а не в форме. Управление описано в [TV-взаимодействии](06_tv_interaction.md#5-вход-с-пульта).
