# 🎮 TV-взаимодействие | AniStar TV

## 1. Focus и активация

Интерактивная плитка должна быть доступна стрелками пульта и иметь видимый focus, Semantics button/focused и semanticLabel. Touch использует то же действие, что и пульт. Контролируемый экран не должен зависеть от наличия клавиатуры или указателя мыши.

TvFocusable принимает Enter, Select/OK, Space и gameButtonA. KeyRepeat обрабатывается без повторного действия.

| Вход | Поведение |
| --- | --- |
| KeyDown без long action | Однократный onPressed |
| KeyDown при наличии long action | Запомнить клавишу и начать timer 600 мс, без немедленного открытия |
| KeyUp той же клавиши раньше порога | onPressed |
| KeyUp после порога | Только onLongPressed |
| Потеря focus или dispose до release | Отменить timer/удержание; ничего не открыть |
| Touch tap | Установить focus, вызвать onPressed |
| Touch long press | Установить focus, вызвать onLongPressed без короткого действия |

Длинное действие вызывается после release, чтобы повторяющийся OK не нажал первую кнопку нового диалога. Нельзя одновременно открыть detail и выполнить favorite action.

## 2. Каталог и диалоги

Каталог, избранное и карточка аниме используют общий TvBackdrop за прозрачным Scaffold. Шапка — TvHeaderSurface с полупрозрачным градиентом и blur 14, ограниченным областью AppBar. Списки остаются под шапкой и не просвечивают сквозь неё при прокрутке. Material surface tint и elevation отключены, чтобы шапка не меняла цвет после прокрутки.

Главная/Избранное выбираются верхними вкладками. При первом входе focus получает первая карточка. Up из любой карточки первого ряда ведёт на текущую вкладку; переход не зависит от расстояния до соседней вкладки или кнопок toolbar. При переключении вкладок focus остаётся на выбранной вкладке, включая пустое избранное; Left/Right позволяют вернуться на соседнюю, Down — перейти к карточкам. Возврат из detail сохраняет выбранную карточку. Focus карточки прокручивает её в видимую область, используя контекст самой карточки. Возврат к первой карточке возвращает начало каталога. Содержимое scroll view ограничено областью под AppBar, включая focus-масштабирование. Вкладки показывают выбранное состояние и отдельную рамку focus. Дозагрузка возможна при extentAfter <500 logical pixels или focus в последних двух рядах, но только из Ready с hasMore. Защита повторных запросов и ручной retry относятся к [пагинации](03_page_loading.md).

Favorite dialog сначала читает свежий статус, показывает loading, затем одно определённое действие. Ошибка предлагает «Обновить статус» и переводит focus на эту кнопку: OK повторяет чтение, не mutation. Во время mutation кнопки действия/отмены не должны инициировать ещё одну операцию. Открытие диалога не изменяет избранное.

После смены параметров detail/route нужно заново загрузить данные; старый Future не определяет содержимое нового экрана. Выход и смена origin закрывают protected navigation и диалоги предыдущего аккаунта.

Пустое избранное предлагает «Перейти на главную». Кнопка не забирает focus у вкладки при загрузке; Down и OK позволяют перейти в каталог. Для экрана без переключения вкладок кнопка не выводится.

CatalogLayout задаёт число колонок и для карточек, и для loading, и для навигации пультом: 2 при ширине меньше 600, затем 3 / 4 / 5 / 6 при порогах 600 / 820 / 1180 / 1700 logical pixels. На узком экране заголовок и счётчик располагаются друг под другом; подсказка описывает touch-действие. Заголовок AppBar ограничен одной строкой.

## 3. Управление player

После native pause или завершения серии controls появляются и остаются видимыми. Это правило действует и для остановки без нажатия кнопки в приложении. Существующий controller сохраняется; дополнительные HTTP-запросы не нужны.

Обработка клавиш player разрешена только при существующем controller и primary focus самого player; диалог выбора не должен параллельно получать команду seek/play.

| Клавиша | Действие |
| --- | --- |
| OK / Enter / Space / mediaPlayPause / gameButtonA | Play/pause |
| mediaPlay | Воспроизвести; повторная команда не ставит на паузу |
| mediaPause | Приостановить; повторная команда не запускает видео |
| Left / Right | Seek −10 / +10 секунд, с ограничением диапазона |
| Up | Диалог качества |
| Down | Диалог серии |
| Back | Закрыть player и освободить native ресурсы |

Обрабатывается KeyDown, не KeyRepeat. Команда показывает controls; timer скрытия — 4 секунды, с учётом текущего playback state. Серии в карточке аниме и диалоге player упорядочены по числовому номеру от последней к первой. В сетке чтение идёт слева направо, затем вниз. Кнопка «Смотреть серию 1» в hero сохраняет запуск первой серии. Диалог серий сразу показывает текущую серию и переводит focus на неё, даже если она далеко от начала списка. Up/Down прокручивают выбранную строку в видимую область. Выбор того же качества/серии или отмена диалога не перезагружают поток. Back из диалога возвращает focus плееру; следующее OK меняет play/pause, Left/Right выполняют seek. После окончательного отказа запуска или прерывания focus получает «Повторить»; OK делает один ручной retry с новым бюджетом. После восстановления focus возвращается управлению видео. Поздний выбор от уже закрытой initialization игнорируется.

Player использует immersiveSticky; при dispose возвращается manual system UI без overlays, как ожидает TV-приложение. Не оставлять timers, listeners или focus nodes после ухода. Сохранение позиции при качестве и сброс при серии задаёт [playback](04_playback.md).

## 5. Загрузка и визуальные состояния

Каталог показывает скелетон заголовка, счётчика и постеров с теми же отступами и сеткой, что загруженная страница. Карточка сериала показывает отдельные формы постера, текста и кнопки; высота hero и число столбцов серий общие для loading и ready. Число столбцов серий вычисляется после горизонтальных отступов.

Один skeleton-контейнер управляет shimmer всех своих форм; вложенные изображения используют его, не создавая дополнительные анимации. При системном отключении анимации формы остаются видимыми без shimmer. Заглушки исключены из Semantics и не принимают focus.

Длинные названия и метаданные ограничены строками с ellipsis. Число строк описания вычисляется по доступной высоте над кнопками и масштабу текста; последняя видимая строка получает многоточие. Фоновой картинке hero не показывают error icon, чтобы он не перекрывал текст. Вход оформлен общей темой; кнопка видимости пароля доступна пультом и касанием.

Golden-проверки закрепляют каталог, вкладки, экран входа, загрузку и длинное содержимое карточки на 960×540 и 1280×720. Изменение baselines требует просмотра PNG; генерация не заменяет проверку пультом и Android E2E.

## 6. Вход с пульта

После завершения восстановления сессии focus получает логин. Действие «Далее» экранной клавиатуры переводит focus в пароль, «Готово» отправляет форму. После отказа пароль очищается и снова получает focus для повторного ввода. При закрытой экранной клавиатуре Down переводит логин → пароль → «Войти», Up из пароля возвращает логин; однострочные поля не перехватывают эти клавиши как движение курсора. Left/Right остаются доступны для редактирования текста. Поля отключены только на время запроса. Focus nodes освобождаются вместе с экраном.

Регрессии проверяют позднюю серию 20 из 24, переход до последней стрелками и OK, отмену диалога, возврат к той же карточке, пустую вкладку и повтор после ошибки избранного. Android E2E дополняет widget-проверки переходами пультом и native playback. Экранная клавиатура и раскладка кнопок конкретного физического TV остаются отдельной ручной проверкой.
