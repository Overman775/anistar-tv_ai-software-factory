## Правила для изменений

- «Должен» обозначает контракт, который изменение обязано сохранить. Новые требования сначала явно оформляются как изменение контракта, затем реализуются и проверяются.
- Указанные исходники и тесты — точки входа для проверки, а не обещание покрытия каждого пункта отдельным тестом. При расхождении кода и текста нужно установить причину; расхождение не разрешает молча менять поведение.
- Успех HTTP, успешный парсинг, подтверждение сессии и подтверждение изменения — разные события. Нельзя подменять одно другим.
- Ошибки возвращаются через Result / Failure на границе repository. HTML, cookies, пароль и подписанные media URL не попадают в пользовательские сообщения или логи.
- Интерактивная CAPTCHA не обходится. Нет браузера, parser-сервера, скачивания и offline режима. Не добавлять эти компоненты как скрытую зависимость.
- Live-вход, restore, избранное и HLS проверены с тестовым аккаунтом; повторяемый запуск описан в руководстве. Результат для данного IP/зеркала не гарантирует доступность сайта с любой сети; fixture/E2E отдельно проверяют протокол и отказы.
- При изменении контракта обновить связанную спецификацию, руководство и значимые регрессионные тесты. Команды проверки не дублировать: [разработка и тестирование](../05_development_and_testing.md).
