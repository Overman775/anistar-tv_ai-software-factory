## Правила изменений

- Перед работой прочитайте блок «Термины и ответственность» выбранной спецификации: он ведёт к применимым разделам [глоссария](../01_01_domain_glossary.md) и [карты ответственности](../01_02_feature_responsibilities.md). Глоссарий определяет смысл понятий, карта — владельцев, спецификация — подробное поведение. Общие UI-контракты указывают распределённую ответственность; ссылка на глоссарий нужна только при наличии применимых терминов.
- При изменении значения термина или владельца обновляйте соответствующий справочник и ссылки в затронутых спецификациях в той же задаче. Подробные правила поведения сохраняйте в спецификации без копирования в справочники.
- «Должен» обозначает контракт, который изменение обязано сохранить. Новые требования сначала явно оформляются как изменение контракта, затем реализуются и проверяются.
- Указанные исходники и тесты — точки входа для проверки. Они не обещают отдельный тест для каждого пункта. При расхождении кода и спецификации установите причину; само расхождение не разрешает молча менять поведение.
- Успех HTTP, успешный парсинг, подтверждение сессии и подтверждение изменения — разные события. Не подменяйте одно другим.
- На границе repository ошибки возвращаются через Result / Failure. HTML, cookies, пароль и подписанные media URL не попадают в пользовательские сообщения или логи.
- Интерактивную CAPTCHA не обходить. В scope нет браузера, parser-сервера, скачивания и offline режима. Не добавлять эти компоненты как скрытую зависимость.
- Live-вход, restore, избранное и HLS имеют подтверждение только в Android-контексте. Опциональный iOS native fixture E2E запускается отдельно; пропуск означает, что iOS Keychain, AVFoundation и HLS не проверены. Повторяемый live Android запуск описан в [руководстве по проверке живого аккаунта](../05_development_and_testing.md#9-проверка-с-живым-аккаунтом). Результат для данного IP и зеркала не гарантирует доступность сайта с любой сети. Fixture/E2E отдельно проверяют протокол и отказы.
- При изменении контракта обновите связанную спецификацию, руководство и значимые регрессионные тесты. Команды проверок приведены в [руководстве по разработке и тестированию](../05_development_and_testing.md).
