# Избранное | AniStar TV

Избранное принадлежит подтверждённому аккаунту AniStar на сайте. В гостевом разделе избранное скрыто. На полной карточке гостю не показывается кнопка избранного или предложение войти ради этого действия. Прямой вызов операции без аккаунта также не отправляет запрос сайту. Постоянного локального списка нет. UI хранит только временные подтверждённые статусы и revision; они уничтожаются вместе с account-bound контекстом.

## Термины и ответственность

- **Термины:** [избранное и просмотр](../01_01_domain_glossary.md#3-избранное-и-просмотр); [доступ, аккаунт и зеркало](../01_01_domain_glossary.md#1-доступ-аккаунт-и-зеркало).
- **Владелец:** [favorites](../01_02_feature_responsibilities.md#1-владельцы-поведения) — статусы, операции и выдача избранного.
- **Участники:** auth определяет доступ; catalog и anime отображают данные и вызывают действия favorites; AniStar подтверждает состояние сайта.

## Статус и чтение

Статус имеет три значения: `true` — добавлено, `false` — не добавлено, `null` — неизвестно. Неизвестность нельзя превращать в `false` и показывать неподтверждённое действие.

GET `/index.php?do=favorites&cstart={page}` возвращает HTML списка. Номер страницы начинается с 1. Pagination поддерживает query `cstart` и `/favorites/page/{page}/`. Также применяются общие [правила страниц](03_page_loading.md) для charset, карточек, ID 9493, deduplication и errors.

Карточки избранного должны читаться внутри `#dle-content`, чтобы рекомендации вне списка не попадали в него. Пустой список принимается, если в `#dle-content` есть явное сообщение об отсутствии закладок или сайт вернул пустой контейнер в полной авторизованной странице. Для пустого контейнера title должен содержать «Мои закладки», canonical должен указывать `do=favorites` на текущем origin, а страница должна содержать допустимую logout-ссылку. Такой ответ вернул живой сайт для пустого тестового аккаунта.

Граница реализации. Без `#dle-content` парсер ищет карточки во всём документе и может принять постороннюю выдачу за избранное. Для пустого результата в этой разметке он возвращает ошибку.

| HTML control текущего anime ID | Статус |
| :--- | :--- |
| `doFavorites(id, 'plus')` | `false`: сайт предлагает добавить |
| `doFavorites(id, 'minus')` | `true`: сайт предлагает удалить |
| href с `do=favorites&id=id&doaction=add` | `false` |
| href с `do=favorites&id=id&doaction=del` | `true` |
| Нет control / control другого ID / противоречивые действия | `null` |

Скрипты не выполняются: `onclick` и `href` читаются как данные. Правая панель действий запрашивает свежую карточку независимо от значка на плитке. Для getStatus проверяются соответствие `detail.id` выбранному ID и наличие определённого статуса.

## Отображение на карточках

Карточки каталога и избранного используют общую визуальную основу UI Kit. На главной и в каталоге подтверждённое избранное показывается сердцем на общей закладке. На TV рейтинг показывается отдельной звездой; на мобильной главной он также показывается при наличии. В избранном закладка скрыта, как и у гостя. Метки сохраняют разные значения и не становятся отдельными целями фокуса или действия. Их геометрия и роли цвета заданы [визуальной системой](11_visual_system.md).

Отметка избранного появляется только для подтверждённого статуса `true`. Статус `false` не показывается как избранное, а `null` не превращается в подтверждённую отметку. В списке избранного сердце не дублируется на каждой карточке. Ошибка изменения не меняет подтверждённое отображение.

Если краткая карточка не содержит статуса, принадлежность подтверждается успешной страницей списка избранного текущего аккаунта. Запрос для отметок запускается в активном каталоге или активной выдаче поиска, если хотя бы у одной карточки статус неизвестен. Страницы читаются последовательно. Найденные ID становятся доступны после каждой успешной страницы. Отсутствие ID и ошибка чтения не подтверждают `false`. Подтверждённая операция имеет приоритет над результатом чтения. Смена revision, аккаунта или зеркала исключает устаревшие ответы. Гостю запрос списка для отметок не отправляется.

Рейтинг показывается с одной цифрой после запятой и без знаменателя, например `★ 8,7`. Семантическая подпись содержит полный смысл: «Рейтинг 8,7 из 10». Отсутствующее, некорректное или выходящее за допустимый диапазон значение не отображается как ноль.

## Изменение статуса

Операция задаёт желаемое значение, а не слепой toggle.

Сначала проверяются slug и соответствие числового префикса `animeId`. Затем запрашивается свежая `/{slug}.html` и читается текущий статус. Для предварительного чтения операции изменения используется переданный slug без перехода по canonical redirect. Чтение `getStatus` и итоговое подтверждение используют [контракт перенаправлений карточки](03_page_loading.md#detail-и-серии). При неизвестном статусе операция останавливается с ошибкой. Если статус уже равен желаемому, он возвращается без запроса изменения.

`dle_skin` читается из inline script как JSON5 string. Допустимы только `[a-zA-Z0-9_-]`, длина 1–64. Если безопасного значения нет, операция завершается ошибкой без подстановки произвольного default.

Изменение выполняется GET `/engine/ajax/favorites.php` с `fav_id`, `action=plus|minus`, `skin`, `alert=0`. Передаются Cookie текущей сессии, Referer карточки и `X-Requested-With: XMLHttpRequest`.

Ответ должен содержать однозначный control того же ID с действием, соответствующим новому статусу. Затем карточка загружается повторно. Её ID и статус должны подтвердить результат. Только после этого repository возвращает успех и UI обновляет состояние.

HTTP 200 сам по себе недостаточен. Пустой fragment, control только другого ID, противоречивый fragment или несовпадение свежей карточки дают ошибку. Fragment подтверждает ответ операции, а карточка — сохранённое состояние сайта.

## Повтор, согласованность и закрытие панели

Mutating GET явно исключён из transport retry. Автоматический повтор при timeout, потерянном ответе или смене зеркала запрещён, поскольку сайт мог уже применить действие. Пользователь повторяет операцию вручную; свежая карточка сначала определяет фактическое состояние.

FavoritesController допускает одно изменение одновременно для всего UI. Повторный вызов получает Failure ожидания. Optimistic star не используется. При ошибке busy снимается, а прежний confirmed state остаётся. В этом случае панель предлагает перечитать статус.

После успеха known status обновляется, revision увеличивается. Значок главной страницы и поиска, кнопка detail и открытый список избранного должны согласоваться с подтверждённым результатом. Удаление из списка вызывает его перезагрузку. Смена раздела или ручной refresh инвалидируют временный кеш. Во время незавершённого изменения инвалидирование сохраняет known status. Автоматического push/polling нет.

При возврате на главную TV и mobile заново запрашивают список избранного для карточек с неизвестным статусом. Единый источник данных для всех экранов — избранное текущего аккаунта на сайте AniStar.

Закрытие панели через Back, «Закрыть» или наружное касание не означает отмену уже отправленного запроса и не откатывает сайт. Завершившаяся операция может обновить controller, если его scope ещё существует; закрытый widget не обновляет своё состояние. После смены аккаунта или зеркала актуальный статус читается заново.

## Обновление списка и TV-действия

На mobile ручной refresh — жест вниз от начала списка, в том числе пустого. Он делает новый GET первой страницы и сохраняет текущие карточки/статусы при ошибке. Временный кеш инвалидируется после успеха, если за время запроса не было нового подтверждённого изменения. Индикатор ждёт ответ сайта; повторные жесты не дублируют запрос. Контракт UI и gesture-тесты: [мобильное взаимодействие](10_mobile_interaction.md).

На TV долгое касание или удержание OK открывает правую панель `TvSideSheet` по [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md). На телефоне долгое касание открывает нижнюю панель. Само открытие ничего не меняет. В гостевой панели доступно «Войти, чтобы добавить в избранное». На TV при закрытии фокус возвращается к доступной карточке. Если удалена последняя карточка избранного, фокус возвращается к пункту левого меню. Полная карточка предоставляет прямую кнопку добавления/удаления. Порядок её состояний описан в [спецификации карточки аниме](12_anime_details.md). Правила удержания описаны в [TV-взаимодействии](06_tv_interaction.md).
