# ⭐ Избранное | AniStar TV

## 1. Источник истины

Избранное принадлежит аккаунту AniStar на сайте. Постоянного локального списка нет. UI хранит только временные подтверждённые статусы и revision; они уничтожаются вместе с protected router.

Статус имеет три значения: true — добавлено, false — не добавлено, null — неизвестно. Неизвестность нельзя превращать в false и показывать неподтверждённое действие.

## 2. Чтение

GET `/index.php?do=favorites&cstart={page}` возвращает HTML списка. Номер страницы начинается с 1; pagination поддерживает query cstart и `/favorites/page/{page}/`. Применяются общие [правила страниц](03_page_loading.md): charset, карточки, ID 9493, deduplication и errors.

Пустой список принимается только при явном сообщении об отсутствии избранного/закладок внутри `#dle-content`. Пустая или незнакомая HTML не означает отсутствие избранного.

| HTML control текущего anime ID | Статус |
| --- | --- |
| `doFavorites(id, 'plus')` | false: сайт предлагает добавить |
| `doFavorites(id, 'minus')` | true: сайт предлагает удалить |
| href с `do=favorites&id=id&doaction=add` | false |
| href с `do=favorites&id=id&doaction=del` | true |
| Нет control / control другого ID / противоречивые действия | null |

Скрипты не выполняются: читаются onclick/href как данные. Диалог действий запрашивает свежую карточку независимо от значка на плитке. Для getStatus проверяются соответствие detail.id выбранному ID и наличие определённого статуса.

## 3. Изменение

Операция задаёт желаемое значение, а не слепой toggle.

1. Проверить slug и соответствие числового префикса animeId.
2. Получить свежую `/{slug}.html` и прочитать текущий статус. При неизвестном статусе остановиться с ошибкой.
3. Если значение уже равно желаемому, вернуть его без запроса изменения.
4. Прочитать `dle_skin` из inline script как JSON5 string. Допустимы только `[a-zA-Z0-9_-]`, длина 1–64. Нет безопасного значения — ошибка, без подстановки произвольного default.
5. Выполнить GET `/engine/ajax/favorites.php` с `fav_id`, `action=plus|minus`, `skin`, `alert=0`. Передать Cookie текущей сессии, Referer карточки и `X-Requested-With: XMLHttpRequest`.
6. Ответ должен содержать однозначный control того же ID с действием, соответствующим новому статусу.
7. Повторно получить карточку. Её ID и статус должны подтвердить результат. Только после этого вернуть успех repository и обновить UI.

HTTP 200 с error, пустой fragment, control другого ID, противоречивый fragment или несовпадение свежей карточки — ошибка. Две проверки нужны: fragment подтверждает ответ операции, карточка — сохранённое состояние сайта.

## 4. Retry и согласованность UI

Mutating GET явно исключён из transport retry. Автоматический повтор при timeout, потерянном ответе или смене зеркала запрещён: сайт мог уже применить действие. Пользователь повторяет операцию вручную; свежая карточка сначала определяет фактическое состояние.

FavoritesController допускает одно изменение одновременно для всего UI. Повторный вызов получает Failure ожидания. Optimistic star не используется. При ошибке busy снимается, прежний confirmed state остаётся; диалог предлагает перечитать статус.

После успеха known status обновляется, revision увеличивается. Значок главной страницы, кнопка detail и открытый список избранного должны согласоваться с подтверждённым результатом. Удаление из списка вызывает его перезагрузку. Смена вкладки/ручной refresh сбрасывают временный кеш, чтобы увидеть изменения другого клиента. Автоматического push/polling нет.

Закрытие диалога через Back/наружное касание не означает отмену уже отправленного запроса и не откатывает сайт. Завершившаяся операция может обновить controller, если его scope ещё существует; закрытый widget не обновляет своё состояние. После смены аккаунта/зеркала актуальный статус читается заново.

Долгое касание / удержание OK открывает диалог; само открытие ничего не меняет. Detail предоставляет кнопку добавления/удаления. Правила удержания: [TV-взаимодействие](06_tv_interaction.md).

## 5. Приёмка и источники

Должны сохраняться: чтение состояния сайта; подтверждённые add/remove; отсутствие лишней мутации при уже установленном значении; одна операция одновременно; error 200 без звезды; ручная сверка после потерянного ответа; обновление вкладки после изменения другим клиентом; отсутствие постоянного локального списка.
