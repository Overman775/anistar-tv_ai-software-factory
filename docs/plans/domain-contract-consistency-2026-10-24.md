## Что меняем

Устранить три противоречия в проектной документации: запрет пустого суффикса slug при поддерживаемом открытии части, устаревшее описание отсутствующего URI аватара и несовместимые правила Left/Right в сортировке. Результат — пять согласованных спецификаций и целевая регрессия управления сортировкой, сохраняющие существующее поведение приложения.

- CAP-01 — Спецификация загрузки разрешает slug вида `10686-`, сохраняя положительный ID, проверку origin и ограничения безопасного пути.
- CAP-02 — TV-спецификация описывает отображение подтверждённого изображения профиля и инициалов; получение и проверка данных остаются контрактом Auth.
- CAP-03 — Сортировка явно исключена из общего закрытия правой панели по Left: Left/Right сохраняют панель, фокус и черновик, а регрессия проверяет отсутствие побочных действий.

**Входит:** правки `docs/specs/03_page_loading.md`, `docs/specs/04_playback.md`, `docs/specs/06_tv_interaction.md`, `docs/specs/08_motion.md`, `docs/specs/09_catalog_filters.md`; целевые widget-проверки сортировки в существующей области `test/`. Пути спецификаций здесь — сами объекты исправления, а не пример размещения будущих файлов.

**Не входит:** новые возможности, смена UI или архитектуры, перенос ответственности, переписывание парсера/DTO/маршрутизации/Auth, изменение API/storage/HLS и безопасности, переделка общего UI Kit, массовая переработка тестов, изменение Factory. Глоссарий и карта ответственности уже согласованы; подробности regex и пульта в них не переносить. Допускается исправить только непосредственно затронутую устаревшую ссылку в этих справочниках, если она обнаружится. Живые проверки сайта, обновление golden-эталонов и публикация вне объёма.

**Источник и контекст:** пользователь запросил самостоятельный план для другого ИИ: «в плане должен быть четко, что делать другому ИИ агенту». Требования ниже полностью перенесены из подтверждённых результатов проверки документов и текущих контрактов проекта. Отчёт аудита, внутренняя сессия и переписка не являются обязательными входами исполнителя. Пользователь отдельно выбрал сохранение поведения Left/Right, отражённое в D-01. Это новый план, а не пересмотр ранее утверждённых планов проекта.

**Авторизация планирования:** ожидает подтверждения редакции. Согласование отдельного решения о клавишах не утверждает весь план. Запрошено только планирование.

## Как будет работать

### Основной поток

1. Ссылка на часть аниме с путём `/10686-.html` текущего origin может открывать соответствующую карточку. Полное значение slug здесь — `10686-`: пустой только суффикс после дефиса. Пустое значение slug целиком допустимым не становится.
2. После подтверждённого входа или восстановления аккаунта Auth отдельно получает необязательные метаданные профиля. Меню отображает переданное проверенное личное изображение либо инициалы согласно условиям ниже. Загрузка профиля не определяет доступ приложения.
3. Пользователь открывает сортировку отфильтрованного каталога. Текущий критерий получает начальный фокус; пять критериев, два направления, «Применить» и «Отмена» образуют один вертикальный список. Up/Down перемещают фокус без перехода через края. OK/Enter/Space/gameButtonA изменяет черновой выбор; смена критерия сохраняет направление.
4. Left/Right, включая KeyRepeat, оставляют фокус на текущей строке и сохраняют черновик. Панель остаётся открытой, запрос не выполняется, фоновый каталог и его меню не получают эти команды (D-01).
5. «Применить» с новым значением подтверждает сохранённый черновик и запускает первую страницу в выбранном порядке по действующему контракту каталога. Панель закрывается; фокус возвращается на кнопку сортировки и сохраняется на ней во время загрузки и после успеха. Down переводит его в новую выдачу.

### Исключения и развилки

| Условие | Поведение | Связанное решение |
| :--- | :--- | :--- |
| Slug отсутствует, не имеет числовой части с дефисом или содержит `/`, `?`, `#`; ID неположительный; ссылка нарушает действующие проверки origin/пути | Уточнение о пустом суффиксе не отменяет соответствующий отказ. Небезопасная ссылка части не становится доступным внутренним переходом. | — |
| Личное изображение отсутствует, подтверждён стандартный аватар, метаданные загружаются или их запрос завершился ошибкой; сама картинка загружается или не загрузилась | Показываются инициалы подтверждённого аккаунта. | — |
| Гостевой режим | Профиль не запрашивается; аватар и выход не показываются. Доступны вход и публичные разделы. | — |
| Ответ профиля относится к прежнему аккаунту, origin или поколению контекста | Ответ отбрасывается; выход и истечение очищают профиль. Ошибка профиля не меняет доступ и защищённую навигацию. | — |
| Back/Escape, «Отмена» или существующее закрытие наружным касанием | Черновик отбрасывается, запрос не выполняется, панель закрывается, фокус возвращается на кнопку сортировки. | D-01 |
| «Применить» без изменения действующего выбора | Дополнительный запрос не выполняется. | — |
| Left в панели серии/качества плеера либо другой панели, для которой действует общее закрытие | Существующее закрытие и возврат фокуса сохраняются; исключение сортировки на них не распространяется. | D-01 |

## Как устроено решение

Сохраняется feature-based CleanArch. AniStar владеет протоколом сайта, Auth — профилем и доступом, catalog — сортировкой и её локальным черновиком, UI Kit — общими панелями и визуальными компонентами. Presentation использует domain-контракты; app сохраняет композицию и маршруты. Новые слои, пакеты, события или DDD-агрегаты не нужны.

## Неизвестное и границы

- Внешних зависимостей и недостающих фактов, препятствующих работе, нет. Новое исследование живого сайта не требуется: исправляются внутренние противоречия подтверждённых контрактов.
- Основной риск — случайно распространить уточнение slug на пустые или небезопасные адреса, либо исключение сортировки на все правые панели. Исполнитель сохраняет независимые проверки адресов и явно ограничивает исключение одним сценарием.
- Производственный код по проверенным сведениям уже соответствует результату. Если новая регрессия выявит реальное расхождение, допустима только минимальная коррекция обработки горизонтального ввода в сортировке в пределах D-01. Она не разрешает менять общий UI Kit, UX остальных панелей или сетевой протокол. Иное обнаруженное расхождение требует отдельного согласования объёма.
- Существующие пользовательские изменения сохраняются. Новые термины и владельцы не вводятся; согласованные планы проекта не редактируются.

## Готовность и проверка

### Приёмка разработчиком и готовность

Все три возможности готовы к выполнению после утверждения плана и отдельного поручения реализации. Исполнителю достаточно этого плана и репозитория; восстанавливать требования по аудиту не нужно.

Критерии завершения:

- CAP-01: в спецификации 03 нет требования непустого суффикса, противоречащего примеру `10686-`; полный пустой slug и неположительный ID не объявлены допустимыми. Сохранены проверки origin и безопасного пути. Подходящая существующая регрессия публичной загрузки slug проходит; парсер ради текста не переписан.
- CAP-02: спецификация 06 больше не отрицает наличие URI. Нормативная ссылка ведёт в спецификацию 01; получение/проверка профиля не скопированы в новый независимый контракт. Гостевой интерфейс и защита от старых аккаунта/origin/поколения сохранены. Новые Auth-тесты только ради правки текста не требуются.
- CAP-03: спецификации 04/06/08/09 одинаково определяют область Left-close; раздел 6 спецификации 09 содержит однозначное исключение. В существующей области widget-тестов сортировки есть детерминированная регрессия со следующими наблюдениями:

| Сценарий регрессии | Проверяемый результат |
| :--- | :--- |
| Открыть сортировку, Up/Down перейти к другому критерию и выбрать его по OK | Создан отличающийся черновик, текущая применённая сортировка не изменилась, дополнительного запроса нет. Фокус и Semantics selected различимы. |
| При несохранённом выборе отправить Left и Right, включая KeyDown, KeyRepeat и завершение нажатия | После каждого направления и повтора панель открыта; та же цель имеет фокус; отмеченные критерий и направление не изменились; запросов нет; фон не получил фокус и его меню не открылось. Проверить горизонтальный ввод на строках критерия, направления и действий, чтобы правило действовало на весь список. |
| После горизонтального ввода отменить через Back, Escape и «Отмена»; проверить существующее закрытие наружным касанием | В каждом независимом сценарии панель закрыта, запросов нет, фокус вернулся на сортировку. При повторном открытии отмечено применённое значение, отменённый черновик не сохранился. |
| Вновь создать другой черновик, отправить Left/Right и нажать «Применить» | Применены именно сохранённые критерий и направление; одна загрузка первой страницы, без промежуточных запросов от клавиш; фокус возвращён на сортировку и не перехвачен успешной загрузкой. |
| Повторно применить уже действующий выбор | Дополнительных запросов нет. |

Существующие проверки Up/Down, выбора, отмены и применения сохраняются. Использовать имеющиеся fakes и сценарии, дополняя только непокрытые наблюдения. Не требовать отдельного нового теста там, где существующий уже доказывает тот же исход.

Проверить локальные ссылки и якоря изменённых спецификаций и `git diff --check`. Запустить подходящие существующие проверки slug и изменённые проверки сортировки из корневого `test/` через `fvm flutter test <root-test-path> --reporter=failures-only`. Актуальные точки входа исполнитель определяет по исходникам и разделам источников спецификаций.

Итоговые проверки по `docs/melos_tooling.md` выполняются последовательно: `fvm dart run melos run check`, затем `fvm dart run melos run test:e2e`, затем `fvm dart run melos run build:android:prod:apk`. Это требования будущего выполнения, а не результаты планирования. Указать фактический результат и точный блокер каждого непроведённого этапа; выборочный тест не выдавать за полный набор. Живые сценарии и обновление golden-эталонов не запускать.

### Проверки QA

- В Android TV fixture-среде открыть сортировку, изменить черновик, нажать и удержать Left/Right: фокус виден на прежней строке, выбор не меняется, панель не исчезает и фоновое меню не открывается. Отдельно проверить отмену и применение с возвратом на кнопку сортировки, затем Down в выдачу.
- В том же окружении убедиться, что Left по-прежнему закрывает панель серии/качества плеера и возвращает фокус видео. Проверка исключения каталога не должна менять действия плеера.
- Для профиля сопоставить документацию с существующими проверками отображения личного изображения/инициалов и гостя; не выполнять новый вход в живой аккаунт ради исправления описания. Если runtime-проверка не проводилась, отметить это отдельно.
- Поведение физического пульта при удержании остаётся отдельной ручной проверкой при наличии устройства; widget/E2E не выдавать за подтверждение каждого физического TV. Новую матрицу устройств и визуальных снимков эта коррекция не требует.
