### Directional Pad в Extended Controls

В AVD `anistar_e2e` (Emulator 36.4.10 / API 36 ARM64) стояли `hw.dPad=yes`, `hw.keyboard=no`. `getevent -pl` показывал только power/touch devices, без стрелок. Прямые Android keyevent работали в каталоге и плеере, но это обходило kernel input крестовины.

Включено `hw.keyboard=yes`, выполнен Cold Boot без очистки данных. Появилось устройство `qwerty2` с `KEYBOARD | ALPHAKEY | DPAD`; аппаратный Right через emulator controller переместил focus на соседнюю карточку. Владелец подтвердил работу кнопок непосредственно в `Extended Controls → Directional Pad` после перезапуска.

Добавлен preflight hardware input перед E2E: отсутствие стрелок останавливает команду до сборки и установки приложения. Прошли 4 регрессии проверки input, 7 тестов HTTPS fixture и 8 тестов APK checker; `bash -n` и `git diff --check` чистые. Код и APK приложения не менялись; Flutter/E2E результаты выше относятся к предыдущему прогону.

## 9. Исправление live-входа

Тестовый аккаунт позволил воспроизвести отказ на настоящем сайте. HTTP POST выдавал cookies и member HTML, но `AnistarAuthHtml.logoutUri()` вызывал `Uri.origin` для ссылки `javascript:` в меню. Dart выбрасывал StateError, а repository возвращал безопасную общую ошибку входа. Исправление отбрасывает посторонние схемы, malformed URI/query, чужой host/port и userInfo перед подтверждением logout. Member fixtures теперь включают javascript ссылку; добавлена регрессия всех этих вариантов.

Android live E2E с отключённым Chrome прошёл на API 36 ARM64: ввод логина/пароля через форму, каталог, пересоздание приложения и encrypted restore без повторного POST, карточка/серии `10938`, изменение избранного и его проверка на сайте, native HLS 720p/360p, remote seek и пауза/resume, качество и серия, галочки и их восстановление после второго пересоздания, logout. Избранное возвращено в исходное состояние; CAPTCHA не требовалась. Этот прогон подтверждает текущее зеркало/IP, а не все возможные сети.

Credentials хранятся локально вне Git. Команда и правила повторной проверки: [разработка и тестирование](05_development_and_testing.md#9-проверка-с-живым-аккаунтом). Пароль, cookies и подписанные URL в этот отчёт не включены.

После исправления формат, analyzer и DCM прошли без замечаний; 134 unit/widget/architecture-теста и 8 goldens прошли с seed 20261010.

Восемь fixture Android E2E и шесть Python-тестов сервера прошли после добавления javascript ссылки в member HTML. Дополнительно прошёл отдельный live-сценарий с настоящим аккаунтом.

Обычный release APK пересобран с исправлением входа; freshness checker прошёл для трёх ABI. Размер и SHA-256 обновлены в разделе 6. Integration entry point и файл credentials при этой сборке не использовались.

## 23. Ускорение перемотки и автоскрытие после смены фокуса (2026-10-10 UTC)

Причины: `_handleKey` видео принимал только KeyDown и отбрасывал KeyRepeat, а шкала отдельно выполняла фиксированный шаг на аппаратный repeat. `_onControlsTimer` возвращался при `_controlsFocus.hasFocus`, поэтому однажды сработавший timer переставал скрывать controls при focus Play/Back/шкалы. Клавиши, обработанные дочерним меню, также не продлевали timer экрана. После pause/resume новый timer снова упирался в этот focus guard.

`PlayerSeekHold` задаёт общий повтор для видео и шкалы. Короткое нажатие сохраняет ±10 секунд. Первый повтор через 500 мс, последующие — каждые 500 мс; частота аппаратного KeyRepeat не добавляет команды.

| Длительность текущего удержания | Шаг повторной перемотки |
| --- | --- |
| 0,5…<2 секунды | 10 секунд |
| 2…<4 секунды | 20 секунд |
| 4…<6 секунды | 30 секунд |
| 6…<8 секунд | 60 секунд |
| От 8 секунд | 120 секунд |

KeyUp текущего направления останавливает timer. Новое удержание/другое направление начинает с шага 10 секунд; отпускание прежнего направления не отменяет новое. Другая команда, уход focus, панель выбора, смена источника, foreground loss, Back и dispose отменяют повтор. Кнопки сохраняют D-pad navigation: Left/Right перемещают focus без seek. Все UI seek ограничены 0…duration; одинаковые цели на границах не отправляются native player повторно.

Native seek выполняются последовательно для текущего controller. Пока команда ожидается, относительные шаги накапливаются от последней запрошенной цели и объединяются в последнюю позицию. Это сохраняет скорость удержания при задержанном native seek без параллельных команд; запоздалый результат после reload/dispose не запускает отложенную перемотку нового controller. Native command error сохраняет прежний bounded recovery.

Во время воспроизведения controls скрываются после 4 секунд бездействия независимо от focus; перед скрытием focus получает видео. Up/Down снова показывает controls и переводит focus на Back/Play после layout. Наблюдатель hardware input только учитывает активность текущего foreground player и не перехватывает D-pad команды кнопок/панелей. KeyDown/KeyRepeat, focus change, pointer down и seek обновляют timer; позиционные события native playback его не продлевают. Удержание seek сохраняет controls и на границах; после отпускания отсчитываются новые 4 секунды. Pause, native stop/completed и chooser сохраняют видимое управление. Условие Android screen-awake не менялось.
