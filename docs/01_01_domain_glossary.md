# 📖 Доменный глоссарий | AniStar TV

Общий язык для требований, кода, тестов и работы агентов. Документ уточняет значения существующих понятий; владельцы перечислены в [карте ответственности фич](01_02_feature_responsibilities.md), правила слоёв — в [архитектурных принципах](01_architecture_principles.md).

## 1. Доступ, аккаунт и зеркало

| Термин | Значение в проекте | Контракт |
| :--- | :--- | :--- |
| Доступ (`AuthAccess`) | Режим доступа приложения. Отделён от загрузки и ошибки операции входа. Владелец — auth. | [Вход](specs/01_authentication.md) |
| Неизвестный доступ (`UnknownAccess`) | Состояние доступа ещё не определено. Отсутствие аккаунта здесь не означает выбор гостевого режима. | [Модель доступа](../lib/packages/features/auth/domain/auth_access.dart) |
| Неавторизованный доступ (`UnauthenticatedAccess`) | Подтверждённого аккаунта и выбранного гостевого режима нет. | [Модель доступа](../lib/packages/features/auth/domain/auth_access.dart) |
| Гость (`AnonymousAccess`) | Пользователь явно выбрал просмотр без аккаунта. Сам выбор гостевого режима не сохраняется между запусками. | [Вход](specs/01_authentication.md) |
| Авторизованный доступ (`AuthenticatedAccess`) | Доступ с подтверждённым аккаунтом; позволяет использовать функции аккаунта. | [Вход](specs/01_authentication.md) |
| Зеркало / origin | Зеркало задаёт адрес сайта. Origin включает схему, хост и порт; path к нему не относится. Сессия связана с origin. | [Зеркала](specs/05_mirrors.md), [сеть](04_network_and_playback.md) |
| Область данных аккаунта | Привязка данных к аккаунту и origin. Ответ прежнего аккаунта или зеркала не должен менять актуальное состояние. Это понятие описывает существующие bindings, а не отдельный обязательный тип. | [Композиция приложения](../lib/app/app_container.dart) |

## 2. Аниме, каталог и поиск

| Термин | Значение в проекте | Контракт |
| :--- | :--- | :--- |
| Краткая карточка (`AnimeSummary`) | Данные элемента выдачи каталога, поиска или избранного. Не полная карточка аниме. | [Модель](../lib/packages/features/catalog/domain/models/anime_summary.dart) |
| Полная карточка (`AnimeDetails`) | Подробные сведения об аниме. `AnimeScreenData` объединяет их с сериями для экрана. | [Карточка аниме](specs/12_anime_details.md) |
| ID / slug | Идентификаторы источника. Не следует выводить их из заголовка или предполагать глобальную идентичность между зеркалами. | [Нормализованный контракт](adr/0010-normalized-anistar-contract.md) |
| Страница выдачи (`AnimePage`) | Порция результатов и сведения для продолжения загрузки. Не экран приложения. | [Загрузка страниц](specs/03_page_loading.md) |
| Фильтр (`CatalogFilter`) | Подписанная ссылка на каталог сайта. `label` служит для отображения, `path` — для запроса; путь не строится из подписи. | [Фильтры](specs/09_catalog_filters.md) |
| Часть (`AnimePart`) | Элемент порядка просмотра связанных произведений. Не серия текущего аниме; открытие части не является просмотром серии. | [Карточка аниме](specs/12_anime_details.md) |
| Номер серии | Номер из данных источника; не индекс в списке и не идентификатор медиа. Номера могут иметь пропуски. | [Карточка аниме](specs/12_anime_details.md), [воспроизведение](specs/04_playback.md) |
| Поисковый запрос | Текст, отправленный явным действием пользователя. Отображаемый текст и нормализация для сравнения истории имеют разные назначения. | [Поиск](specs/13_search.md) |
| История поиска | Локальные сохранённые запросы с областью origin и гостя/аккаунта. Её сохранение не означает сохранение гостевого доступа. | [Поиск](specs/13_search.md) |
| Неизвестное значение | Отсутствие данных, выраженное nullable-полем контракта. Не заменяется нулём, `false` или вымышленными метаданными. | [Нормализованный контракт](adr/0010-normalized-anistar-contract.md) |

## 3. Избранное и просмотр

| Термин | Значение в проекте | Контракт |
| :--- | :--- | :--- |
| Статус избранного | Подтверждённая принадлежность к избранному аккаунта. В nullable-статусе `null` означает неизвестность, `false` — отсутствие, `true` — наличие. | [Избранное](specs/02_favorites.md) |
| Изменение избранного | Запрос желаемого состояния с подтверждением сайта. Нажатие кнопки само по себе не подтверждает результат. | [Избранное](specs/02_favorites.md) |
| Воспроизведение началось | Native controller сообщил фактическое `isPlaying`. Инициализация источника или команда play ещё не подтверждают начало. | [Просмотренные серии](specs/07_watched_episodes.md) |
| Просмотренная серия | Сервер подтвердил отметку просмотра. Эта отметка относится к началу воспроизведения, а не к досмотру или проценту прогресса. | [Просмотренные серии](specs/07_watched_episodes.md) |
| История просмотра | Подтверждённые отметки серий аккаунта на сайте. Отличается от локальной истории поиска и текущей позиции плеера. | [Просмотренные серии](specs/07_watched_episodes.md) |
| Продолжить / смотреть заново | Выбор серии для запуска с карточки по доступным сериям и подтверждённым отметкам. Не обещает восстановить сохранённую временную позицию. | [Правило выбора](../lib/packages/features/anime/domain/models/anime_watch_action.dart), [карточка аниме](specs/12_anime_details.md) |
| Playback session (`PlaybackSession`) | Данные для воспроизведения: источники, серии, качества и параметры доступа. Отличается от native controller и авторизационной сессии. | [Модель](../lib/packages/features/player/domain/models/playback_session.dart), [воспроизведение](specs/04_playback.md) |
| Запрошенное / выбранное качество | Пользовательский выбор и фактически доступное качество могут различаться из-за fallback. Текущее сопоставление выполняет playback repository. | [Воспроизведение](specs/04_playback.md) |
| Подписанный media URI | Адрес источника с параметрами доступа. Сохраняется без потери query-параметров; не выводится в логи. | [Сеть и HLS](04_network_and_playback.md) |
| Обновление playback session | Повторное получение данных источника в рамках playback-сценария. Не обновление авторизационной сессии. | [Воспроизведение](specs/04_playback.md) |

## 4. Как использовать и обновлять глоссарий

Используйте эти значения в задачах, именах и тестах. Для нового термина сначала проверьте существующее понятие и его владельца. Добавляйте строку, когда различие влияет на поведение или помогает избежать неоднозначности; перечень всех классов здесь не нужен.

Числовые лимиты, переходы состояний, обработку ошибок и критерии приёмки изменяйте в соответствующей спецификации. При изменении смысла термина обновляйте глоссарий в той же задаче. Расхождение кода и спецификации фиксируйте явно, не переопределяя термин по одному наблюдаемому участку реализации.
