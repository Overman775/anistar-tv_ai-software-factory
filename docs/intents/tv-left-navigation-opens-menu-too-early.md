# Баг: Left на TV-карточках открывает меню раньше времени

## Зачем

По наблюдению пользователя, навигация пультом между карточками аниме сломалась.
На главной можно нажимать Right и переходить на следующие карточки. Но после
этого Left открывает боковое меню вместо перехода на соседнюю карточку слева,
хотя слева ещё есть карточки. Это мешает возвращаться по ряду с пульта.

## Чего хочу

- Разобраться в причине преждевременного открытия меню и исправить навигацию.
- При нажатии Left переводить фокус на соседнюю карточку аниме слева,
  пока такая карточка есть в текущем ряду.
- Открывать боковое меню по Left только с крайней левой карточки ряда.
- Сохранить работающий переход вправо по Right.
- Добавить интеграционные регрессионные тесты управления пультом: перейти
  вправо на несколько карточек, затем возвращаться по Left. Каждый Left
  до крайней левой карточки должен переводить фокус на карточку слева,
  сохраняя меню закрытым. Следующий Left с крайней левой карточки должен
  открывать меню.

## Что важно сохранить

Речь о TV-навигации пультом. Воспроизведение начинать с главной и ряда карточек
аниме. Пользователь также называл элементы «сериями»; при расследовании нужно
проверить, затрагивает ли та же причина карточки серий и другие TV-экраны.

Правила TV-навигации сверять с [ADR-0008](../adr/0008-youtube-tv-interaction-reference.md)
и [спецификацией TV-взаимодействия](../specs/06_tv_interaction.md).
Тесты должны проверять фактический фокус и состояние меню при событиях пульта.

## Технический контекст

По чтению текущего кода найден вероятный механизм ошибки; запуском приложения
он пока не подтверждён:

- [HomeScreen._sections](../../lib/packages/features/home/presentation/screens/home_screen.dart#L69)
  встраивает главную и избранное как `CatalogScreen(embedded: true)` в `TvRouteShell`.
  В [CatalogScreen._handleCatalogKey](../../lib/packages/features/catalog/presentation/screens/catalog_screen.dart#L489)
  Left открывает меню при `_selectedIndex % columns == 0`, а на остальных
  карточках возвращает `KeyEventResult.ignored`. Внешний обработчик каталога
  `_handleContentKey` также игнорирует событие от `AnimeCard`.
- [TvRouteShell._handleContentKey](../../lib/packages/features/home/presentation/screens/tv_route_shell.dart#L180)
  перехватывает оставшийся Left: для любого содержимого, кроме редактируемого
  поля, вызывает `_openNavigation()` на `KeyDownEvent` и `KeyRepeatEvent`,
  затем возвращает `handled`. Условие первой колонки здесь отсутствует.
  Эта цепочка объясняет, почему Left может открыть меню до стандартного
  перехода фокуса, тогда как Right продолжает работать.
- Кандидат касается и избранного, и [TV-каталога по фильтру](../../lib/app/app_routes.dart#L239):
  они используют ту же связку embedded-каталога с оболочкой. Это область
  дополнительной проверки, а не подтверждённые пользователем воспроизведения.
  У [AnimeScreen._handleNavigation](../../lib/packages/features/anime/presentation/screens/anime_screen.dart#L371)
  иной путь: Left внутри ряда серий явно выбирает `index - 1` и возвращает
  `handled`. Переносить вывод о причине с каталога на серии без проверки нельзя.

Геометрию колонок задаёт [CatalogLayout.columnCount](../../lib/packages/features/catalog/presentation/widgets/catalog_layout.dart),
а `_selectedIndex` обновляется в `CatalogScreen._onCardFocusChanged`. При проверке
нужно сопоставлять индекс с фактическим фокусом, а не только со сменой текста
инспектора. [Motion-контракт](../specs/08_motion.md) требует немедленной обработки
команд и раскрытия меню без перестройки сетки; исправление не должно вводить
ожидание анимации для перехода по карточкам.

В [catalog_screen_test.dart](../../test/packages/features/catalog/presentation/screens/catalog_screen_test.dart#L26)
есть Left с последней карточки виртуализированного каталога и проверка открытия
меню с первой колонки. Эти случаи создают самостоятельный `CatalogScreen` и
не покрывают конфликт с внешним `TvRouteShell`. В
[catalog_section_navigation_test.dart](../../test/app/catalog_section_navigation_test.dart)
проверяются разделы `HomeScreen`, а в
[Android E2E](../../integration_test/app_e2e_test.dart#L420) — меню, пустое
избранное и возврат из маршрутов. В этих сценариях нет последовательности
Right → Right → Left → Left с проверкой карточки и закрытого меню после каждого
шага. Именно проверка композиции экрана с оболочкой нужна для этой регрессии.

Для воспроизведения достаточно главной с тремя карточками в одном ряду:
зафиксировать первую сфокусированную карточку, дважды нажать Right, затем
возвращаться Left. До первой колонки проверять ID фактически сфокусированной
`AnimeCard` через `FocusManager.instance.primaryFocus` и `expanded == false`
у `CatalogNavigationRail`; следующий Left должен сфокусировать активный пункт
меню. Повторить на нижнем ряду, с удержанием Left и в reduced motion на TV
960×540 и 1280×720. Widget-проверку с `HomeScreen` и fake repository дополнить
запрошенным Android fixture E2E; синтетические клавиши не подтверждают работу
[Directional Pad эмулятора и физического пульта](../05_development_and_testing.md#directional-pad-эмулятора).

## Что пока неясно

Точное устройство, сборка и последовательность событий исходного наблюдения
не зафиксированы. Нужно отдельно подтвердить, воспроизводится ли ошибка на
сериях в полной карточке аниме или слово «серии» относилось к карточкам главной.
Это не мешает проверить найденный путь `CatalogScreen` → `TvRouteShell`.
