# Project review inputs — adapt to your tracker

Read the PR title/body and explicit task links first. If an issue ID is present,
use the environment's tracker connector to obtain its description, acceptance
criteria and relevant authorized clarifications. Record source ID/URL, captured
content and timestamp in review context. No connector or credentials are granted
by this instruction; report unavailable sources without inventing their contents.

For this example, explicit user input has priority over inferred branch-name
matches. Do not silently pick among contradictory task/PR statements. A task,
incident or user request can establish intent without a separate specification.
Pass captured sources to reviewers; they verify PR assertions against actual code.
