# Git and Graphify exclusions

These are different policies. Keep shared factory files and project configuration
in Git by default. Keep factory implementation out of the application's graph,
but index factory settings and project-specific factory instructions.

Read existing ignore files, tracked paths, symlinks and active Graphify rules first.
Keep factory-local exclusions in the tracked `.factory/.gitignore`. Merge a delimited
`# BEGIN Factory Install` / `# END Factory Install` block into root `.graphifyignore`
when Graphify is selected/already used. Preserve the root application `.gitignore`;
add root rules only for selected host/vendor artifacts that actually require them.
Preserve other rules and comments. Update the same block on rerun, without duplicates.
Adapt paths to the actual installation. Resolve contradictory broad patterns rather
than assuming the block overrides them. Do not remove tracked files from Git.

Keep corpus configuration outside disposable graph output. Standard layout:

```text
project/
├── .gitignore          # shared rules
├── .graphifyignore     # shared corpus configuration; preserve across rebuilds
└── graphify-out/       # generated graph, caches, memory and local sidecars
```

This is the current AniStar layout: `.graphifyignore` is tracked at the project
root, not inside `graphify-out/`. Do not create another copy inside the output
directory or assume Graphify reads an arbitrary nested ignore file.

## Git

Exclude actual local environments, bytecode, state/staging/history, credentials,
local host overrides and graph outputs.

### Factory-local `.factory/.gitignore`

Keep this tracked file with the bundle; merge existing local rules without loss.
Patterns below are relative to `.factory/`. The application root `.gitignore`
retains its own rules; add selected host overrides or `graphify-out/` there only
when needed, without replacing user rules.

```gitignore
/memory/
/.venv/
/.venv.setup.lock
__pycache__/
*.py[cod]
.pytest_cache/
.mypy_cache/
.ruff_cache/
.coverage*
htmlcov/
```

Expected to remain tracked: `.factory/factory.yaml`, `.factory/project/`, factory
source, `.graphifyignore`, `AGENTS.md`, safe shared host/MCP configuration and
application lockfiles. The negation makes the intended Git policy explicit; it
does not protect a file from filesystem deletion.

Add these entries only for the selected installation/host; use actual paths:

| Local artifact | Git and Graphify rule |
| --- | --- |
| Factory virtualenv, if located here | `/.factory/.venv/` |
| Python bytecode under factory tools/skills | `/.factory/**/__pycache__/`, `/.factory/**/*.pyc`, `/.factory/**/*.pyo` |
| Test/linter caches created under the factory | `/.factory/**/.pytest_cache/`, `/.factory/**/.mypy_cache/`, `/.factory/**/.ruff_cache/` |
| Personal root instructions | `/AGENTS.local.md`, `/CLAUDE.local.md` |
| Local host overrides | `/.claude/settings.local.json`, `/.codex/settings.local.json` when actually used |
| ACP registry generated by factory setup | `/.acpxrc.json` when machine-local, as described below |

The factory Python helper owns `.factory/.venv/`; this does not prescribe paths for
external tools. Derive
ignore entries from the documented project installation and actual generated paths;
do not create directories just to match these examples or move vendor files.
An inherited environment outside the repository needs no repository ignore, but
does not satisfy the project-local environment required for a new installation. Do not add root `/.venv/`
unless that is the chosen environment. Ignore discovered local locks, logs, backups,
downloads and credentials by their owned paths; do not add blanket `*.lock`, `*.json`,
`*.log`, `.env*` or `.*` patterns that hide application inputs or public templates.

Factory ACP setup currently writes resolved executable paths to `.acpxrc.json`.
Treat that generated registry as machine-local. If an existing registry is an
intentionally shared portable configuration, preserve it in Git and the graph;
do not convert it to local settings or overwrite it silently. Resolve this conflict
before setup. Shared safe `.mcp.json`, `.codex/config.toml` and `.claude/settings.json`
remain tracked/indexable; secrets and machine paths require local storage supported
by the selected host. Never assume that a host supports an invented override file.

Do not ignore all `.factory/`, `factory.yaml`, `project/` or shared host configuration.
An ignore rule does not untrack an existing file; report that separately. Do not
copy AniStar's unrelated external-skill exclusions into other projects.

## Graphify

### Example: .graphifyignore

This example uses the standard layout, the same local environment/settings as
above, and a local Graphify skill. Enumerate the factory skills actually installed;
do not paste missing entries or infer ownership from a name alone. Add exact host
discovery aliases if present. Existing application exclusions stay outside the block.

```gitignore
# BEGIN Factory Install
# Factory implementation, not its project configuration.
/.factory/roles/
/.factory/contracts/
/.factory/gates/
/.factory/workflow/
/.factory/adapters/
/.factory/tools/
/.factory/factory_tooling/
/.factory/tests/
/.factory/skills/
/.factory/skills/factory-install/
/.factory/skills/factory-planning/
/.factory/skills/factory-decompose/
/.factory/skills/factory-implement/
/.factory/skills/factory-code-review/
/.factory/skills/factory-code-audit/
/.factory/skills/factory-code-debt/
/.factory/skills/factory-pr/
/.factory/skills/factory-meta-retro/
/.factory/skills/factory-meta-develop-tooling/

# Tool documentation and disposable output.
/.factory/skills/graphify/
/.factory/memory/
/graphify-out/

# Local data is excluded explicitly, independently of .gitignore.
/.factory/.venv/
/.factory/.venv.setup.lock
/.factory/**/__pycache__/
/.factory/**/*.pyc
/.factory/**/*.pyo
/.factory/**/.pytest_cache/
/.factory/**/.mypy_cache/
/.factory/**/.ruff_cache/
/AGENTS.local.md
/CLAUDE.local.md
/.claude/settings.local.json
/.codex/settings.local.json
/.acpxrc.json
# END Factory Install
```

Expected to remain indexable (no parent directory exclusion):

```text
.factory/factory.yaml
.factory/project/project.yaml
.factory/project/rules/...
.factory/project/gates/...
.factory/project/decisions/...
AGENTS.md
.graphifyignore             # maintained corpus policy, outside generated output
.codex/config.toml          # shared and secret-free
.claude/settings.json      # shared and secret-free
.mcp.json                  # shared and secret-free
```

Also exclude each installed factory skill by its exact directory, plus discovery
aliases/symlinks that duplicate it. Do not exclude the whole `.factory/skills/`
when it contains project-owned instructions. Exclude local environments and secrets.
Graphify's own skill is tool documentation, not application corpus.
Apply the local-artifact rules above to Graphify too; do not rely on it inheriting
Git exclusions. If installing a local Graphify skill bundle, exclude its exact
directory and discovery aliases from the graph. Git ownership is separate: preserve
a tracked shared bundle; ignore a locally downloaded bundle only when that is the
chosen delivery policy. Graphify output exclusion includes its memory, caches and
machine-specific interpreter sidecar, not just graph.json.

Keep `.factory/factory.yaml`, `.factory/project/project.yaml` and all associated
project rules, gates, decisions and setup documentation indexable. Shared host
settings are indexable after checking they contain no secrets. Keep project
AGENTS.md indexable. Examples and licenses shipped as factory implementation may
be excluded by exact path; do not mistake them for active settings. A secret in a
shared config is a blocker to indexing that file, not permission to leak it.

Never exclude the `.factory/` parent then assume child negations reopen traversal.
Git-style matching and Graphify traversal must be checked against the installed
version. Git ignore is not proof of Graphify exclusion. Graph exclusion does not
prevent agents from reading factory instructions directly.

## Verification and existing graphs

Check Git matches with `git check-ignore -v --no-index` on representative local
outputs and shared files; inspect tracked status separately. Use Graphify's own
current discovery/inspection procedure to check actual detected paths BEFORE a
build (including whether the detector traverses hidden `.factory/`; if it does not,
report the profile and rules as not indexed): roles/tools/skills absent; factory.yaml, project.yaml, rules/gates/decisions,
application code/tests/docs present. Do not rely on text pattern inspection alone.
If Graphify is absent, report its exclusions as configured but unverified.

Representative negative checks: virtualenv interpreter, bytecode, runtime lock,
history log, local ACP registry and Graphify memory are excluded. Positive checks:
factory.yaml, project rules/gates/decisions, safe shared MCP/host config and an
application lockfile remain visible. For Git, factory source remains visible too.

For an existing graph, check whether old factory nodes remain. Follow the installed
Graphify instructions for refresh/rebuild within authorized scope. Back up existing
graph output before a destructive rebuild; do not bypass shrink guards automatically.
Before clearing output, locate the actual corpus configuration and record its
contents/hash. Preserve root `.graphifyignore` and its user rules byte-for-byte
unless this operation explicitly changes corpus policy. Verify it still exists
with the expected contents before rebuilding. Never use a broad `graphify*` glob
or delete the project directory to reset graph output.

If an existing/custom setup stores maintained configuration inside an output
directory, do not delete that directory wholesale. First copy the configuration
to a safe location outside the deletion scope; check the installed tool's supported
configuration path, then restore or explicitly migrate it before rebuilding.
Do not silently move it to a location the tool may not read. Git ignore/negation
rules control tracking only: neither prevents a cleanup command from deleting files.
Hooks and initial indexing are optional separate actions. Exclusions must be ready
before either can trigger indexing; do not alter unrelated existing hooks.

Enumerate every factory discovery link individually under `.agents/skills/` and
`.claude/skills/`; preserve third-party and project instructions. If an application
has a Docker build context, add `.factory/` to its `.dockerignore` and verify the
effective context; do not create this rule without a Docker build.
