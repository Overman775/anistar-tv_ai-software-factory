# Evaluate a procedure change

For a lesson-driven revision, compare the cited cases with the current procedure.
Identify the ambiguity and propose the smallest change. If existing examples
already resolve it, retain the wording.

For an instruction audit, trace the actual role packet to each owning file.
Keep permissions, completion gates and universally required behavior in their
owning contract. Select a conditional example only when its trigger, evidence,
action and an allowed counterexample are identifiable. Search the catalog for an
existing equivalent. Record the source paragraph and case, proposed lesson ID,
and exact shorter wording. An unsupported anecdote stays a proposal.

Before removing text, have the coordinator run paired trials in disposable
checkouts with fresh workers, the same executor settings, tasks and hidden
criteria. Compare the original packet with the shortened packet and the candidate
card available through normal search. Include the original incident, an allowed
counterexample and unaffected behavior. Give workers their normal task without
the lesson ID or a retrieval hint. Check actual retrieval, decisions and outcomes.
If the worker misses the lesson or behavior regresses, keep the original text.

Return the comparison and limits to the coordinator. Publish a supported lesson
through Capture using the original evidence, then submit the owning-file diff and
regression cases for normal review. Remove the paragraph only after the lesson
is available and the change is accepted.
