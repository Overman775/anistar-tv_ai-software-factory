# Исправления извлечения graphify

Локальный инструмент сопровождает extractor graphify для AniStar TV. Текущий патч предназначен для **graphifyy 0.9.92**. Он исправляет причины
двух пустых endpoints и одиннадцати ложных self-loops в графе AniStar TV:

- Dart-строки и комментарии маскируются перед поиском объявлений. URI импортов
  и пути навигации читаются из оригинальных строк. Позиции и номера строк
  сохраняются. HTML fixtures больше не создают объявления с пустым типом.
- `$` сохраняет отдельную идентичность Dart-символа (маркер `_u0024_` в ID),
  включая определения mixin, ссылки и сопоставление stubs. `Route` и `$Route`
  больше не сливаются.
- Kotlin `super.method()` разрешается через локальную цепочку наследования.
  Внешний метод остаётся unresolved. `this.method()` и настоящая рекурсия
  сохраняются. Вызов superclass не связывается с одноимённой свободной функцией.

## Использование

Правила корпуса находятся в tracked `.graphifyignore`, поэтому одинаково
работают в клонах и worktree. Подготовка проекта находит Python совместимой
существующей установки и записывает абсолютный путь в локальную ignored
sidecar `graphify-out/.graphify_python`. Sidecar не переносится между машинами.
Для выбора другой установленной копии задай локальную переменную
`ANISTAR_GRAPHIFY_PYTHON` при запуске helper.
При первом успешном применении installer патчит четыре проверенных файла из
`graphify-0.9.92.patch`; `--check` подтверждает совпадение их хешей с исправленной
версией.

Применение меняет установленную копию graphify, а не приложение или исходники репозитория. Installer проверяет версию и SHA-256 всех четырёх файлов, выполняет dry-run, допускает повторный запуск и восстанавливает оригиналы при ошибке. Применяйте его только к graphifyy **0.9.92**. После обновления graphify патч может исчезнуть; другую версию нужно отдельно проверить. Автоматически применять к ней этот diff нельзя. Патч для **0.9.85** сохранён отдельно и не используется текущим installer.

Переход с предыдущего подтверждённого трёхфайлового patch обновляет только
`detect.py` после проверки точных исходного и patched SHA-256. Частичная или
неизвестная установка остаётся ошибкой. Graphify reinject-ит
`graphify-out/memory` для query feedback, если каталог не исключён явно в
`.graphifyignore` или аргументах CLI. Общий ignore в `.gitignore` не отключает
эту upstream функцию.

Если patch ещё не применён, используй Python разрешённой Graphify установки и
примени его из корня checkout:

```sh
<graphify-python> tool/graphify/patch_graphify.py
```

Затем проверь установленный инструмент и создай локальные sidecar:

```sh
python3 tool/graphify/prepare.py
```

После первого применения требуется полная пересборка graphify с новым AST cache,
поскольку номер версии инструмента не изменён. После неё владелец задачи
выполняет один `graphify update .` после всех изменений индексируемых входов.
Остальные роли могут читать текущий граф через query. Если после refresh меняется
индексируемый файл, владелец обновляет граф снова после последнего изменения.

Для нативных Git hooks отдельно выполните `graphify hook install` из корня проекта. Graphify устанавливает hooks `post-commit`, `post-checkout`, `post-merge` и `post-rewrite`, а также merge driver `graphify` и правило для `graphify-out/graph.json` в `.gitattributes`. Эти post-event hooks обновляют граф после Git-событий. Они дополняют Lefthook `pre-commit` и `pre-push`; установка Graphify не заменяет Lefthook.

Полная пересборка включает корпус, разрешённый tracked `.graphifyignore`: code
nodes строятся для maintained исходников и тестов, а документы требуют отдельной
semantic extraction. Успешный `graphify update .` подтверждает проход CLI, но не
полноту semantic fragments. Generated code, binary assets, credentials и
build/runtime artifacts исключены правилами проекта.
Извлечение Dart остаётся regex-based: патч не превращает его в полный Dart AST.

## Как проверить

Проверка `--check` не меняет установленный инструмент. Подготовка с `--check`
проверяет patch и запускает regression-тесты в том же окружении:

```sh
python3 tool/graphify/prepare.py --check
```

При полном `check` команда `test:tooling` использует `prepare.py --optional
--check`. Она пропускает Graphify только при фактическом отсутствии установки.
Обнаруженная установка с неверной версией, patch или sidecar завершает проверку
ошибкой. `graph:check` выполняет те же проверки без режима optional. Итоговый
incremental update через Melos запускается из корня:

```sh
fvm dart run melos run graph:update --include-private
```

Regression tests проверяют реальные проблемные файлы, HTML внутри строк,
импорты и навигацию, номера строк, `$` mixins в отдельном part-файле, локальный
superclass и внешний superclass. Они также проверяют сохранение настоящей
рекурсии. Массового удаления циклов или фильтрации рёбер после извлечения нет.

Доказательства выполнения полной пересборки сохраняются в ignored
`build/verification/graphify-rebuild/`: regression logs до/после, свежий AST,
semantic fragments, health summaries и резервная копия прежнего графа.
Raw health и post-build health проверяются отдельно: обычный undirected Graph
объединяет разные связи между одной парой узлов. Сырой extraction сохраняет
исходные отношения и позиции. Это ограничение формата, а не устранённый дефект.
Ссылки на внешние Python/Android библиотеки не объявляются локальными реализациями.
